# Tex Studio 工作台契约 v1

> 状态：本地 Web 工程工作区，包含通用项目编辑与可选专业预览。Electron、远程账户和正式提资发布不在本子集中。

## 专业插件与宿主

Python entry point 组为 `texsys.studio`，入口对象实现 `StudioPlugin`。清单必须声明 `id`、`name`、`version`、`api_version=1`、`discipline` 和能力列表。专业 ID 使用命名空间，不允许重复；错误插件独立诊断，不冒充可用专业。宿主不导入具体专业，前端贡献通过插件声明的 TSX 入口组成。

Tex Studio 以项目编辑能力承载工程工作。专业工作台是通用内核、通用模块与领域模块的一组配置；BOM、系统图、原理图和计算结果作为专业文档或 Preview 接入。通用文件浏览、全文搜索、Git 与文本编辑由宿主提供，无专业插件时仍可使用。工程变更使用源文件、Git diff 和构建检查；专业适配器提供可执行的工程判据。

前端贡献实现 `WorkbenchPlugin`，提供清单和 React 专业组件。专业通过宿主 `WorkbenchSurface` 贡献资源、文档标签、预览、属性和底部内容；宿主统一组织 Explorer、Search、Source Control 和源文件文档。宿主负责启动、专业切换、项目上下文、错误呈现、状态刷新、全局布局控制及任务内容。专业组件通过 `layout` 和 `changeLayout` 管理面板开关和尺寸。`taskPanel` 将宿主任务内容嵌入底部面板，`navigationRequest` 传递概览／能力导航请求。切换隐藏但不销毁专业工作台；源文件文档属于项目，切换 Activity 或专业不会丢失未保存内容。专业预览异常时仍可使用通用编辑入口。

宿主的 `showTasks(jobId?)` 可定位具体任务；可选 `taskResult` 将用户从任务面板发起的打开结果请求交给所属专业，宿主不解释专业产物。此请求包含任务记录和递增令牌，不替代结果的输入版本校验。

macOS 上的标准开发实例由 Podman 容器运行，登录后由 `launchd` 启动。Vite 在容器内运行，宿主只在 `127.0.0.1:8710` 发布端口，Python API 绑定容器内回环地址。安装和维护按[常驻开发容器说明](../../docs/development-container.md)执行，浏览器验证按 [AGENTS.md](../../AGENTS.md#tex-studio-开发与验证)复用现有 Google Chrome 和唯一实例。宿主的会话令牌与同源校验用于保护本地读写 API，不能作为远程多用户认证。

## 数据与操作

`GET /api/design-index` 读取项目源目录的 SDL 定义、部件库归属与实例引用。部件库按定义和所属模块展开，项目实例按模型的组合关系递归展开，每条实例路径保持独立。文件资源管理器以专用图标标识模块目录。点击模块目录名称打开模块概览，展开箭头只显示磁盘上的子目录和文件。对象文档提供查看模块入口源码的操作。部件库中的同一模块定义打开相同文档。

作用域文档提供模型属性、局部组成与端口连接。点击项目实例树的根名称打开对象文档，折叠箭头只控制展开状态。对象文档不内嵌 BOM、拓扑、原理图或场景子标签，实例树不提供虚拟“交付物”套娃入口。工程产物通过真实文件路径独立打开。

文件预览遵循 [DDR-0012](../../docs/ddr/0012-studio-file-preview-and-source.md)、后继交互决策 [DDR-0013](../../docs/ddr/0013-studio-editor-actions-and-open-with.md)、[DDR-0014](../../docs/ddr/0014-studio-editor-group-actions-and-disk-comparison-removal.md) 与 [ADR-0028](../../docs/adr/0028-file-based-artifact-preview.md)。文件共享标签、路径、工具栏、编辑和保存布局；路径导航右侧使用打开方式选择器，显示当前方式并只列出实际可用的文本编辑器和预览器，替代「预览 / 源代码」双按钮。只有一种方式时不显示选择器；有多种方式时，菜单支持键盘操作、Escape 和点击外部关闭。专业能力仅替换预览区域的渲染实现，不增加专用文档布局、产物标题、运行 ID、目标判定、缓存或只读状态条。

删除专用磁盘比较入口、弹窗与更新保存基准流程；普通文件仍保留共享草稿、未保存标记、保存版本保护及文件菜单的保存、另存为、还原，Git diff 继续表达版本变化。内容区域不重复展示已保存状态页脚。标签栏更多操作管理当前组，提供显示打开的编辑器、全部关闭、关闭已保存和配置编辑器；批量关闭逐项处理未保存文件，取消即停止，其他组的视图和草稿继续保留。本轮不提供临时预览标签复用或锁定组入口。Markdown 首次打开使用文本编辑器，操作图标依次为「预览、分栏预览、分栏、更多操作」：预览在当前组使用预览器打开，分栏预览在相邻组打开同文件预览，分栏在相邻组打开当前文件及其打开方式；预览模式提供「源代码、分栏、更多操作」。各编辑器组独立切换文档、打开方式和关闭标签；同一路径共享内容、保存基准与未保存状态，保存后同步所有视图。关闭其中一组的文件视图保留其他视图和共享草稿；关闭最后一个视图时才处理未保存内容，空组随之收起。不同打开方式仍使用相同文件组件。

普通 JSON 使用通用代码编辑器，BOM 数据和检查结果不自动变成专用页面。Markdown 提供文档预览，图纸与场景提供相应格式的图形预览。生成文件同样允许编辑保存；预览使用当前内容，不以不可变历史快照替代。构建状态继续保存在 `build/build.json` 及日志中。

Markdown 的打开方式包含文本编辑器、Markdown 预览和真实可编辑的 Markdown Editor。Markdown Editor 只替换通用文件组件的内容编辑实现，编辑同一 Markdown 源文本并共享保存、未保存状态和其他组的预览。打开方式菜单提供按当前扩展名设置默认值的子菜单；默认值保存在浏览器个人偏好的 `fileAssociations` 中，以小写扩展名区分 `md`、`markdown` 等类型，跨页面重载保留。默认值只在新视图建立时应用，修改偏好不会切换已有视图。未设置时 Markdown 使用文本编辑器、图纸与场景使用预览；不适用或非法偏好回退到该文件的格式默认值，普通 JSON 始终只使用其实际支持的文本编辑器。

对象选择与源码定位使用可用的稳定对象 ID 与源映射；图纸渲染仅允许受支持的 SVG 图元和属性。图形交互暂不反向写回声明式设计，源代码编辑只保存所选文件。重新构建可能覆盖生成文件的手工修改；未来反向编辑须另行定义源操作、校验与冲突契约。

部件库和项目实例支持跨折叠层级搜索。项目实例默认按组合层级浏览，可按楼层（`floor`）、专业（`discipline`）、标段（`lot`）或自定义标签分组。依赖声明通过通用文本编辑器修改，安装与同步通过 CLI 执行，见 [依赖与锁文件](../../docs/project-layout.md#依赖与锁文件)。

浏览标签保存在项目 `texsys.toml` 的可选 Studio 表中。部件库键使用项目相对 SDL 路径加 `#` 和定义名，实例键使用含根名称的完整实例路径。楼层和标段记录在实例标签中。标签仅用于导航，可填字符串或字符串数组；缺失值归入「未标注」。

```toml
[studio.library_tags."src/library/modules/pump-group/pump-group.sdl.json#PumpGroup"]
discipline = "暖通"

[studio.instance_tags."Station.PG-01"]
floor = "B1"
lot = "机电一标"

[studio.instance_tags."Station.PG-02"]
floor = "B2"
lot = "机电二标"
```

`GET /api/state` 返回协议版本、项目身份及输入修订、专业清单、插件数据、任务和诊断。输入修订覆盖清单、设计锁、source 和 assets 的路径与内容摘要，不覆盖生成物。外部文本修改在刷新时重新读取，不能被缓存冒充当前模型。

`GET /api/files` 在同一会话授权下索引当前项目文件与目录，包含空目录，文件与目录各最多 5000 项并显式标明截断。构建目录中的公开文件正常参与索引，排除运行快照、依赖缓存、Studio 中间存储、版本库内部目录和符号链接。清单可以附加预览格式与源映射，不决定文件可发现性或编辑权限。

`GET /api/file?path=...` 返回所选文件实际内容、版本及不可显示原因，支持的格式可携带预览描述。文本编辑限 1 MiB UTF-8；显示统一换行，保存保留原有换行形式和 BOM。普通构建文件与其他文件共用搜索、替换、保存和版本冲突处理。自动刷新不得覆盖未保存内容；同路径各读取入口通过共享请求身份拒绝过期响应。

`POST /api/file` 支持 `create`、`create_text`、`mkdir`、`save`、`rename`、`delete`。保存、文件重命名和删除携带基准 `version`，不一致返回 409。保存使用同目录临时文件原子替换。另存为用 `create_text` 一次创建完整的 UTF-8 文件，目标已存在时返回 409。路径拒绝越界、内部构建存储、版本库内部文件和符号链接。目录重命名和删除只支持空目录。关闭未保存文档时可保存、放弃或取消，离开浏览器页面时默认提示未保存内容。

文件资源管理器按面板标题、独立的「工作区」可折叠分区标题、项目根树条目三层组织。新建文件、新建文件夹、刷新与全部折叠四个按钮属于工作区标题行，与分区开关具有独立命中区域；项目根使用实际项目名称，是普通根 `treeitem`，不承载这些工具按钮。层级与折叠契约见 [DDR-0015](../../docs/ddr/0015-studio-explorer-workspace-section-and-project-root.md)。

收起工作区分区时隐藏项目根、文件树与四个工具按钮，保留根和子目录的展开状态，再次展开分区时恢复。单独收起项目根只隐藏其子树并保留子目录展开状态，工作区标题和工具按钮仍可使用。「全部折叠」一次收起项目根并清除全部子目录展开状态，工作区分区保持展开；再次展开根时仅显示第一层条目。分区与项目根分别保存展开状态，不能将二者混为同一个开关。点击根节点同步更新文件树选择，不能继续沿用此前子目录作为新建目标。

资源管理器面板标题右键与更多按钮共用视图和布局菜单，工作区分区标题右键提供视图菜单；两处都可显示或隐藏「打开的编辑器」分区，文件夹视图必需，仍可独立折叠。打开的编辑器分区按组列出视图，打开或收起此分区不改变文档状态。活动栏右键区分入口与空白；入口操作只针对点中的活动，源代码管理可单独切换徽标。活动栏可以切换外缘、顶部、底部与默认／紧凑尺寸，主侧栏可以隐藏和左右换位。关闭主侧栏时活动栏仍可操作。鼠标右键和键盘菜单键共用菜单，Escape 关闭。交互见 [DDR-0016](../../docs/ddr/0016-studio-explorer-and-activity-context-menus.md)。

文件资源管理器的新建文件与新建文件夹使用树内行内输入。工作区工具栏、文件树右键菜单与文件菜单的项目内新建共用此入口，禁止弹出新建对话框。选中目录时在该目录内创建，选中文件时在其父目录创建，选中项目根节点或没有选择时在项目根目录创建。新建与文件定位主动展开工作区分区、项目根及所需祖先路径。新建文件夹输入位于目录列表开头，文件输入位于目录之后、已有文件之前。Enter 提交，Escape 或点击文件树空白区域取消，即使已输入名称也不创建文件。名称或创建错误在输入行显示并保留输入，不覆盖既有文件。创建文件后打开通用编辑器，创建文件夹后选中该目录。

`GET /api/search?q=...&case=true&word=true&regex=true&include=...&exclude=...` 搜索已保存项目文本。默认按字面量匹配；可切换大小写、整词和 Python 正则。包含／排除支持路径片段、通配符及逗号分隔。返回独立匹配 `matches` 和按文件／行组织的 `lines`；同一行多个匹配只占一条结果，保留各自列位置与总计数。点击高亮精确定位文件中的对应文本。索引沿用文件浏览，跳过二进制与超过 1 MiB 文件；扫描限 32 MiB、匹配限 1000，显式显示跳过和截断。正则在独立进程执行，2 秒超时，最多两个并行任务。未保存编辑不参与磁盘搜索。

Code Search 提供搜索／替换、三种匹配开关、保留替换大小写、可折叠的路径条件、文件分组与计数、平铺结果、折叠全部、清空与刷新，并能在中央文档区域打开搜索结果。搜索框的焦点边框属于整个输入组，内层输入没有第二个边框。

`POST /api/search/replace` 先返回逐文件替换预览、变更计数和 `snapshot`。请求带 `apply:true` 与预览的快照后重新计算并核对文件版本，过期返回 409；每个文件仍通过通用文件 API 原子保存。支持全部匹配或显式文件范围，正则替换支持 `$1`、`${name}`、转义换行与制表符。搜索截断时禁止替换；前端对涉及未保存草稿的文件要求先处理草稿。批次不承诺跨文件事务：执行中出现磁盘错误会返回 `complete:false`、已完成文件列表和错误，避免把部分成功显示成全部完成。

`GET /api/scm` 返回真实 Git 分支、项目相对仓库范围、暂存／未暂存变更和操作快照。项目可位于父级仓库，默认列表仅显示项目范围；显式选择 `scope=repository` 时管理服务端定位的整个 Git 仓库。`GET /api/scm/diff?path=...&staged=true` 区分 HEAD 与暂存区、暂存区与工作区；未跟踪文本显示新增内容，差异限 1 MiB 并标记截断。

源代码管理面板顶部显示当前范围，范围菜单可查看对应的完整路径。macOS 和 Linux 上的集成终端通过同源 `/api/terminal/ws` 连接 Studio 服务环境中的独立 PTY 和交互式 Shell。标准开发实例的 Shell 在容器内运行。每个会话从项目根目录启动，显式请求时可从所属 Git 仓库根目录启动。用户可以按服务进程用户的权限切换目录。切换会话或隐藏面板时保留进程，终止会话时回收进程，刷新页面后重新建立会话。Shell 返回提示符或会话退出时刷新当前源代码管理范围。菜单执行选定文本或已保存的 Shell／Python 脚本时使用独立终端会话。旧的 `POST /api/terminal` 保留逐条执行接口和原有目录规则。

`POST /api/scm` 支持初始化当前无仓库项目、逐文件或批量暂存／取消暂存、确认后放弃工作区更改和本地提交。变更操作携带状态快照，文件或索引变化后返回 409。暂存只操作显式文件路径；提交只包含已暂存内容。父级仓库存在项目外的暂存变更、隐藏变更或未解决冲突时拒绝提交，避免夹带其他内容。Git 运行使用固定参数和字面量路径，不开放任意命令。`GET /api/scm/history` 返回整个仓库的真实提交拓扑，初次 50 条，最多 500 条；`GET /api/scm/commit` 按所选范围返回历史差异，合并提交以第一父提交为基准。拉取、推送、分支创建／切换和专门的合并编辑器留待后续。

`POST /api/edit` 包含专业、基准修订与专业定义的编辑操作。宿主串行处理提交；基准不一致返回 409。专业校验编辑候选后原子写入权威文件，返回新修订。v1 HVAC 支持实例参数完整覆盖与恢复继承；保存保留数值、单位、六态和来源，不改变共享 Component。撤销使用同一接口恢复前一绑定，仍需通过修订检查。

`POST /api/jobs` 包含专业、操作、基准修订与专业参数。后台任务基于提交时复制的 source、assets 和清单快照执行，保留原始输入摘要；本地路径依赖先验证原锁，再显式重绑定到相同来源并为执行副本锁定。任务不修改工作项目或自动采用求解结果。v1 同一项目同时运行一个任务，避免无限排队。

任务操作由专业声明和校验，不接受任意 shell、路径或命令。运行进程的状态为 running、completed、failed、cancelled 或 interrupted；工程结论单独记录 pass、fail、indeterminate 或 error。用户取消时终止任务进程组，重新启动宿主后未完成任务标记 interrupted。`POST /api/jobs/ID/cancel` 取消任务。

`GET /api/artifact?path=...` 只读取项目 build 内的固定文件。运行目录保存请求、输入副本、日志、结果与任务元数据。结果是否适用于当前设计由输入修订判断；历史产物可以查看但必须标记失效。页面刷新后仍可以读取持久化任务及结果。

项目原有 CLI 生成物可以作为历史预览读取；没有完整 Studio 输入修订的产物不自动标记为当前有效，重新运行后建立当前版本关联。

### 部件库

左侧「部件库」（Library）按库来源浏览，可跨来源搜索，并按族或其他定义标签分组。族是分类。类型由 SDL 部件定义表达，可用 `studio.library_tags` 中的 `family` 标签归类。型号是目录里可选用的具体产品或标准规格。项目短名单、选型确认和项目加工记录属于具体工程对象。

「添加库目录…」接入带 `texsys.toml`、`project.name` 和 `project.version` 的本地路径包。路径可为绝对路径或相对当前项目，Studio 将解析后的目录保存到本机浏览器，最多保存 16 个。外部条目按库名称和版本显示，只读浏览。移除库目录只改变浏览列表。

库的 SDL 类型沿用项目部件库目录约定。可选的 `<source>/library/models.json` 使用以下格式。条目键在库内稳定，`specifications` 和 `reference` 可省略。规格值为标量，单位随字段名或文本值表达。

```json
{
  "schema_version": 1,
  "models": {
    "end-suction-80": {
      "family": "冷冻水泵",
      "manufacturer": "示例厂家",
      "model": "ES-80",
      "specifications": { "接管": "DN80" },
```

`POST /api/library` 的 `index` 操作组合项目索引与给定的 `folders`，为每个外部来源返回身份、版本、内容摘要和索引诊断。`reference` 操作接收 `folder`、`entry` 和预览时的 `digest`，校验公开导出及其来源、版本、摘要与项目已锁定且同步的部件包一致后，将选择记录写入 `[[studio.library_references]]`，不修改设计依赖声明或锁文件。未通过 CLI 导入的包只能浏览，并提供导入命令提示。项目引用记录条目和来源版本。SDL 实例化、选型决定和计算输入绑定分别由相应流程表达。

没有打开匹配的库目录时，Studio 从项目已同步的依赖目录展示锁定版本。已同步且明确声明 `kind="component"` 与 `exports.components` 的包，其导出部件与型号进入部件库，不要求先写入 `studio.library_references`；已有 SDL 导入按定义身份去重。安装包不会自动创建项目实例或完成选型。registry 包保留仓库来源身份，不能把同步目录或本机缓存路径重新登记为本地路径依赖；其版本通过 CLI 更改。

CLI 更新项目依赖后，旧版本的部件引用需要单独复核；确认引用版本只更新选择记录，不安装或升级包。复核须携带原摘要 `previous_digest`，已安装新版本须保留全部已引用的公开条目身份及类型。读取后的源内容变化及其他锁定依赖漂移均使操作失败。依赖契约见 [依赖与锁文件](../../docs/project-layout.md#依赖与锁文件)。

### 项目依赖文件与命令行

依赖声明保存在 `texsys.toml`，从文件资源管理器或快速打开进入通用文本编辑器；`texsys.lock` 以原始文件查看，由 CLI 生成和维护。JSON、YAML、TOML 等配置使用现有编辑能力，不另造项目依赖 activity、专用页面或表单。

安装、更新、移除、同步和包测试通过集成终端的 `texsys` CLI 执行，状态使用 `texsys package status` 查看。已同步、运行环境就绪、包测试通过和工程接受分别判断；`sync` 不安装第三方运行环境或 IDE 插件。部件库只消费明确的部件导出，扩展管理 IDE 的交互能力。

Studio 不提供 `/api/packages` 路由；依赖操作使用公共 CLI 包管理内核。

IDE 插件不能通过直接导入宿主求解器完成项目工程操作。项目检查、构建、求解及编辑前工程校验由公共操作接口在新进程中激活项目依赖闭包，并返回实际运行包身份。项目没有声明工程包时，不从宿主安装集合回退。

## 扩展 Activity

扩展 Activity 使用通用主侧栏。标题栏提供刷新和管理菜单，搜索框直接查询 Open VSX，支持扩展 ID、排序和分页。无搜索条件时显示可折叠的已安装与推荐分组，可从视图菜单显示已启用或已禁用分组。项目推荐读取 `.vscode/extensions.json`，添加建议经普通文件保存保护写入该文件，可以在源代码管理中审查。Tex Studio 随宿主加载的专业插件列在已安装分组，仍由专业插件发现机制管理。

扩展条目在编辑区复用一个详情标签。详情立即呈现列表已有的名称、描述和下载地址，异步补齐版本、兼容性及该版本的 Open VSX README。只有当前版本确认兼容后才提供安装动作，版本切换重新核验。列表三行依次展示名称与统计、描述、发布者与操作，窄侧栏优先保留名称。扩展整行、分组标题、面板空白、搜索框及搜索工具分别打开对应的右键菜单。搜索工具的显隐保存在浏览器偏好中，可从搜索框容器的菜单恢复。

快速输入在停顿后发出查询，切换查询时取消浏览器端的旧请求并保留已有列表。会话短期复用成功的搜索响应和同版本详情请求，显式刷新清空该缓存。每个列表共享按需挂载的菜单，推荐在可见时查询，宿主复用已读取的版本化清单。

Open VSX 提供扩展身份、版本、图标与 VSIX 下载地址。Tex Studio 可安装只贡献 `contributes.snippets` 的声明式 VSIX，读取包内清单与代码片段，并在语言匹配的源代码编辑器中提供 Monaco 补全。需要 VS Code 运行时、扩展依赖或其他贡献点的条目仍可搜索、查看版本和下载。宿主不执行 VSIX 内的 JavaScript、安装脚本或本地程序。

安装记录与启停状态保存在宿主用户数据目录（`$XDG_DATA_HOME/texsys/studio-extensions.json`，默认 `~/.local/share/texsys/studio-extensions.json`）。扩展可全局启停，也可按项目路径覆盖启停状态。更新使用相同的 VSIX 校验与安装流程，失败保留现有版本。自动更新默认关闭，启用后在打开扩展 Activity 时检查，使用各扩展的自动更新开关。扩展安装和启停不改写项目依赖或专业包锁。

## 工程变更使用现有开发入口

工程变更直接修改源文件，使用现有 Source Control／Git diff 查看差异，在终端运行声明的构建和工程检查。不提供工程变更 activity、专用页面、预览／确认／接受表单，也不提供 `/api/engineering` 专用 HTTP 路由。旧活动选择回退到文件资源管理器。

POC 输出明确的退出码、诊断与结果文件；失败展示、合并门禁和消息通知属于外部 DevOps／协作平台，不在当前 POC 中实现。当前约束见 [ADR-0026](../../docs/adr/0026-git-build-workflow-and-devops-boundary.md)。

## 工作台排版

工作台使用常规字重和不超过 500 的中等字重。标题层级通过字号、间距和颜色区分。空白工作区欢迎页以「启动／最近」和「演练」组织入口。pre-commit 的 `studio-no-bold` 检查拦截界面源码中的粗体样式。

## 本机设置与 AI 提交说明

设置提供语言、工作台布局、源码编辑器与终端的个人偏好，保存在当前浏览器。AI 连接由本机 Studio 后端保存，适用于该用户打开的项目。密钥只写入项目和仓库以外的本机用户配置文件，也不通过 API 回传。

设置以分类导航和紧凑表单呈现，默认打开「常用设置」。搜索支持中英文名称、说明和常用关键词，结果可直接调整普通偏好或打开 AI 连接。「文件」分类与文件菜单共用自动保存和离开前确认状态。普通偏好立即生效，页面注明浏览器保存范围，偏离默认值的条目标记「已修改」并可单项重置。AI 连接注明适用于本机所有项目，保存和测试由用户分别触发。

- BYOK 使用自己的 API 密钥连接兼容 Chat Completions 的服务。BYOA 使用自己的 Agent 网关，网关须提供相同的请求与文本回复格式，可选 Bearer 凭据。基础 URL 填到 API 前缀（例如 `https://api.openai.com/v1`），Studio 附加 `/chat/completions`。远程服务使用 HTTPS，本机回环地址支持 HTTP。
- `GET /api/ai/settings` 返回连接方式、基础 URL、模型或 Agent 标识及密钥是否存在。`POST /api/ai/settings` 保存连接，密钥字段为空时清除。连接测试 `POST /api/ai/test` 使用已保存的配置和固定测试文本。
- 源代码管理的「AI 生成」显示当前范围、接收地址与模型或 Agent，确认后以 Git 状态快照请求 `POST /api/ai/commit-message`。只发送范围内的 UTF-8 暂存差异，最多 48 KiB，快照、范围和连接须与确认时一致。服务返回可编辑的提交说明草稿，实际提交仍由用户触发。

## HVAC 首个切片

专业 ID 为 `texsys:hvac`。工作台包含系统设计、设备表、器件库、仿真分析、检查报告、模型源与专业能力说明。复用既有工程图元、系统投影、check、build 与动态求解器，浏览器不实现第二套物理方程。

「场景预览」从构建清单选择明确的 USD 产物与运行快照，不按文件修改时间寻找场景。没有清单或存在多个候选且未指定身份时，返回明确的缺失或歧义诊断。视图显示来源和适用状态，支持标准网格、立方体和 `BrepArray` 包络、对象选择、旋转、缩放和重置视角。几何使用预览配色，场景和工程输入均为只读。

Web 标题栏包含左侧应用菜单、受保护的后退／前进和全局面板按钮组，以及正常工作台宽度下按窗口居中的项目命令入口。菜单不足时按原顺序收进“更多”，不压缩五个按钮；一级菜单点击展开，二级可悬停展开。原生窗口控件预留由宿主能力声明，Web 不留空白红绿灯占位。菜单命令使用平台无关模型，命令中心采用 Hanging：标题栏项目名原位切换为输入框，结果列表从其下沿展开，无独立弹窗与全页遮罩；点击与快捷键共用该状态，菜单模型绑定相同入口。当前命令面板与菜单共用命令 ID；Web 应用菜单已经复用这些处理入口；原生菜单绑定留给实际桌面宿主。左侧 Activity Bar 默认按文件资源管理器、搜索、源代码管理、扩展、部件库、项目实例排序。扩展列出宿主已加载的专业插件。切换 Activity 保留中央文档，打开资源时才切换文档。文件编辑与产物预览共享文档区域，构建产物作为独立文件打开；专业工作台可以提供已有的分析与回放视图。底部的问题与任务日志通过标签互斥呈现。文档标签支持打开、切换与关闭。参数草稿属于当前对象，关闭文档或收起属性面板不丢弃草稿；切换对象前须保存或显式放弃，草稿未保存时不能提交计算。

状态栏左侧依次显示宿主、Git 分支、问题，以及项目、专业和任务等 Tex Studio 入口。错误和警告共用一个「问题」按钮；点击后可在面板定位源码诊断。工程问题保留专业判定与统计。右侧跟随活动源码编辑器，显示行列与选区、缩进、UTF-8 编码、行尾、语言状态和语言模式。可调整缩进、语言、编码和行尾；编码及行尾随普通文件保存生效。预览和终端焦点不显示源码字段，通知保持可用。右键可逐项隐藏；整栏从「查看 → 状态栏」或命令面板恢复。详见 [DDR-0018](../../docs/ddr/0018-studio-status-bar-editor-and-workbench-actions.md)。

应用菜单按「文件／编辑／查看／转到／运行／终端／帮助」排列。文件菜单提供未命名文本、项目内新建与打开、最近文件、另存为、全部保存和还原。未命名文本首次保存时询问项目相对路径。全部保存先处理有路径的文件，再逐个为已编辑的未命名文本命名。自动保存默认关闭，启用后延时保存有路径的文件，外部版本冲突时保留编辑内容。还原从磁盘读取，放弃未保存编辑前须确认。最近文件按项目记录，离开页面的确认可独立设置。

编辑菜单和命令面板共用当前源文件的撤销、重做、查找与替换命令。替换先修改编辑器中的内容，保存时才写入文件。编辑菜单也可打开项目搜索与替换，对支持的文本格式切换行注释，并提供全选及多处匹配选择。查看菜单的「打开视图」按名称筛选工作台和当前专业的视图。工具面板可停靠在编辑区底部、左侧或右侧，侧边宽度与底部高度分别记忆。转到菜单支持源文件的行列定位，并按当前报告的问题顺序定位到对象、工况或检查记录。暖通的工程对象选择器可搜索定义和完整实例路径，打开时在模型源数据视图中定位声明。转到定义使用选中对象的类型，查找使用位置列出该类型的项目实例。运行菜单显示当前专业提供的工程操作以及取消后台任务。暖通可使用上次操作的工况和求解后端，在当前输入修订上重新运行。终端菜单提供当前会话的聚焦、清空、终止及脚本命令。帮助菜单从已绑定的菜单命令生成快捷键参考。菜单与专业命令共用可用状态和命令处理入口。

类型选择只显示类型默认值、接口、依据和使用实例，不把代表实例当作类型编辑。实例编辑仍仅保存实例覆盖。源数据定位区分类型与实例的完整对象路径。

设计画布默认展示设计参数。用户显式打开结果叠加后持续显示工况、求解后端、时刻与版本状态；只有结果和图纸均对应当前输入时才将计算值叠加到图面。分析与成果区允许查看已保留的历史文件，但必须标记历史输入。

问题视图汇集模型诊断、图纸待办及未满足的工况约束，分别保留最新模型检查和图纸检查报告。诊断只能凭显式对象引用定位，不从报错文字猜测对象。工况约束可定位变量与首次越限采样点；没有对应越限采样点时明确定位到极值或初始时刻，不将采样时间声称为连续物理越限时间。

后台操作为模型检查、图纸构建、单工况或全部工况动态求解。构建生成系统图与原理图；仿真在输入副本上求解并生成关联图纸。任务完成不表示工况通过，停泵失效仍呈现为工程 fail。模型编辑使旧图纸和计算结果失效，重新构建后恢复当前结果。

架构搜索、物理布局布线、正式提资、拓扑编辑与器件类型创建仅显示明确的能力边界；不能提供伪造执行或把图元比例调整称为器件性能建模。

## 验证
