# Tex Studio 工作台契约 v1

> 状态：本地 Web Editor，包含通用项目编辑能力与可选专业预览。Electron、远程账户和正式提资发布不在本子集中。

## 专业插件与宿主

Python entry point 组为 `texsys.studio`，入口对象实现 `StudioPlugin`。清单必须声明 `id`、`name`、`version`、`api_version=1`、`discipline` 和能力列表。专业 ID 使用命名空间，不允许重复；错误插件独立诊断，不冒充可用专业。宿主不导入具体专业，前端贡献通过插件声明的 TSX 入口组成。

Tex Studio 首先是项目 Editor。专业工作台是通用内核、通用模块与领域模块的一组配置；BOM、系统图、原理图和计算结果作为专业文档或 Preview 接入。通用文件浏览、全文搜索、Git 与文本编辑由宿主提供，无专业插件时仍可使用。

前端贡献实现 `WorkbenchPlugin`，提供清单和 React 专业组件。专业通过宿主 `WorkbenchSurface` 贡献 Activity、资源、文档标签、预览、属性和底部内容；宿主统一组织 Explorer、Search、Source Control 和源文件文档。专业 Activity 排在三个通用入口之后。宿主负责启动、专业切换、项目上下文、错误呈现、状态刷新、全局布局控制及任务内容。专业组件通过 `layout` 和 `changeLayout` 管理面板开关和尺寸。`taskPanel` 将宿主任务内容嵌入底部面板，`navigationRequest` 传递概览／能力导航请求。切换隐藏但不销毁专业工作台；源文件文档属于项目，切换 Activity 或专业不会丢失未保存内容。专业预览异常时仍可使用通用编辑入口。

宿主的 `showTasks(jobId?)` 可定位具体任务；可选 `taskResult` 将用户从任务面板发起的打开结果请求交给所属专业，宿主不解释专业产物。此请求包含任务记录和递增令牌，不替代结果的输入版本校验。

启动命令为 `uv run texsys studio -p PROJECT --port 8710`；`--open` 可打开浏览器。仅监听本机回环地址。宿主的会话令牌与同源校验用于保护本地读写 API，不能作为远程多用户认证。

## 数据与操作

`GET /api/state` 返回协议版本、项目身份及输入修订、专业清单、插件数据、任务和诊断。输入修订覆盖清单、设计锁、source 和 assets 的路径与内容摘要，不覆盖生成物。外部文本修改在刷新时重新读取，不能被缓存冒充当前模型。

`GET /api/files` 在同一会话授权下索引当前项目文件与目录，包含空目录，文件与目录各最多 5000 项并显式标明截断。排除项目构建目录、版本库内部目录、依赖缓存和符号链接。`GET /api/file?path=...` 返回项目内文件内容或不可编辑原因，以及文件版本。文本编辑限 1 MiB UTF-8；显示统一换行，保存保留原有换行形式和 BOM。

`POST /api/file` 支持 `create`、`create_text`、`mkdir`、`save`、`rename`、`delete`。保存、文件重命名和删除携带基准 `version`，不一致返回 409。保存使用同目录临时文件原子替换。另存为用 `create_text` 一次创建完整的 UTF-8 文件，目标已存在时返回 409。路径拒绝越界、构建产物、版本库内部文件和符号链接。目录重命名和删除只支持空目录。关闭未保存文档时可保存、放弃或取消，离开浏览器页面时默认提示未保存内容。

`GET /api/search?q=...&case=true&word=true&regex=true&include=...&exclude=...` 搜索已保存项目文本。默认按字面量匹配；可切换大小写、整词和 Python 正则。包含／排除支持路径片段、通配符及逗号分隔。返回独立匹配 `matches` 和按文件／行组织的 `lines`；同一行多个匹配只占一条结果，保留各自列位置与总计数。点击高亮精确定位文件中的对应文本。索引沿用文件浏览，跳过二进制与超过 1 MiB 文件；扫描限 32 MiB、匹配限 1000，显式显示跳过和截断。正则在独立进程执行，2 秒超时，最多两个并行任务。未保存编辑不参与磁盘搜索。

Code Search 提供搜索／替换、三种匹配开关、保留替换大小写、可折叠的路径条件、文件分组与计数、平铺结果、折叠全部、清空与刷新，并能在中央文档区域打开搜索结果。搜索框的焦点边框属于整个输入组，内层输入没有第二个边框。

`POST /api/search/replace` 先返回逐文件替换预览、变更计数和 `snapshot`。请求带 `apply:true` 与预览的快照后重新计算并核对文件版本，过期返回 409；每个文件仍通过通用文件 API 原子保存。支持全部匹配或显式文件范围，正则替换支持 `$1`、`${name}`、转义换行与制表符。搜索截断时禁止替换；前端对涉及未保存草稿的文件要求先处理草稿。批次不承诺跨文件事务：执行中出现磁盘错误会返回 `complete:false`、已完成文件列表和错误，避免把部分成功显示成全部完成。

`GET /api/scm` 返回真实 Git 分支、项目相对仓库范围、暂存／未暂存变更和操作快照。项目可位于父级仓库，默认列表仅显示项目范围；显式选择 `scope=repository` 时管理服务端定位的整个 Git 仓库。`GET /api/scm/diff?path=...&staged=true` 区分 HEAD 与暂存区、暂存区与工作区；未跟踪文本显示新增内容，差异限 1 MiB 并标记截断。

源代码管理面板顶部显示当前范围，范围菜单可查看对应的完整路径。macOS 和 Linux 上的集成终端通过同源 `/api/terminal/ws` 连接独立的 PTY 和交互式 Shell。每个会话从项目根目录启动，显式请求时可从所属 Git 仓库根目录启动。用户在 Shell 内可以按本机用户权限切换目录。切换会话或隐藏面板时保留进程，终止会话时回收进程，刷新页面后重新建立会话。Shell 返回提示符或会话退出时刷新当前源代码管理范围。菜单执行选定文本或已保存的 Shell／Python 脚本时使用独立终端会话。旧的 `POST /api/terminal` 保留逐条执行接口和原有目录规则。

`POST /api/scm` 支持初始化当前无仓库项目、逐文件或批量暂存／取消暂存、确认后放弃工作区更改和本地提交。变更操作携带状态快照，文件或索引变化后返回 409。暂存只操作显式文件路径；提交只包含已暂存内容。父级仓库存在项目外的暂存变更、隐藏变更或未解决冲突时拒绝提交，避免夹带其他内容。Git 运行使用固定参数和字面量路径，不开放任意命令。`GET /api/scm/history` 返回整个仓库的真实提交拓扑，初次 50 条，最多 500 条；`GET /api/scm/commit` 按所选范围返回历史差异，合并提交以第一父提交为基准。拉取、推送、分支创建／切换和专门的合并编辑器留待后续。

`POST /api/edit` 包含专业、基准修订与专业定义的编辑操作。宿主串行处理提交；基准不一致返回 409。专业校验编辑候选后原子写入权威文件，返回新修订。v1 HVAC 支持实例参数完整覆盖与恢复继承；保存保留数值、单位、六态和来源，不改变共享 Component。撤销使用同一接口恢复前一绑定，仍需通过修订检查。

`POST /api/jobs` 包含专业、操作、基准修订与专业参数。后台任务基于提交时复制的 source、assets 和清单快照执行，保留原始输入摘要；本地路径依赖先验证原锁，再显式重绑定到相同来源并为执行副本锁定。任务不修改工作项目或自动采用求解结果。v1 同一项目同时运行一个任务，避免无限排队。

任务操作由专业声明和校验，不接受任意 shell、路径或命令。运行进程的状态为 running、completed、failed、cancelled 或 interrupted；工程结论单独记录 pass、fail、indeterminate 或 error。用户取消时终止任务进程组，重新启动宿主后未完成任务标记 interrupted。`POST /api/jobs/ID/cancel` 取消任务。

`GET /api/artifact?path=...` 只读取项目 build 内的固定文件。运行目录保存请求、输入副本、日志、结果与任务元数据。结果是否适用于当前设计由输入修订判断；历史产物可以查看但必须标记失效。页面刷新后仍可以读取持久化任务及结果。

项目原有 CLI 生成物可以作为历史预览读取；没有完整 Studio 输入修订的产物不自动标记为当前有效，重新运行后建立当前版本关联。

## 本机设置与 AI 提交说明

设置提供语言、工作台布局、源码编辑器与终端的个人偏好，保存在当前浏览器。AI 连接由本机 Studio 后端保存，适用于该用户打开的项目。密钥只写入项目和仓库以外的本机用户配置文件，也不通过 API 回传。

- BYOK 使用自己的 API 密钥连接兼容 Chat Completions 的服务。BYOA 使用自己的 Agent 网关，网关须提供相同的请求与文本回复格式，可选 Bearer 凭据。基础 URL 填到 API 前缀（例如 `https://api.openai.com/v1`），Studio 附加 `/chat/completions`。远程服务使用 HTTPS，本机回环地址支持 HTTP。
- `GET /api/ai/settings` 返回连接方式、基础 URL、模型或 Agent 标识及密钥是否存在。`POST /api/ai/settings` 保存连接，密钥字段为空时清除。连接测试 `POST /api/ai/test` 使用已保存的配置和固定测试文本。
- 源代码管理的「AI 生成」显示当前范围、接收地址与模型或 Agent，确认后以 Git 状态快照请求 `POST /api/ai/commit-message`。只发送范围内的 UTF-8 暂存差异，最多 48 KiB，快照、范围和连接须与确认时一致。服务返回可编辑的提交说明草稿，实际提交仍由用户触发。

## HVAC 首个切片

专业 ID 为 `texsys:hvac`。工作台包含系统设计、设备表、器件库、仿真分析、检查报告、模型源与专业能力说明。复用既有工程图元、系统投影、check、build 与动态求解器，浏览器不实现第二套物理方程。

Web 标题栏包含左侧应用菜单、受保护的后退／前进和全局面板按钮组，以及正常工作台宽度下按窗口居中的项目命令入口。菜单不足时按原顺序收进“更多”，不压缩五个按钮；一级菜单点击展开，二级可悬停展开。原生窗口控件预留由宿主能力声明，Web 不留空白红绿灯占位。状态栏按项目 → 专业 → 分支排列，分支为只读 Git 身份，与输入修订分别展示。菜单命令使用平台无关模型，命令中心采用 Hanging：标题栏项目名原位切换为输入框，结果列表从其下沿展开，无独立弹窗与全页遮罩；点击与快捷键共用该状态，菜单模型绑定相同入口。当前命令面板与菜单共用命令 ID；Web 应用菜单已经复用这些处理入口；原生菜单绑定留给实际桌面宿主。左侧先显示文件资源管理器、搜索、源代码管理，再显示系统对象、器件类型库、工况与分析、成果文件等专业 Activity；切换 Activity 不替换中央文档，打开资源才改变文档。文件编辑与专业预览共享文档区域；项目概览、图纸、设备表、类型库、源数据、分析、检查和成果继续使用专业视图。底部的问题与任务日志通过标签互斥呈现。文档标签支持打开、切换与关闭。参数草稿属于当前对象，关闭文档或收起属性面板不丢弃草稿；切换对象前须保存或显式放弃，草稿未保存时不能提交计算。

应用菜单按「文件／编辑／查看／转到／运行／终端／帮助」排列。文件菜单提供未命名文本、项目内新建与打开、最近文件、另存为、全部保存和还原。未命名文本首次保存时询问项目相对路径。全部保存先处理有路径的文件，再逐个为已编辑的未命名文本命名。自动保存默认关闭，启用后延时保存有路径的文件，外部版本冲突时保留编辑内容。还原从磁盘读取，放弃未保存编辑前须确认。最近文件按项目记录，离开页面的确认可独立设置。

编辑菜单和命令面板共用当前源文件的撤销、重做、查找与替换命令。替换先修改编辑器中的内容，保存时才写入文件。编辑菜单也可打开项目搜索与替换。查看菜单的「打开视图」按名称筛选工作台和当前专业的视图。转到菜单支持源文件的行列定位，并按当前报告的问题顺序定位到对象、工况或检查记录。运行菜单显示当前专业提供的工程操作以及取消后台任务。集成 Shell 的会话和脚本命令保留在终端菜单。菜单与专业命令共用可用状态和命令处理入口。

类型选择只显示类型默认值、接口、依据和使用实例，不把代表实例当作类型编辑。实例编辑仍仅保存实例覆盖。源数据定位区分类型与实例的完整对象路径。

设计画布默认展示设计参数。用户显式打开结果叠加后持续显示工况、求解后端、时刻与版本状态；只有结果和图纸均对应当前输入时才将计算值叠加到图面。分析与成果区允许查看已保留的历史文件，但必须标记历史输入。

问题视图汇集模型诊断、图纸待办及未满足的工况约束，分别保留最新模型检查和图纸检查报告。诊断只能凭显式对象引用定位，不从报错文字猜测对象。工况约束可定位变量与首次越限采样点；没有对应越限采样点时明确定位到极值或初始时刻，不将采样时间声称为连续物理越限时间。

后台操作为模型检查、图纸构建、单工况或全部工况动态求解。构建生成系统图与原理图；仿真在输入副本上求解并生成关联图纸。任务完成不表示工况通过，停泵失效仍呈现为工程 fail。模型编辑使旧图纸和计算结果失效，重新构建后恢复当前结果。

架构搜索、物理布局布线、正式提资、拓扑编辑与器件类型创建仅显示明确的能力边界；不能提供伪造执行或把图元比例调整称为器件性能建模。

## 验证

验证插件空状态、重复与不兼容诊断；验证外部修改冲突、实例覆盖／继承／撤销；验证任务输入快照、取消、重启记录和旧结果标记。浏览器核验专业入口、视图切换、对象选择、参数保存、实际后台求解、失败工况、结果回放和窄屏布局。

本规范关闭 OQ-16、OQ-17 中首个本地切片的接入问题；完整跨端 SDK、远程执行与跨专业提资交换继续由对应开放问题跟踪。
