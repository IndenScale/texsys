# SDL 核心模型

> 状态：草案。本文记录当前已经对齐的核心概念，不确定具体文本语法。

## 核心概念

SDL 以六个概念构成组成、连接和空间语义的核心：

1. **Component**
2. **Instance**
3. **Port**
4. **Netlist**
5. **Layout**
6. **Placement**

Connection、Net 和 Frame 是支撑这些核心概念的语义对象。

BOM、系统图、原理图、布置图、设备表、计算书等交付物**不是**核心对象，而是这些对象的投影（见「交付物与视图」一节）。

## Component

Component 是可复用的类型定义或设计资产，可以声明参数、端口、行为、几何、内部实例、Netlist、候选 Layout、约束和设计依据。

Component 采用递归组合模型：

- 没有内部实例的 Component 是叶子部件；
- 包含内部实例、Netlist 或 Layout 的 Component 是复合部件；
- 顶层设计同样是 Component，其实例化结果是整个设计的根实例；
- “系统”和“装配”只是 Component 在特定层级与语境中的角色，不作为独立核心概念；
- 叶子与复合是结构状态，不要求使用不同的声明语法。

每个 Component 都可以定义自己的外部端口契约和内部实现。

## Instance

Instance 是 Component 在具体上下文中的实例化结果，具有稳定身份、参数绑定和所属层级。实例化是产生 Instance 的操作，不作为另一个独立核心对象。

实例可以先存在，之后再连接或放置。已实例化但未连接、已实例化但未放置、已连接但未完成布局，都是合法的设计中间状态。

Component 与 Instance 必须严格区分。修改共享 Component 定义不允许的实例内部结构时，应创建参数化变体或新的 Component 定义，而不是静默修改类型。

## Port

Port 是 Component 与外界交互的类型化边界，可以声明交互类型、方向、单位、容量、协议、兼容条件、连接数量限制和空间参考信息。

Port 在 Component 上定义，并随 Component Instance 自动派生。SDL 不设置独立的 PortInstance 生命周期，也不要求用户显式实例化、创建或删除实例端口。

不同实例上的同名端口通过实例路径和端口路径共同定位，例如 `pump-01.inlet`。该路径直接引用 Port，不引入独立的 Endpoint 对象或端口副本。

## Netlist、Connection 与 Net

Netlist 描述 Component 内部的逻辑连接拓扑，不描述空间位置。

### Connection

Connection 是两个 Port 之间的连接边，可以具有稳定身份、连接类型、方向、容量、参数、所属 Net、设计依据和验证状态。

### Net

Net 是由一组 Port 和 Connection 构成的类型化网络，表示连接关系的整体功能与语义。Net 可以拥有稳定身份、网络类型、网络级参数、目标、约束、关联评估器以及空间路由和交付物引用。

Net 可以表示电源、传热、水循环、控制信号、巡检动线、疏散动线等不同网络。核心模型不预设所有 Net 都具有相同方向、连通或状态语义，具体规则由网络类型及其评估器定义。

Connection 决定局部连接事实，Net 保存网络身份和整体语义。[JSON 交换子集 v2](02-json-exchange.md#显式网络v2) 定义根部件内的显式声明和成员校验。匿名推导与跨层级成员规则见 [OQ-3](../../docs/open-questions.md#oq-3)。

在复合 Component 内，Netlist 可以连接内部实例端口和 Component 自身端口。Netlist 与 Layout 必须引用同一组内部实例，不得各自创建部件副本。

## Layout

Layout 描述一个 Component 的内部实例在共同空间上下文中的组织方式。一个 Component 可以拥有多个候选 Layout，以支持方案比较而无需复制系统模型。

Layout 可以包含根坐标系及可选地理配准、Placement、空间边界、定位约束、验证约束、安装与维护区域、禁入区域和路由几何引用。

Netlist 管逻辑连接，Layout 管空间组织。

## Placement 与 Frame

Placement 是某个 Component Instance 在某个 Layout 中的空间绑定，至少关联：

- 被放置的实例；
- 所属 Layout；
- 实例局部 Frame 与参考 Frame；
- 位姿表达或待求解状态；
- 自由度与定位状态。

Frame 是解释位姿所需的坐标参考系。Placement 的核心语义是实例局部 Frame 相对于另一 Frame 的变换，而不是孤立的一组坐标。

地理坐标、全局坐标和相对坐标不是不同的 Placement 类型，而是参考 Frame 不同。实例通常使用 Layout 的局部工程坐标系，地理坐标通过 Layout 的地理配准变换获得。

Placement 支持：

1. **未放置**：位置未知，不能与坐标为零混淆；
2. **固定位姿**：位姿已经确定，自动布局器不得修改；
3. **部分定位**：部分自由度固定，其余自由度开放；
4. **约束求解**：通过几何约束确定位姿，可以附带非强制性的初始位姿。

直接相对位姿引用必须可求值且无环；几何约束图可以包含闭环，由求解器处理。Component 的组成层级可以是树，但空间关系不受树状结构限制。

空间约束分为：

- **定位约束**：用于减少自由度，例如重合、同轴、平行、距离和角度；
- **验证约束**：用于判断布局是否成立，例如最小净距、禁入区域和维护空间，不应被求解器擅自转化为唯一位置。

欠约束表示仍有开放自由度，不一定错误；是否允许取决于设计阶段与交付要求。过约束需要区分一致冗余、冲突过约束和数值病态。编译期负责引用、单位、坐标系和直接位姿环等静态检查，布局求解与评价阶段负责自由度、数值残差、冲突和解的稳定性检查。

## 交付物与视图

BOM、系统图、原理图、布置图以及设备表、计算书等交付物都是同一模型的投影，不是核心对象。它们按两个正交维度界定：

- **逻辑维度**：组成 → 组成＋拓扑 → 组成＋拓扑＋行为；
- **空间维度**：未放置 → 部分 Placement → 完整约束布局。

空间维度与逻辑维度独立演化，不是逻辑维度的下游阶段。架构依据见 [ADR-0018](../../docs/adr/0018-deliverable-semantics-and-baseline-gates.md)。

### BOM

BOM 描述**组成与数量**：在明确统计范围内记录对象、数量、当前规格及其状态。BOM 中的层级与分类不是本质，而是对同一条目集合的不同聚合视图，聚合规则由显式视图规格定义。

BOM 条目允许聚合多个实例；条目身份的强度随 profile 递进，可研设备组、工程设计实例、采购项与物理资产通过显式映射关联（见 [ADR-0014](../../docs/adr/0014-target-bom-and-configuration-baselines.md)）。相对地，图类交付物的节点保持实例身份，同一语义对象的重复 occurrence 不得被统计为多个设备。

### 系统图

系统图（system diagram）描述**组成＋拓扑**：实例、端口与连接关系。拓扑是类型化网络，方向、连通与状态语义由网络类型及其评估器定义，不预设为有向图。

颗粒度是视图属性：子系统可以在顶层视图中折叠为黑盒节点，展开后为内部子图；折叠前后，跨越边界的端口契约（Port Signature：介质、电压等级、协议等）必须严格守恒。展开边界、筛选、分组与分页由视图契约声明，筛选后的视图不得被误认为完整系统拓扑。

### 原理图

原理图（schematic）在系统图之上增加**行为承诺**：它承诺"系统如何工作"，通过行为参数标注（特性曲线、设计工况点、容量、热排放、控制关系等）与行为定义引用兑现。行为本体属于 Component 定义，原理图不成为行为的第二事实源。其信息来源为：

- 连接、介质、流向来自 Netlist／Net；
- 行为参数与行为定义引用来自 Component 行为与参数绑定；
- 相对位置、分区与标高等空间标注来自 Layout，只在确有依据时输出，属于可选增强而非本质成分；
- 图面上的文字、图例、标注属于投影层，不得引入模型之外的事实。

**几何归属按是否进入行为方程划分**：影响系统性能的几何（水力直径、等效长度、换热面积、高差等）以集总参数形式进入行为模型，属于原理图语义；只决定空间组织的几何属于 Layout。同一几何事实可以两侧都使用，但始终只有模型一个事实源，由投影与提取保证一致，不靠图面之间人工同步。

行为未定义或待定（pending）时，投影必须显式降级为系统图或标记行为缺失，不得生成"看起来像原理图"的交付物。

由此产生四条约束：

1. **不需要"保持一致"。** 原理图由模型生成，模型与图之间的漂移在构造上被排除，因此不需要一致性检查。
2. **图面不是第二事实源。** 原理图编辑器可以直接充当模型编辑器（这对习惯于画图的使用者是低摩擦入口），但任何图面编辑都必须落在模型上。
3. **人工编辑必须归属明确。** 专业注记、现场确认标记等一旦由人编辑，重新生成会覆盖判断，其所有权与合并规则见 [ADR-0017](../../docs/adr/0017-schematic-projection-symbol-resolution-and-rendering.md)。
4. **投影允许降级。** Layout 不完整时，缺少 Placement 只影响空间类信息，不得阻塞连接类表达；行为不完整同理，只降级行为承诺，不得伪装完整。降级规则见 [ADR-0017](../../docs/adr/0017-schematic-projection-symbol-resolution-and-rendering.md) 与 [ADR-0018](../../docs/adr/0018-deliverable-semantics-and-baseline-gates.md)。

图与模型之间的可逆性属于界面层问题，不构成语言契约。设备表、材料表、计算书的组织方式与此同理：均为同一模型的不同投影（方法论依据见《设计自动化原理》第七章 7.5）。

### 布置图

布置图（layout drawing）描述实例与连接在共同空间上下文中的**空间嵌入**：位姿、包围几何、定位约束、验证约束与路由几何，语义由 Layout、Placement 与 Frame 承载。

布置图的**结构合法性**只依赖实例身份：Placement 必须引用已存在的实例，路由几何必须映射 Net，这是任何时刻都成立的静态不变量。布置图的**行为可接受性**依赖行为模型与验证证据，二者不得混为一谈：行为未建模不阻塞布置工作，只阻塞"行为已验证"的声明。

### 几何预算与回注验证

原理图阶段对尚未确定的几何声明**几何预算**：性能允许的参数上下界（如等效长度、流阻上限），参数状态为假设（assumed）并记录依据，使行为评估先行可解。几何预算是设计承诺。

布置阶段将几何预算作为硬约束参与定位与路由求解；布置完成后，提取器从几何计算实际参数，回注到**模型与验证证据**并重新评估行为：实际值落入预算容差内，参数转为已知（known）；超出预算则验证失败。回注不得直接修改原理图等投影产物，投影随模型重新生成。

### 交付门禁

任何完整度的中间状态都合法；交付闭环由 target 契约规定。施工等交付阶段的基线准出要求布置图、空间完整性、行为验证与几何回注断言整体闭环，缺失按未闭环处理，不得以出图顺序禁令的形式提前施加。阶段与基线准出规则见 [ADR-0018](../../docs/adr/0018-deliverable-semantics-and-baseline-gates.md)。

## 所有权与不变量

- Component 拥有内部实例声明、Netlist 和候选 Layout；
- Instance 引用 Component 定义，不是 Component 定义的副本；
- Port 属于 Component 定义，其实例端口随 Instance 自动派生；
- Connection 和 Net 引用 Port，不保存端口副本；
- Connection 表示两个 Port 之间的边，Net 表示具有整体语义的网络；
- Layout 放置当前 Component 的内部实例；
- Placement 引用 Instance，而不是直接引用 Component 类型；
- 同一 Layout 中的实例默认至多有一个有效 Placement；
- 同一实例可以在不同候选 Layout 中拥有不同 Placement；
- 根实例没有父实例，也不被放置到自身 Layout 中。
