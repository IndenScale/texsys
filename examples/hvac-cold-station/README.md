# 冷站设备布置与真实资料输入审查

本项目保留原有设备布置、安装事件和通风／露点概念校核，并通过工程变更入口审查一份冻结的真实验收报告配置。两部分分别声明对象和范围；参考资料里的两台冷机没有被映射成原概念模型中的单台通用冷机。

## 两组输入的用途

| 输入                                            | 用途与边界                                                                                          |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `src/hvac.json`、`src/system.sdl.json`          | 1 台通用 100 kW 冷机、4 个通用泵与 80 kW 负荷的设备布置概念模型；用于原有 BOM、投影、安装及环境校核 |
| `assets/reference/cold-station-acceptance.json` | 真实初验／终验资料的脱敏事实快照；保留来源 SHA-256、位置、配置声明、资料差异及未确认事项            |
| `src/reference-capacity.study.json`             | 本轮审查者引入的负荷率、可用台数和容量余量要求；用全文件摘要固定上述快照                            |

源快照是报告声明的输入记录，数值状态保留 `assumed`，尚未由专业人员确认。原始 DOCX／PDF 留在本地参考目录，不随项目发布；项目可用脱敏快照重跑算术，但不能仅凭摘要独立核实原件内容或真实性。

## 工程问题

在指定负荷率和两台冷机可用的假设下，报告声明的冷源能力能否覆盖机柜负荷的账面合计？哪些条件仍缺少性能证据？

终验报告列出 2 台 75 kW 冷机、7 架 15 kW 假负载机柜及 2 架 45 kW 液冷机柜。报告未声明机柜同时满负荷运行，也未给出这组配置在特定水温、湿球温度下的实测冷量。因此，本审查明确引入以下条件：

- 两类机柜的报告 kW 值暂作为同一冷源边界内的名义热负荷上限。
- 冷机可用台数为审查假设；暂不考虑降额、寄生热负荷、备用冗余、故障和瞬态。
- 风冷与液冷负荷率分别可修改，默认均为 0.6，表示本轮假设，不是报告给出的运行工况。
- 不把板换、空调末端的换热能力或冷却塔流量加到冷源制冷能力上。

对应算式为 `7 × 15 × 风冷负荷率 + 2 × 45 × 液冷负荷率`，可用账面冷量为 `可用冷机台数 × 75 kW`。

| 状态                     | 假设负荷 | 可用账面冷量 | 账面余量 | 工程结论边界                                               |
| ------------------------ | -------: | -----------: | -------: | ---------------------------------------------------------- |
| 两类负荷率 0.6、两台可用 |   117 kW |       150 kW |    33 kW | 算术判据满足；真实性能仍无法判定                           |
| 两类负荷率 1.0、两台可用 |   195 kW |       150 kW |   −45 kW | 该假设下容量账面不足；不能据此断言现场实际不足或否定原终验 |
| 恢复两类负荷率 0.6       |   117 kW |       150 kW |    33 kW | 恢复算术结果；缺失性能证据没有因此消失                     |

## 可重跑入口

从仓库根目录执行：

```bash
uv run --locked texsys lock -p examples/hvac-cold-station
uv run --locked texsys engineering inspect --adapter hvac:reference-capacity -p examples/hvac-cold-station
uv run --locked texsys engineering run hvac:reference-capacity -p examples/hvac-cold-station
```

初始工程判定应为 `indeterminate`，CLI 退出码为 3。`arithmetic_execution: completed` 表示上述算术已执行；`solver_execution: not-run` 表示真实热力／水力性能求解没有运行。运行成功与工程可接受分别判断，当前证据不能通过 `engineering accept`。

完整流程验证使用独立副本，不修改标准示例：

```bash
uv run --locked tools/verify_reference_engineering_poc.py
```

脚本检查基线、假设修改、旧证据失效、容量反例、恢复、接受拒绝以及快照变化后摘要不匹配。脚本本身通过仅说明流程符合预期，不能改写领域结果中的 `indeterminate` 或 `fail`。

## 审查与继续建模

在承载本项目的 Tex Studio 中打开「工程变更」，选择「真实资料容量审查」，查看来源、负荷率、影响和逐项判据。所有数值变更先预览，再应用与重算。当前运行的 Studio 项目可能不同；实例管理遵循仓库 `AGENTS.md`，不另起第二个实例。

原资料之间的塔类型、数量、泵数量和机柜配置差异保留在快照中，不能静默选择某个版本代替全部事实。终验报告声明的安装、单机调试和建设质量结论保留其原范围；本工具新增审查不取代该历史决定。

接入真实性能求解前仍需核实设备型号、额定工况、性能曲线、回路和测点身份、校准时序、同时运行条件及责任人的审查。详见 [资料核读与边界](../../docs/cold-station-reference-review.md)。
