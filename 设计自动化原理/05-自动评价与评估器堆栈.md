# 第五章　自动评价与评估器堆栈

## 5.1 评价是设计自动化的中心

自动评价回答三个不同问题：

1. 方案是否可行；
2. 方案在可行集合中表现如何；
3. 当前证据是否足以支持决策。

第三个问题经常被忽略。一个高分方案可能只经过了粗模型评价，一个低分方案也可能因为输入缺失而被错误淘汰。设计系统必须同时表达结论和证据强度。

评价不是综合完成后的附属步骤，而是综合能够成立的前提。没有评价，生成器只能生产变化，无法生产有方向的搜索。

## 5.2 评价维度

常见评价维度包括：

- **可行性**：结构、参数和行为能否成立；
- **合规性**：是否满足适用规则和批准条件；
- **性能**：容量、效率、精度、响应等表现；
- **经济性**：采购、实施、运行和维护代价；
- **可实施性**：能否制造、施工、安装和调试；
- **可运维性**：能否检查、维修、替换和升级；
- **鲁棒性**：条件波动和模型误差下是否仍然成立；
- **可持续性**：资源、环境和生命周期影响；
- **可审查性**：结论是否可解释、可追溯和可复现。

不同维度不一定能够通约。系统应避免在缺乏明确授权时，把它们全部压缩成一个总分。

## 5.3 目标与代理之间的距离

评价函数通常只是设计目标的代理。仿真得分是实际运行的代理，规则检查是合规目标的代理，成本模型是真实经济后果的代理。

代理越方便计算，越需要警惕它与真实目标之间的距离。自动综合会系统性地利用代理的漏洞：如果评价只计算平均性能，搜索可能牺牲极端工况；如果成本只计算采购，搜索可能把代价转移到维护；如果几何规则过于简化，搜索可能产生指标合格但无法实施的方案。

因此，评价系统需要持续接受真实项目、测试和运行数据的校准，而不能因为形式化完成就被视为永远正确。

## 5.4 评估器堆栈

一个通用评估器堆栈可以按证据成本与强度分层：

| 层级 | 典型评估器                     | 主要作用               |
| ---- | ------------------------------ | ---------------------- |
| L0   | 模式、类型、单位和完整性检查   | 排除无效描述           |
| L1   | 依赖、接口和静态规则检查       | 排除结构与合规问题     |
| L2   | 解析计算和快速近似模型         | 低成本筛选候选         |
| L3   | 数值求解、专业仿真和测试运行器 | 获得主要性能证据       |
| L4   | 鲁棒性、敏感性和不确定性分析   | 检查结论稳定性         |
| L5   | 实物试验、现场验证和运行数据   | 校准模型，建立最终证据 |

分层不意味着高层级总是比低层级“更正确”。规则检查和现场试验回答的是不同问题；高层级评估器也可能因为模型不适用而给出无效结论。

## 5.5 评估器契约

每个评估器都应声明清晰的运行契约：

- 所需输入及模式版本；
- 前置条件和适用范围；
- 所需数据、规则和部件模型版本；
- 输出结构、单位和状态语义；
- 精度、近似和已知限制；
- 运行成本、超时和资源需求；
- 确定性条件及随机种子要求；
- 版本和验证状态。

输出不应只有一个数值，还应包括适用对象、运行状态、诊断、关键中间结果和输入摘要。失败时也应区分输入错误、数值不收敛、资源超时和内部缺陷。

## 5.6 评估器自身的验证

设计对象需要验证，评价设计对象的程序也需要验证。评估器至少应拥有：

- 正常输入的预期结果测试；
- 边界条件和极端值测试；
- 无效输入与缺失数据测试；
- 已知失败模式测试；
- 与参考计算、试验或历史案例的对比；
- 版本升级前后的回归测试。

如果一个评估器升级导致相同输入得到不同结论，平台必须能够识别这是缺陷修复、模型变化、数值波动还是环境差异。

## 5.7 调度、缓存与增量评价

评价成本是设计闭环的重要约束。合理的调度策略是：

1. 先运行廉价检查，快速淘汰无效候选；
2. 只对通过前置条件的候选运行高成本评价；
3. 对相同输入摘要复用缓存；
4. 设计局部变更时，只重跑受影响的评估器；
5. 在发布前补齐必要的完整评价。

缓存键不能只包含设计文件名称，还应包含相关模型、数据、规则、评估器和环境版本。否则，缓存可能把已经失效的证据重新贴到方案上。

## 5.8 冲突与聚合

不同评估器可能给出冲突结论。例如，快速模型认为可行，精细仿真不收敛；几何检查通过，维护评审不通过。系统不应简单按固定优先级覆盖，而应记录冲突并依据预先声明的证据策略处理。

在聚合报告时，应分别呈现：

- 硬约束是否满足；
- 各项目标的表现；
- 证据完整度；
- 评估器失败和无法判断项；
- 已豁免事项；
- 尚需人工判断的问题。

“全部自动检查通过”只能表示指定检查在指定版本和输入下通过，不能被扩张解释为现实世界中的一切风险都已消失。
