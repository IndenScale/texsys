# ADR-0031：只读 HTTP 工程包源

- 状态：已接受
- 日期：2026-11-15
- 取代：无（修订 ADR-0024／0025 的首期分发边界，机制不变）
- 被取代：无

## 背景

AIDC Reference Design 端到端演示要求在全新 CI 环境中可复现地拉取全部工程依赖。文件 registry 依赖作者机器的共享目录，独立检出与 CI runner 无法访问。用户明确本轮不开放第三方，演示即第一个真实消费方；范围契约原先排除托管分发，经用户决定收窄边界，开放只读 HTTP 分发。

## 决策

1. CLI 依赖声明与锁接受 `registry = "http(s)://..."` 源。`add`／`sync`／`lock` 按 `packages/<名称>/<版本>/{package.json,artifact.texpkg}` 拉取，校验 sha256 内容摘要与归档摘要，复用内容缓存；传递依赖沿用 `"."` 别名指向同一源。锁记录绝对源地址，跨机器可复现。
2. 仅分发官方包。不提供账户、第三方上传或发布者签名；完整性由不可覆盖版本、摘要校验与 HTTPS 承担（本机回环演示允许 HTTP）。
3. 服务端是现有文件 registry 布局的静态镜像，不新增服务代码。首期部署为开发容器 `127.0.0.1:8711`（`python3 -m http.server`），仅供本机演示与 CI 复现，不对公网发布。
4. 发布仍写目录（`package publish --registry <目录>`），镜像提供该目录；`package list` 浏览仍限本地目录。Studio 不新增任何包接口，ADR-0025 的 IDE／项目边界不变。
5. 客户端安全边界：拒绝重定向、非 http(s) 协议、带凭据或查询的源；元数据与归档分别限额；元数据与归档交叉校验，篡改任一方即失败。

## 备选方案

- 公网托管加账户与签名：演示不需要第三方，包运行契约尚未稳定到可公网固化，未采用。
- Git 子模块或子树分发包：绕开锁与摘要机制，会形成第二事实源，未采用。
- 继续共享目录：无法满足独立 CI 复现，未采用。

## 后果

收益：CI 在全新环境经 HTTP 拉取依赖并完成构建与检查；锁不再绑定作者机器路径。代价：执行环境仍须显式满足包声明的第三方运行要求（本闭包为 numpy）；本机 HTTP 源无传输加密，仅限回环。风险：将来开放第三方须先补签名与上传鉴权；公网托管另行决策。

## 验证与复审

- `tests/test_registry_http.py` 12 项正例／反例；既有 registry、依赖、部件与 CLI 套件通过。
- 独立演示仓库 `aidc-reference-design`：冷启动（全新缓存、无 build/）`sync → lock --check → build → check → package status` 五步全零，12 条设计校核通过，BOM 512 条；证据在该仓库 `build/ci-demo/`。
- 复审条件：出现第三方上传需求、公网部署需求，或包格式／版本语义变化。
