# ADR-0008：采用六阶段 SysDA 模型并区分三类仿真

- 状态：已接受
- 日期：2026-11-05
- 取代：无
- 被取代：无

## 背景

SysDA 需要一个能够指导需求、原理、布局、实施和验证的通用阶段模型。阶段数量本身不是核心；真正的划分依据是每一步增加什么设计承诺、产生什么证据，以及失败后应回退到哪里。

早期讨论中的“行为与性能”同时承载简化行为模型、容量分析和冗余设计，而末阶段又使用“性能验证”，容易造成两种精度和两类结论的混淆。“实现与交付”也需要与产品行为仿真区分：它主要研究实施过程中的事件、资源、顺序和时序。

当前物理工程工作可以归纳为原理建模、物理布局和仿真验证三条主线，但不同阶段的仿真对象、模型保真度和证据能力不同，不能统称为一种仿真。

## 决策

### 六阶段模型

SysDA 采用以下六个阶段。它们是主要承诺层级，不是严格瀑布流程；后续证据可以使工作回退到能够解决问题的最浅阶段。

| 阶段 | 名称           | 核心问题                                                           | 主要输出                                                                        |
| ---- | -------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| 1    | **需求与规格** | 为什么做、需要做到什么、如何判断成功？                             | 需求基线、工况、约束、目标、验收准则、风险接受边界和追溯关系                    |
| 2    | **架构与拓扑** | 系统由哪些功能角色构成，如何分工与连接？                           | 功能分解、角色、抽象接口、架构候选、功能网络、冗余与隔离策略                    |
| 3    | **行为与容量** | 系统如何作用，能力是否足够，扰动或部件失效时是否有裕量和降级路径？ | 简化行为模型、容量与负载平衡、能力边界、裕量、冗余配置、降级路径及相应近似证据  |
| 4    | **实例与布局** | 具体创建哪些对象，其参数、连接和空间关系是什么？                   | 实例、稳定身份、参数绑定、实例级 Netlist、Layout、Placement、安装与维护空间约束 |
| 5    | **实现与交付** | 制造、施工、部署、切换和交付过程是否可执行？                       | 实施事件、顺序、资源、时序、切换窗口、交付约束和离散事件仿真证据                |
| 6    | **性能与韧性** | 详细物理行为是否满足要求，系统在扰动下能否承受、恢复和适应？       | 高保真性能证据、多物理场结果、韧性评价、适用边界、试验或运行校准证据            |

第二阶段的拓扑是架构级功能网络；第四阶段才形成引用具体实例端口的 Netlist。二者不得因名称相同而混为同一对象。

### 行为与容量采用简化模型

“行为与容量”使用功能关系、低阶模型、稳态或准稳态近似、经验关系和能力包络，回答“如何作用、是否够用、是否具备备用能力和降级路径”。

本阶段所称“冗余”指备用部件、并联路径、隔离、能力储备和降级运行，不是模型中的重复信息。容量结论必须声明模型假设、输入状态、适用范围和误差口径，不得表述为高保真性能验证结果。

### 三类仿真不得混用证据

| 阶段 | 仿真或模型类型       | 评价对象                                           | 证据边界                                                     |
| ---- | -------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| 3    | 简化行为／容量模型   | 系统功能行为、能力、裕量、冗余和降级               | 用于原理筛选和容量判断，不证明详细物理场或全部极端工况       |
| 5    | 离散事件仿真         | 实施事件、资源、排队、顺序、时序、切换和交付过程   | 用于过程可行性，不证明产品物理性能，也不表示实施事件已经发生 |
| 6    | 有限元／多物理场仿真 | 详细物理性能、局部场、耦合效应、扰动响应和恢复能力 | 只在其几何、材料、边界、数值和试验校准范围内成立             |

有限元／多物理场仿真当前是物理工程范围内第六阶段的主要手段，不是 SysDA 对所有行业的排他性要求。其他领域可以使用等效的高保真模型、实物试验、现场验证和运行证据。

### 三条工程主线

1. **原理建模**：主要覆盖阶段 1—3，建立需求、功能架构、抽象拓扑、行为和容量模型。
2. **物理布局**：主要覆盖阶段 4，并向实施空间、维护空间和高保真几何提供输入。
3. **仿真验证**：覆盖阶段 3、5、6，但必须标注仿真对象、模型类型、保真度和证据边界。

形式检查、依赖锁定、证据管理和人工批准是横切能力，不另立第七阶段。实际建造、运行、维护和退役是外部生命周期事件；第五、六阶段是设计期对相关过程和行为的建模与验证，不得把仿真完成报告为现实事件已经完成。

### 阶段门与回退

每个阶段门至少检查本阶段主要承诺、输入版本、假设、未知项和证据。简化模型无法支持结论时返回“无法判断”，不得自动升级到高保真结论。容量不足优先回退架构与拓扑，局部布局失败优先回退实例与布局，实施过程不可行优先回退实例、布局或实施约束，详细性能或韧性失败则根据原因回退到相应承诺层级。

## 备选方案

### 使用四阶段或五阶段作为另一套正式模型

不采用。四、五阶段可以作为沟通时的合并视图，但不再建立独立编号体系。合并展示不得删除验证活动或改变证据语义。

### 保留“行为与性能”的名称

不采用。“性能”会与第六阶段的高保真性能验证混淆，也不能清楚表达容量、裕量和冗余在本阶段的主要作用。

### 将所有验证统一称为仿真验证

不采用。静态检查、离散事件仿真、有限元分析、实物试验和运行确认提供不同证据，不能相互替代。

### 把第六阶段强制限定为有限元分析

不采用。有限元是物理工程的重要手段，但 SysDA 不应形成有限元中心主义；证据方法必须服从评价对象和适用条件。

## 后果

### 收益

- 原理容量、实施过程和详细物理性能具有明确的模型与证据边界。
- “行为与容量”能够自然容纳简化模型、冗余和降级设计，同时避免夸大精度。
- 阶段名称保持行业中立，不直接复制电子、建筑、机械或软件领域的完整流程。
- 评估器可以按阶段和仿真类型组织，失败能够映射到较小范围的回退。

### 代价与风险

- “容量”需要在水力、热力、电气、软件和组织能力等不同语境中定义单位与评价方法。
- 离散事件和多物理场模型会增加输入、版本、校准和计算成本。
- 高保真不自动等于高可信；错误边界条件和未校准模型仍可能产生无效证据。
- 当前暖通冷启动只要求第三阶段的一个近似环境评价器；本 ADR 不表示离散事件或多物理场能力已经实现。

## 验证与复审

- 每个评估器声明所属阶段、模型类型、输入需求、适用范围、精度和失败状态。
- 原理、布局和三类仿真的示例不得共用含糊的“性能通过”结论。
- 第五阶段证据必须关联实施事件与资源模型，第六阶段证据必须关联详细物理模型及其校准状态。
- 引入第一个离散事件评估器或多物理场适配器时，使用真实用例复审输入契约和证据分级。
- 扩展到非物理工程领域时，复审第六阶段的证据方法，但不先改变六阶段承诺边界。
