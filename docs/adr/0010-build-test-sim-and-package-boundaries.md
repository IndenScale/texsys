# ADR-0010：划分 build、test、sim 与领域包边界

- 状态：已接受
- 日期：2026-11-05
- 取代：无
- 被取代：无

## 背景

ADR-0008 已区分行为与容量、实现与交付、性能与韧性。进一步讨论明确：阶段 5 不是纯排队或资源模型，而是包含几何实体、运动路径和时空碰撞的实施过程仿真，因此它与阶段 6 一样属于几何驱动的 `sim`，只是模型类型和证据对象不同。

暖通闭环还需要同时使用简化行为模型、Modelica 形式、USD BRep 场景和几何事件检查。若把这些技术直接写入 SDL 核心，会把设备族、求解器、几何内核和格式细节污染为通用语义；若把 `build`、模型执行和结果断言合并为一个 `test`，又会把“产物生成”“求解完成”和“测试通过”混为一谈。

## 决策

### 命令语义

| 命令    | 职责                                                                          | 不代表什么                                                   |
| ------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `build` | 从锁定输入确定性生成解析模型、USD 场景、Modelica 文本、投影和构建证据         | 不作新的设计决策，不自动更新锁，不表示测试通过或现实建造完成 |
| `test`  | 执行阶段 3 的行为、容量、裕量、冗余和降级测试，依据需求、不变量和容差给出结论 | 不是几何或有限元仿真，不把求解完成等同于通过                 |
| `sim`   | 执行几何驱动仿真并保留场景、运行诊断和原始结果                                | 不因几何内核或求解器返回成功而声称需求满足                   |

`sim` 分为两类模型配置：

1. `event`：阶段 5 的几何离散事件仿真。输入包括几何包络、布局、事件序列、资源、运动路径和时间窗口，输出时空碰撞、路径阻塞、顺序冲突和可实施性证据。
2. `field`：阶段 6 的有限元／多物理场仿真。输入包括详细几何、材料、网格、物理边界和求解参数，输出场数据和韧性证据。

阶段 4 的静态碰撞与净距检查属于布局检查，不因使用几何内核就自动成为 `sim(event)`。只有加入事件、运动、时间占用或实施过程后才进入该类别。`sim(event)` 不证明物理性能，`sim(field)` 不证明实施顺序可行。

### 激励—求解—断言

行为测试和几何仿真统一采用三段式执行契约：

```text
Stimulus → Solve → Assert
```

- **Stimulus**：明确模型、工况、事件、边界、参数状态和求解配置。
- **Solve**：通过抽象求解器或几何内核产生结构化结果、诊断和运行状态。
- **Assert**：独立比较需求、不变量、预期碰撞和容差，输出通过、失败、无法判断或执行失败。

求解器不得自行把“收敛”报告为需求满足；断言不得重新实现求解过程。pytest 用于验证 texsys 实现和驱动公开示例，但领域模型的 `test` 命令与 pytest 的软件测试保持不同报告对象。

### 抽象适配边界

核心只定义稳定协议：

- `Solver`：消费激励并返回结构化求解结果；
- `GeometryKernel`：创建、测量和检查抽象几何实体；
- `TestCase`／`Assertion`：组织激励、求解和独立断言；
- `TexsysPackage`：暴露设备族、规则、投影、求解器和模拟器；
- 证据记录：关联输入摘要、包版本、模型类型、适用条件、诊断和断言。

Modelica 是行为模型的交换与执行形式，不进入 SDL 核心对象。首个内置后端只执行显式支持的有序方程子集，并生成对应 `.mo` 文本；OpenModelica 等外部后端通过同一协议接入，未安装或模型超出子集时必须明确失败。

USD 是原生场景表示，`BrepArray` 是精确 B-rep 资产形式。几何内核与 USD 场景写出分离，核心语义不依赖 SMLib API。当前闭环可以使用真实 USD BRep 资产、引用和变换，但在 ADR-0001 的 spike 完成前，不声称 SMLib 布尔、修复、测量或三角化已经验证。

### 领域包模块化

设备族、HVAC linter、HVAC formatter 和行为模型分别成为独立的 texsys 包，通过 Python entry point 发现，并同时具有 `texsys.toml` 设计包清单。核心通过协议调用，不导入暖通设备名、介质名称或判据。

包之间可以声明依赖：规则与投影复用设备模型，行为模型复用设备族。包发布必须带版本、测试和适用边界。暖通示例通过现有 `lock`／`sync` 机制固定这些包，不把插件源代码复制进项目源目录。

### 暖通闭环范围

首个闭环执行：

```text
SDL／HVAC 描述
  → 核心与领域 lint
  → build：USD BRep 场景＋Modelica 文本＋文本投影
  → test：激励→有序方程求解→容量／环境断言
  → sim(event)：安装事件→几何检查→碰撞断言
  → 可复现证据清单
```

首个闭环不实现 `sim(field)`，不声称完成有限元、多物理场、制造级几何或实际施工验证。缺少该能力时必须显示为未实现或不适用，而不是通过。

## 备选方案

### 用一个 test 命令覆盖全部模型执行

不采用。行为容量、几何事件和物理场的输入、成本和证据边界不同，合并会使命令语义和结果解释失真。

### 按是否调用几何内核定义 sim

不采用。静态几何检查也使用内核。`sim` 必须执行事件、运动或物理场模型。

### 核心直接支持 HVAC 设备与判据

不采用。暖通是首个领域扩展，不应成为 SDL 核心中心。

### 首个版本绑定 OpenModelica 和 SMLib 的全部 API

不采用。核心需要薄协议和可回归的最小后端；外部工具的平台限制应隔离在适配器内。

## 后果

### 收益

- 行为测试、实施事件和物理场仿真具有清晰边界。
- 设备、规则、格式和求解器可以独立版本化、锁定和测试。
- Modelica 与 USD BRep 可以进入真实闭环，同时避免核心绑定具体求解器或内核。
- 激励、求解和断言可以分别替换与验证。

### 代价与风险

- 多包工作区和 entry point 发现增加发布与测试配置。
- 有序方程子集不是完整 Modelica 求解器，超集模型必须拒绝。
- USD BRep 资产可用不等于 SMLib 全链路已经通过 ADR-0001 门禁。
- 几何事件与物理场共享场景时，需要保持身份和版本映射。

## 验证与复审

- 每个包可独立安装、发现、锁定和运行测试。
- 构建两次产生相同文本与场景结构，测试和模拟不修改源输入。
- 容量不足、环境断言失败、几何碰撞、输入缺失和求解失败具有不同结果。
- USD 资产包含真实 `BrepArray`，场景可往返读取，身份与路径映射稳定。
- Modelica 文本与内置方程执行结果一致；不支持的方程显式失败。
- 引入 OpenModelica、SMLib 或首个 `sim(field)` 后端时复审适配契约和证据分级。
