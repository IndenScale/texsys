# ADR-0026：工程变更使用 Git 与构建，DevOps 集成在 POC 之外

- 状态：已接受
- 日期：2026-11-11
- 修订：工程变更与证据 v1 的专用交互流程，以及 Studio 工作台的工程变更入口

## 决策

工程变更就是对版本库中工程源文件的修改。使用普通编辑器编辑，通过 `git diff` 审查差异，通过构建、检查和测试判定修改后是否满足声明的工程条件。Studio 保留通用文件编辑、Source Control 和终端，不提供工程变更专用 activity、页面、参数表单、确认或接受界面。

文本合并冲突由 Git 处理。能够完成文本合并但违反模型接口、连接、容量或其他已声明约束的变更，由相应构建检查失败表达。POC 不另建工程语义合并器或人工接受门禁，也不声称未建模的问题都会被检出。

POC 负责可重跑命令、明确退出码、结构化诊断和结果文件。执行完成、回归符合预期与工程判定分别记录；必需工程检查不满足、执行错误或无法判定，均不能作为成功检查。旧运行结果不能代替本次输入的检查。

主线保护、必需状态检查、合并队列、失败可视化和 Slack、Linear、飞书、钉钉等通知交给已有 DevOps／协作平台，不属于当前 POC。POC 无需自建这些能力，也不因本地命令返回失败就声称远端已禁止合并。

## 实现边界

- 删除 Studio 的工程变更 GUI 及仅供它调用的 `/api/engineering` HTTP 路由。
- 保留已有求解、检查与证据产物；`engineering inspect/run` 可作为现有只读诊断／计算命令使用。
- 删除专用变更事务与本地接受的 CLI、Python API、内部实现和相关测试；示例直接编辑源文件、记录 Git diff 并运行检查。
- 普通 `texsys build` 仅对实际选定的目标负责，目前不会自动运行全部工程适配器。所需工程检查必须在构建命令序列中明确声明，不能仅凭模型编译或反例回归成功推断设计满足。
- 本轮不修改 CI 工作流、远端保护规则或通知配置；这类接入属于后续独立集成。

## POC 验收

在隔离项目副本中，直接修改源文件，保存真实 `git diff`，运行声明范围的检查；验证基线通过、工程反例非零退出、修复后通过，诊断及结果文件与各次输入对应。流程不需要专用变更 GUI、本地接受操作、外部 DevOps 或通知服务。
