# ADR-0018：以组成、拓扑、行为与空间界定工程交付物并采用基线准出门禁

- 状态：已接受
- 日期：2026-11-05
- 取代：无
- 被取代：无
- 补充：ADR-0013、ADR-0017（修订首个图类 target 的命名与原理图的信息承诺；其余决策不变）
- 修订：开放问题 OQ-1 的结论

## 背景

BOM、系统图、原理图、布置图在传统流程中往往是四套工具产出的静态文档，靠人工核对保持一致。ADR-0013、0014、0016、0017 已分别把 BOM 和原理图确立为模型投影，但四个术语作为一个体系从未被统一界定，仓库中已出现实际漂移：

- 核心模型称"原理图（schematic）是 Netlist 与 Layout 的投影"，ADR-0017 的首个 target 却命名为 `hvac:system-diagram`，同一交付物两个名字；
- "原理图是 Netlist＋Layout 的投影"这一定义不含行为，无法回答"系统图与原理图差别是什么"，也无法表达"行为未定义时这张图算不算原理图"；
- 影响性能的几何（管长、换热面积、高差）在原理图阶段就需要进入行为方程，但真实几何只有布置完成后才确定，形成先有鸡还是先有蛋的循环依赖；
- 一种有吸引力的表述是把四类交付物理解为"单调精化链"，并主张"原理图未建模，绝不能出具布置图"。这与核心模型已规定的合法中间状态（已实例化但未连接、已连接但未完成布局）正面冲突，也排除了概念设计阶段粗布置先行这一合理工作方式。

需要在不推翻投影架构的前提下，统一四类交付物的语义界定，给出几何循环依赖的契约化解法，并把"绝不能"这类禁令安置到正确的位置。

## 决策

### 四类交付物按两个正交维度界定

交付物的信息含量沿**逻辑维度**递进：**组成 → 组成＋拓扑 → 组成＋拓扑＋行为**。**空间维度**（未放置 → 部分 Placement → 完整约束布局）与逻辑维度正交，独立演化，不是逻辑维度的下游阶段。

| 交付物                   | 信息承诺             | 语义来源                               |
| ------------------------ | -------------------- | -------------------------------------- |
| BOM                      | 组成＋数量           | 设备台账／实例集合的聚合投影           |
| 系统图（system diagram） | 组成＋拓扑           | Netlist／Net                           |
| 原理图（schematic）      | 组成＋拓扑＋行为     | Netlist／Net＋Component 行为与参数绑定 |
| 布置图（layout drawing） | 实例与连接的空间嵌入 | Layout／Placement／Frame               |

由此形成信息包含链：原理图 ⊇ 系统图 ⊇ BOM 的实例视图。四类交付物均为投影，不是核心对象；具体语义由 [SDL 核心模型 · 交付物与视图](../../spec/sdl/01-core-model.md#交付物与视图) 承载，本 ADR 不重复定义，只记录以下关键取舍。

**BOM 的层级与分类是视图，不是本质。** 按功能域、采购包或空间位置的聚合都是对同一条目集合执行不同 GROUP BY 的派生视图（ADR-0013、0016 已实现此分离）。BOM 条目允许聚合多个实例，其身份强度随 profile 递进：可研设备组、工程设计实例、采购项、物理资产通过显式映射关联（ADR-0014），不要求所有 profile 下都是实例级唯一标识。相对地，图类交付物的节点保持实例身份，重复 occurrence 不得被统计为多个设备（ADR-0017）。

**拓扑是类型化网络，不预设方向。** 系统图不统一建模为"有向超图"；方向、连通与状态语义由网络类型及其评估器定义，与核心模型对 Net 的既有规定一致。

**颗粒度是视图属性，且有可检查的不变量。** 子系统在顶层视图中折叠为黑盒节点、展开为内部子图时，跨越边界的端口契约（介质、电压等级、协议等 Port Signature）必须在折叠前后严格守恒。视图契约声明展开边界（ADR-0017），守恒性属于静态校验规则。

### 原理图的行为承诺通过标注与引用兑现

原理图承诺"系统如何工作"。该承诺在图面上的形式是**行为参数标注与行为定义引用**——特性曲线、设计工况点、容量、热排放、控制关系等；行为本体（本构方程、端口契约、Modelica 模型）始终属于 Component 定义，原理图不成为行为的第二事实源。

行为未定义或待定时，投影必须显式降级为系统图或标记行为缺失，不得生成"看起来像原理图"的交付物。这与 ADR-0017 的 `connectivity-only` 降级同构：缺 Placement 时降级空间标注，缺行为时降级行为承诺，两者都进入图面状态与检查证据。

### 几何归属按是否进入行为方程划分

影响系统性能的几何（水力直径、等效长度、换热面积、高差、特征阻抗等）以集总参数形式进入行为模型，属于原理图语义；只决定空间组织的几何属于 Layout。同一几何事实可以两侧都使用，但始终只有模型一个事实源，由投影与提取保证一致，不靠两张图人工同步。

### 几何循环依赖用"预算—约束—回注"闭环解决

原理图阶段不对未确定的几何写死数值，而是声明**几何预算**：性能允许的参数上下界（如等效长度 ≤ 15 m、流阻 ≤ 上限），参数状态为假设（assumed）并记录依据，使原理图级行为评估先行可解。几何预算是设计承诺，受 SDL 规范范围第 5 项约束。

布置阶段将几何预算作为硬约束参与定位与路由求解（约束驱动布局）。布置完成后，提取器从几何计算实际参数，回注到**模型与验证证据**并重新评估行为：实际值落入预算容差内，参数转为已知（known）；超出预算则验证失败，按 ADR-0011 报告 `fail`，不得签发声称行为闭环的交付物。

回注的目标是模型参数与证据，**不得直接修改原理图等投影产物**；原理图随模型重新投影。生成方向单向（模型 → 投影），验证方向双向（预算下发、实测上传），不存在图与图之间的回写。

### 过程自由，基线有门

不采用"原理图未建模，绝不能出具布置图"这类出图顺序禁令。正确的规则形式是**基线准出门禁**：

- 工作副本上，任何完整度的组成、连接、行为与布置在任何阶段都是合法中间状态；粗布置可以先于行为模型存在。
- 布置图的结构合法性只依赖实例身份（Placement 必须引用已存在的实例，路由必须映射 Net），这是任何时刻都成立的静态不变量，不要求行为已建模。
- 当 `current_stage` 推进到施工等交付阶段并请求合入配置基线时，对应 target 的闭环契约必须整体满足：布置图产物存在、空间完整性检查通过、行为验证与几何回注断言通过。缺任何一项按 ADR-0011 报告 `indeterminate` 或 `fail`，基线合入被拒绝。被拒绝的是承诺，不是工作。

相应地，"单调精化"的合法落点是 **main 基线上的承诺演进**，而不是图纸序列：承诺只能显式增加或显式回退（ADR-0008 允许回退到能解决问题的最浅阶段），不允许静默漂移。禁的是静默，不是回退。该单调性挂在 ADR-0008 的承诺层级上，不得解释为 Target BOM profile 之间的大小关系——ADR-0014 明确禁止 `feasibility < engineering < as-purchased` 这类排序。

### 首个图类 target 更名为 `hvac:system-schematic`

ADR-0017 的首个 target `hvac:system-diagram` 更名为 **`hvac:system-schematic`**，与核心模型的交付物术语一致：该 target 的完整承诺是原理图（组成＋拓扑＋行为），系统图是它的拓扑子集视图与显式降级产物，不是另一个 target。target 标识以最完整承诺命名，降级与视图由视图契约和 profile 表达。

该 target 尚未实现，更名只涉及文档；ADR-0017 的推导管线、图元解析、排版、overlay 与检查决策全部不变，仅 target 标识以本 ADR 为准。产物文件名（`system.json`、`system.svg` 等）保持不变。

## 备选方案

### 将四类交付物作为独立核心对象

不采用。四套独立维护的对象必然产生身份、数量与连接漂移，违背单一事实源；ADR-0013、0014、0017 已确立投影架构，本 ADR 在其上统一术语而非另建对象。

### 采用单向硬阶段链，禁止跨阶段出图

不采用。它与核心模型的合法中间状态冲突，排除了粗布置先行、设备摆位与检修空间先行等合理工作方式；空间排他、净距、维护通道等约束均不需要行为方程。引用完整性只需要实例与拓扑外键，不构成行为前置。顺序问题转化为基线准出门禁后，原表述关心的"施工交付不得缺布置图与行为验证"仍然被强制，且语义更精确。

### 维持"原理图＝Netlist＋Layout 投影"且不含行为承诺

不采用。该定义下系统图与原理图无法区分，行为待定时也没有降级依据，容易交付"看起来像原理图"但行为未定义的图。空间标注改为有依据时的可选增强，行为承诺成为原理图的本质成分。

### 保留 target 名 `hvac:system-diagram`

不采用。该名会持续暗示交付物是"系统图"而非原理图，正是本次要消除的漂移。实现尚未开始，更名成本为零。

### 将提取参数直接回写原理图产物

不采用。这会让图面成为第二事实源，违反 ADR-0017 的投影约束。回注只进入模型与验证证据。

## 后果

### 收益

- 四类交付物有统一、可检查的语义界定，系统图与原理图的差别从习惯用法变成契约。
- 行为未知时的显式降级与六态纪律、ADR-0017 降级机制同构，杜绝"看起来像"的交付物。
- 几何预算—回注闭环同时保住原理图先行可解与布置后验证严肃性，且不破坏单一事实源。
- 早期粗布置、行为后建等真实工作方式合法化，施工基线的完整性要求反而被更精确地强制。
- target 命名与交付物术语一致，后续按视图扩展不再需要新 target。

### 代价与风险

- 原理图视图契约需要声明必需行为标注清单及缺失时的降级表达，增加视图规格与检查工作量。
- 几何预算需要评估器接受区间或上界输入，提取器尚未实现；首版只承诺契约语义，不声称回注闭环已落地。
- 两个正交维度使交付物状态组合增多，图面状态与证据必须分别记录逻辑降级与空间降级，不能合并为一个"完成度"。
- Port Signature 折叠守恒需要静态校验支持，属于校验器新增规则而非现有能力。

## 验证与复审

### 验证

- 冷站 spike 在 ADR-0017 门禁基础上增加：行为参数待定时的产物显式标记降级，不得以完整原理图名义闭环；`system-check.json` 分别记录行为降级与空间降级。
- 视图展开／折叠用例中，跨边界端口契约不一致必须产生确定性诊断。
- 首个几何预算用例：预算内提取值使参数转为已知并保留依据；超预算用例必须 `fail`，不得静默放宽。
- 施工阶段 target 在布置图缺失或行为未闭环时不得 `pass`；同一输入在早期 stage 的粗布置 target 可以闭环。
- 文档中 `hvac:system-diagram` 的现行引用全部更新为 `hvac:system-schematic`，历史 ADR 原文保留。

### 复审条件

- 实现首个几何提取器或回注闭环时，复审预算契约的字段与证据格式；
- 引入第二个专业，其"原理图"行为承诺形式与 HVAC 不同时，复审视图契约的通用性；
- 出现需要独立闭环的纯拓扑交付 target 时，复审"系统图作为视图而非 target"的划分。
