# ADR-0002：调度属于运行期，不进入 SDL 设计模型

- 状态：已接受
- 日期：2026-11-03
- 取代：无
- 被取代：无

## 背景

暖通冷启动场景包含调度。此处的**调度是运营侧概念**：机组启停、负荷分配、运行时序与设定值，即系统建成之后如何被操作。

SDL 面向设计期，回答"系统由什么构成、如何连接、受什么约束、依据是什么"。若把调度并入设计模型，需要引入时间、状态机与序列语义，并把"设计是否成立"与"运行是否可行"两类判断混在一起：拓扑正确但调度不当的系统，与拓扑违规但调度可行的系统将难以区分，回退层级也会被打乱。

## 决策

1. **调度、时序、设定值与运行策略属于运行期模型**，不进入 SDL 核心语义。
2. **SDL 为运行期提供消费条件，而不是消费过程**：稳定身份、可寻址的部件与 Port、能力参数、拓扑与介质语义，以及部分可在设计期表达的运行约束（如最小流量、最小启停间隔作为设计约束，而非时序逻辑）。
3. **运行期结论以证据形式回流设计期**，用于评价与复审；不回写设计意图。
4. **设计模型不得内嵌调度脚本或时序逻辑。** 需要表达"某运行工况"时，使用工况／场景参数（设计期常量），不是时间序列。

## 备选方案

### 把调度作为 SDL 的一部分

不采用。引入时间语义会显著扩大核心，且暖通精度下无法用证据验证调度结论。

### 完全不管运行期

不采用。设计若不能被调度消费，评价就缺少最关键的一类证据，"可实施"退化为纯几何判断。

### 把调度放进 Layout／Placement 的扩展属性

不采用。位置与运行策略无关，混放会破坏 Placement 的语义单一性。

## 后果

### 收益

- 核心语义保持静态、可校验、范围可控；
- 调度侧可直接使用既有工具与方法，不必等待语言完备；
- 设计期与运行期边界清晰，回退层级不被搅乱。

### 代价与风险

- **身份稳定性成为硬要求**：运行期引用的对象一旦改名，证据链立刻断裂（见 [OQ-5](../../docs/open-questions.md)）。
- 需要定义设计期与运行期的接口形态，否则"可被消费"只是一句口号（见 [OQ-12](../../docs/open-questions.md)）。
- 拓扑与调度的联合优化无法在单一模型内完成，必须通过外部循环组合，会牺牲一部分搜索效率。

## 验证与复审

- 第一个暖通切片必须证明：设计模型能被运行期消费——至少能导出可寻址的设备与连接清单。
- 若运行期反馈无法在不修改设计模型的前提下回流，说明边界划错，需重新审议。
