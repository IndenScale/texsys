# ADR-0030：独立维护图页设计组件与项目内容

- 状态：已接受
- 日期：2026-11-13
- 补充：ADR-0017 的文档与页面分层、ADR-0025 的工程能力包边界、ADR-0029 的命名构建目标

## 背景

现有原理图和平面生成器分别输出独立视图，但标题、说明、字体与布局常写在专业生成器中。工程师修改总说明需要修改程序，多个项目难以复用同一图框，图纸也缺少可独立维护的纸幅和标题栏。

BOM、Schematic、Drawing 与 Scene 的工程语义不同，不能因为都需要发布就共享同一种对象模型。图框和纸面文字属于交付编排，可同时组合原理图和空间图的已有视图。此层不得产生第二套工程事实或代替源模型、求解、专业检查与责任审查。

## 决策

引入专业无关的 `sheet` 能力包及 `sheet:compose` 构建目标，将以下三类源分开维护：

1. **设计组件。** 图框、标题栏、纸幅、线宽、文字样式与内容区域由独立模板定义。可复用模板随能力包分发，项目也可显式引用自己的模板文件。
2. **项目内容。** 项目、图名、图号、修订等标题栏元数据与 UTF-8 总说明、页脚文字保留为项目源文件。文字允许显式引用元数据字段；缺失字段不得被空字符串默默替代。模板不包含特定项目事实。
3. **图页装配。** 单独的 JSON 声明模板、元数据、文字源和已有 SVG 视图。项目命名目标声明视图生成目标的依赖，通过同一构建链先生成视图、再编排图页。

图页以纸面毫米为坐标，纸面文字与线宽不随内嵌视图的缩放改变。第一版提供 A3 横向视图页与总说明页，视图采用 `fit` 适配；适配不生成工程比例尺，也不改变视图中的工程参数或声明。原理图的图形距离不转化为安装尺寸，已有平面的物理尺寸依据保持在原模型和标注中。

模板、说明、元数据与视图摘要进入组合证据，输出自包含 SVG 和相邻来源报告。图页组合不执行新的工程求解。输入缺失、错误引用或不能完整排版时返回失败；不把被截断的说明或任意缩小到不可读的文字作为成功结果。目标级缓存继续使用共享构建机制，相关源变化后重新组合。项目内模板与内容独立追踪；共享能力包组件变更仍触发包锁和全局工具链摘要的保守失效，不承诺仅重组图页。

命名目标允许声明额外依赖，既可引用包注册目标，也可引用另一个项目命名目标。生成器读取本轮构建提供的依赖产物，不能仅凭公开输出路径存在就使用上次遗留的图。依赖失败必须阻止相应图页成为当前完整产物；其他独立目标仍可执行。

Studio 继续通过普通文件资源管理器、文本编辑器、终端和 SVG 预览使用这些文件，不增加图框编辑器或专用确认页面。生成 SVG 中的手工改动不反向写回模板或内容。

## 边界

标题栏中的设计、校核、批准字段是声明式文字。第一版不实现数字签名、印章认证或审查流程，也不把图页生成成功解释为专业设计接受。示例标题栏保持“方案草稿”和“待复核”。

总说明是工程师维护的版本化项目内容，不从程序推断设计依据或补写未声明事实。第一版支持纯文本段落、显式编号与字段绑定，不提供富文本编辑、自动法规引用、图元引线注记或尺寸生成。包模板可跨项目复用；锁定字体、正式出版输出、复杂排版与真实工程制图校核需要独立验证。

## 备选方案

- 在每个专业生成器中加入图框与说明：实现短，但将可复用版式与项目文字固化在程序中，多专业维护容易分歧。
- 在导出的 SVG 内直接手工编辑：可用于一次性查看，重建会覆盖修改，且无法追踪上游设计变化。
- 同时建设专用 GUI 排版与签章流程：扩大当前交付边界，不能先证明源文件、依赖与构建整合正确，因此不在本次实现。

## 验证与复审

首案例将冷站原理图与独立总说明编为两页；第二案例将风冷机房平面与独立内容装入同一图框组件，检验模板复用和项目输入隔离。验证内容、元数据、模板与视图变化后的产物及缓存适用性，覆盖缺失引用、文本溢出、失效依赖和确定性输出。

本阶段证明图页编译机制和概念示例贯通。实际工程的图纸完整性、制图标准、打印字体、签章与责任审查仍按相应既有流程验证；需要新增比例尺、复杂图页、字形锁定或正式交付格式时复审实现边界。
