# ADR-0029：命名构建目标、自动重建与文件视口

- 状态：已接受
- 日期：2026-11-12
- 补充：ADR-0027 的目标解析与产物发布、ADR-0028 的文件刷新与视口

## 决策

专业包注册生成器。项目通过 `texsys.toml` 将支持命名配置的生成器实例化为多个目标，每个目标拥有独立的名称、范围和公开输出路径。房间、楼层和标段等范围引用源模型中的标识，专业包校验引用及出图规则。既有目标仍可按注册名执行。构建记录关联本次调用的目标名、实际生成器、范围和产物。

手动构建和监听模式使用同一执行器。监听模式由 CLI 启动，Studio 可从集成终端启动同一命令。短时间内的落盘变更合并为一次构建请求。JSON 或 TOML 暂时不可解析时，终端给出输入诊断并继续监听。每轮构建加载当前锁定依赖，执行过程中变更的输入由构建一致性检查处理。

生成器先在暂存目录写出产物。执行错误或输入漂移保留原路径上一次发布的内容，当前运行继续记录诊断。工程检查不满足时，可发布同一输入下完整的独立图纸、场景和报告，本次构建保留失败判定。生成器正常返回的可读草稿可以首次发布，也可替换仍与历史摘要一致的已发布草稿。通过目标契约且明确允许发布的降级产物也可替换与历史摘要一致的完整产物。这两种草稿都保留不完整标记。公开产物通过路径进入普通文件编辑器，历史运行通过构建记录定位。

文件内容更新与当前观察状态分别管理。Studio 的每个编辑器组按文件路径记住视口。2D 图纸保存图页、平移与缩放，3D 场景使用稳定坐标中的观察中心、旋转及比例。首次打开与主动重置视角按场景范围取景。文件刷新时用新内容重新绘制当前视口。

## 验证

用现有暖通项目验证源输入变更、自动重建、公开文件更新与视口连续性，覆盖无效保存及修复。用数据中心项目验证同一生成器的房间、楼层和跨楼层标段三个目标。构建运行记录用于区分目标执行、工程判定与公开产物发布。
