# ADR-0007：以 JSON 交换子集启动形式检查与格式化

- 状态：已接受
- 日期：2026-11-04
- 取代：无
- 被取代：无

## 背景

`lint` 和 `format` 需要真实、稳定的输入契约。当前 SDL 核心模型只有草案，面向人的声明式文本语法尚未开始；若立即设计完整语法，会把 Net、身份和投影等未决问题提前冻结。若先提供空命令，则会把“命令运行”误报为“检查通过”。

JSON 已具备严格解析器、确定性序列化和清晰的语义保持边界，适合作为首个可执行交换表示，用来验证静态规则和 CLI 行为。

## 决策

1. 首个可执行输入为 `src/` 下的 `*.sdl.json` 文件。它是 SDL 核心模型的 JSON 交换子集，不是最终面向人的 SDL 文本语法，也不阻止以后增加其他语法前端。
2. 交换子集声明模式版本、根 Component、Component 定义、Port、Instance 和 Connection。每个项目文件可以独立校验，禁止依赖 JSON 对象顺序表达语义。
3. `texsys lint` 依次执行项目清单检查、JSON 语法检查、模式检查和静态语义检查，包括根组件引用、组件引用、端口引用、介质兼容、方向和连接数上限。
4. `lint` 不运行求解器或评价器，不修改输入，不自动同步依赖，也不把缺失信息当作通过。结果状态区分为 `pass`、`fail`、`indeterminate` 和 `error`。
5. CLI 退出状态为：全部通过返回 `0`；存在规则失败返回 `1`；没有规则失败但存在无法判断返回 `3`；参数或工具执行失败返回 `2`。CI 不得只识别其中一种非零状态。
6. 默认输出人类可读诊断，`--json` 输出稳定字段：规则编号、状态、文件、对象身份和消息。对象身份使用组件、实例和端口的显式路径。
7. `texsys format` 对交换子集执行确定性 JSON 格式化：两个空格缩进、键排序、文件末尾一个换行。默认原子改写，`--check` 只报告差异，`--diff` 输出统一差异。
8. `texsys fmt` 是 `format` 的等价别名，共用实现、参数、输出和退出状态。
9. 格式化不得改变任何 JSON 值或 SDL 语义；无法解析的文件不得改写。`format --check` 在存在差异或无效输入时返回非零状态。
10. `lint` 不提供自动修复。格式修复只处理呈现，不能代替规则修复或人工设计决策。
11. 当前 JSON 子集不承载注释。未来引入面向人的语法时，格式化器必须保留注释，并通过独立规范与 ADR 复审，不能把本决策解释为最终语法选择。

## 备选方案

### 立即定义完整 SDL 文本语法

不采用。OQ-3 等语义问题尚未关闭，完整语法会把实现便利性误当成语言契约。

### lint 只检查 texsys.toml

不采用。项目清单有效不代表 SDL 模型有效，无法验证引用、端口和连接等核心约束。

### format 通过语义模型重新生成所有未来语法

不采用。该方式容易丢失注释、未知状态和人工呈现意图。它仅适用于无注释的 JSON 交换子集。

### lint 自动修复失败

不采用。静态规则只报告；设计修改需要明确的人为意图。

## 后果

### 收益

- 形式检查、诊断、退出状态和 CI 可以立即形成可执行闭环。
- JSON 格式化天然保持值语义并满足幂等性。
- 交换表示与最终文本语法解耦，后续语法演进不必重写全部静态规则。

### 代价与风险

- JSON 不适合作为长期手写体验，也不支持注释。
- 当前只覆盖核心模型的有限子集，不代表完整 SDL 校验器。
- 规则编号和交换模式一旦发布，需要维持兼容或显式迁移。

## 验证与复审

- 有效、语法错误、未定义引用、介质冲突、方向冲突、连接数超限和幂等格式化均有测试。
- `format` 与 `fmt` 行为一致，`--check` 不改文件，`--diff` 不写文件。
- 所有公开 examples 在 CI 中执行 lint 和格式检查。
- 开始实现手写 SDL 语法、Net 推导或跨文件引用时，新增规范并复审本决策的输入边界。
