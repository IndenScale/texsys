# ADR-0024：可移动工程能力包与项目锁定执行

- 状态：已接受，实施验收见工程 POC 台账
- 日期：2026-11-11
- 修订：ADR-0006 的来源范围及 ADR-0010 的执行能力发现

## 问题

已有路径依赖能够固定内容，但同步和模型解析仍依赖作者目录；求解器和规则从宿主 Python 环境发现，设计包的锁定版本未必就是实际执行版本。用户要求将已经准备好的族、求解器、规则与 Unit Test 打包，并通过 `add / sync` 在多个项目中使用，首期采用 Studio 包管理与可共享包仓库。

## 决策

1. 包是可复用能力的版本单元。公共类型、接口、行为、提取器、规则、求解器适配器、图元与包自身验证进入包；项目实例、拓扑、负载、场景、覆盖参数、现场资料、例外和接受记录留在项目。
2. 开发时保留路径依赖。发布时显式声明 `[package] kind = "capability"`，准备可移动 `.texpkg` 归档，在发布副本中把包间开发路径转换为明确版本的发布依赖，不改作者源清单。
3. 首个仓库协议采用本地或共享文件目录，版本精确指定。同一名称和版本不可替换成不同内容；同内容重复发布可幂等返回。首期不实现公网托管、账户权限、版本范围求解或自动选择最新版。
4. 归档收集清单、声明的源与资产、可选 Python 安装元数据及显式附加文件。包内测试、说明等通过 `include` 声明。项目构建结果、接受记录和原始参考资料不默认进入发布物。
5. 锁记录精确发布身份、内容与归档摘要以及完整依赖闭包。`sync` 只还原该锁，不重新选择版本；可用缓存仍须校验。源目录不再是发布包消费者的运行依赖。
6. Studio 与 CLI 共用包状态、发现、预览、应用和同步接口。版本、来源与摘要变更先呈现差异；应用校验预览身份，拒绝外部改动后的旧计划。升级和回退均显式改变依赖意图。
7. 发布包的纯 Python 能力由 `[package.runtime]` 声明 API 版本、模块白名单、入口及 PEP 508 运行要求。执行操作从锁定内容加载实际代码，不能用宿主恰好安装的同名开发版本替代。仅提供导入模块的库可以没有能力入口。
8. Python、Node 和外部二进制工具继续使用各自运行环境管理方式。首期同步能力源码并检查 Python 运行要求，不隐式安装第三方依赖，也不声称还原完整离线执行环境。OpenModelica、图形渲染与 Studio 专业 UI 的外部要求分别声明。
9. 包测试与项目测试分开。`package test` 在新进程执行已锁包明确声明的测试，保存版本、摘要和结果；它不创建项目工程接受记录。测试成功只说明声明的包验证成立。
10. 包管理界面负责发现、版本和同步；部件库负责发现与选用包内公共对象。已安装包自动进入可浏览来源，不把本机缓存位置写成新的开发路径依赖。

## 状态与证据

包内容同步、执行环境就绪、包测试结果和项目工程判定分别展示。依赖升级改变项目修订，旧计算与接受记录按照既有工程证据机制重新判定适用性。

内容摘要用于发现漂移，不自动证明发布者身份、模型正确性、标准适用性或现场真实性。共享仓库的目录访问权限由部署环境管理；首期无签名身份或多租户审批承诺。

## 验收

以两个独立项目验证同一能力包：发布后移除作者副本，删除消费项目构建目录，再由仓库及锁恢复；实际执行模型检查和求解，确认代码来自锁定包。项目参数改变不得修改包或另一项目。发布新版后普通同步保持原版，显式升级只影响选中的项目，旧工程证据失效。摘要篡改、依赖缺失、运行要求不满足及过期更新计划必须失败且保留原项目状态。

该验收推进能力复用与输入还原，不代替真实设备校准、独立用户验收或完整运行环境封装。
