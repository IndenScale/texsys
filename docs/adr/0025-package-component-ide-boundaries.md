# ADR-0025：项目包、部件包与 IDE 插件的边界

- 状态：已接受，实施验收见工程 POC 台账
- 日期：2026-11-11
- 修订：ADR-0024 的 Studio 安装入口和部件发现；ADR-0021 的插件与工程能力组合方式

## 问题

用户明确要求：包通过命令行导入；部件是包的一种，但不是全部；插件属于 IDE，与项目依赖独立。上一轮实现将 Studio 包页面及部件引用变成依赖安装入口，将所有同步包加入部件库，并允许宿主工程包回退成为项目能力。HVAC 插件直接导入宿主求解器还与项目锁定版本发生冲突。

## 决策

1. 通用 Package 负责发布身份、版本、依赖、锁定内容和可声明的运行能力。部件包是其一种；规则、求解器、提取器、测试或组合能力也可作为项目包。项目实例和现场接受记录仍归项目。
2. 项目依赖的导入、更新、回退、移除及同步通过 `texsys` CLI 完成。依赖声明由通用文本编辑器直接查看和修改，锁文件由 CLI 维护。Studio 不设置项目依赖 activity、专用页面、表单或配套 HTTP 包接口；直接复用文件资源管理器和终端。
3. 部件包声明 `package.kind = "component"` 及 `package.exports.components`。导出路径相对包根，限定在源目录的 `library/` 约定内，可指向公开 SDL 入口、`library/models.json` 或部件目录。一般包使用 `kind = "capability"`，不凭自由标签或偶然存在的 SDL 文件成为部件包。
4. 部件包复用 `texsys.toml` 的项目名称、发布版本及依赖锁。导出身份由包身份与包内入口组成；`module.toml` 描述内部入口、资产、端口绑定及内部资源修订，不构成第二个包安装或版本选择系统。不要求每个内部定义或项目实例独立发布。
5. 部件库只消费明确导出的部件。外部目录可以只读浏览；引用须确认同一包已由 CLI 导入、锁定和同步，来源、版本、摘要均一致。引用只更新项目选择记录，不安装包或改写依赖锁。CLI 升级后，旧引用按新版本独立复核；引用不等于工程接受或自动创建实例。
6. IDE 插件图与项目依赖图独立。`texsys.studio` 承载 IDE 编辑器、视图和命令映射；项目包的检查、构建、求解与测试属于工程工具链。IDE 插件可以有自己的实现依赖，但这些依赖不能扩充或替代项目工程能力。
7. 无项目依赖就没有隐式工程扩展。路径包和 registry 包均按项目声明闭包加载；宿主环境的安装发现不作为项目执行的默认回退。缺失声明、不同版本预加载或源漂移应明确失败。
8. IDE 通过公共工程操作接口发起项目任务。项目工程代码在新进程中按锁加载，返回结果及实际运行包身份；IDE 发现和状态读取不得先加载项目求解代码。编辑前语义验证同样遵循该执行边界，不能偷偷使用 IDE 自带的求解版本。

## 保留的机制

ADR-0024 的不可覆盖发布版本、归档内容校验、明确版本、锁定同步、升级预览、缓存恢复以及包测试与工程接受分离继续有效。命令行的预览／应用契约保留；移除 GUI 安装入口不改变这些基础机制。

## 验收

- 空项目不获得宿主工程能力；更换 IDE 插件不改变项目包集合。
- 只导入规则或求解器包时，不新增部件库节点；声明部件导出的包可浏览和引用。
- 未导入的外部部件不能被引用来隐式安装；已导入部件的引用不改变依赖声明和锁。
- Studio 不再显示项目依赖 activity 或专用文档；清单可在通用文本编辑器打开，退役的包 HTTP 路径不修改项目。
- 同一 IDE 插件分别操作锁定不同求解器版本的两个项目，实际任务使用各自版本；IDE 预加载不再导致来源冲突。
- CLI 继续完成发布、导入、同步、升级、回退及两项目复用；旧工程证据随依赖变化重新判定适用性。

当前进程隔离保证项目能力注册及已声明模块按项目锁选择版本，不是完整 Python 环境隔离。执行仍使用宿主解释器及其第三方库；包代码遗漏声明后自行导入宿主中其他模块的情况尚未全面拦截，也不进入已声明包的运行身份。完整环境隔离与未声明导入检测另行验收。

以上验证仍不代替真实设备校准、完整第三方运行环境还原和正式工程接受。
