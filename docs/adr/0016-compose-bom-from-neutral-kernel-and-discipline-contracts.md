# ADR-0016：以通用 BOM 内核和专业契约组合替代继承

- 状态：已接受
- 日期：2026-11-05
- 取代：无
- 被取代：无
- 补充：ADR-0013、ADR-0014

## 背景

Target BOM 的快照、身份映射、数量、配置比较和证据并非 HVAC 专属。首个实现将这些通用机制与 HVAC 设备族、容量和工程参数检查放在同一包中，导致其他专业若要复用，只能复制实现或引入 HVAC 依赖。

专业组合不能依赖多继承。多继承会把字段所有权、方法覆盖和规则优先级隐藏在类层次及方法解析顺序中，使通用生命周期事实与专业设计规则难以独立演进。

## 决策

### 通用 BOM 内核独立成包

`texsys-bom` 提供专业无关的条目结构、scope、投影、聚合、外部事实快照、身份映射、维护历史、受控比较、通用结构检查和 `bom:diff` target。它只依赖 texsys 核心，不得导入任何专业包。

`family` 在内核中只是不透明分类引用，`specifications` 是带数值、状态和依据的通用参数集合。内核不解释容量、热排放、电压或管径，也不判断专业型号是否存在。

### 专业通过显式契约组合

`BomContract` 声明后端标识、工程 profile 必需参数、外部项专业校验器和视图扩展。HVAC 包提供自己的契约并组合通用 `project_bom`，不继承或覆盖通用推导器。

通用规则与专业规则只叠加，不相互覆盖。字段、规则、视图和诊断必须由明确的命名空间或所有者定义；冲突不得通过方法解析顺序、注册顺序或“后注册者获胜”解决。

### 保持首个 HVAC 接口兼容

`hvac:equipment-bom`、`src/hvac.json`、五类 profile 和现有 HVAC 产物路径保持稳定。`hvac:equipment-bom-diff` 暂时保留为兼容入口，新通用比较使用 `bom:diff`。

Target 依赖只表达构建顺序，不表达继承或跨专业接口绑定。跨专业接口继续由 ADR-0012 的独立契约约束。

## 备选方案

### 保留 HVAC BOM 作为其他专业的基类

不采用。这会让通用生命周期机制反向依赖首个专业，并引入方法覆盖和菱形继承。

### 为每个专业复制 BOM 实现

不采用。快照、映射和比较语义会漂移，修复也难以同步。

### 使用无约束扩展字典代替专业契约

不采用。通用参数可以承载专业数值，但必需参数、型号有效性和视图计算必须保留版本化、可测试的专业所有者，不能变成无校验的扩展袋。

## 后果

### 收益

- 通用 BOM 不需要安装或理解 HVAC 即可独立测试和使用。
- 新专业只增加来源适配和规则组合，不复制快照、映射和比较机制。
- HVAC 接口和现有构建行为保持兼容，拆分可以增量验证。

### 代价与风险

- 包数量和公开契约增加，需要保持通用与专业协议版本兼容。
- 回调组合若缺少清晰所有权，仍可能形成隐式耦合；新增扩展点必须经过 ADR 和契约测试。
- 当前 `BomContract` 只覆盖首个 HVAC 切片需要的组合点，不声称已经解决所有专业的 schema 注册和跨专业接口问题。

## 验证与复审

- `texsys-bom` 源码和 Python 依赖不得出现 HVAC 引用。
- 不使用 HVAC 包的中性条目可以完成设计投影、外部快照消费和比较。
- 现有 HVAC 测试保持通过，容量聚合与工程必需参数仍由 HVAC 契约提供。
- `hvac:equipment-bom` 与 `bom:diff` 分别保持专业和通用边界，重复构建保持确定性。
- 新增第二个真实专业或需要覆盖已有规则时，复审契约所有权和组合机制，不得退回多继承。
