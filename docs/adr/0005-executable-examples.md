# ADR-0005：以可执行 examples 统一参考用例与端到端桩数据

- 状态：已接受
- 日期：2026-11-04
- 取代：无
- 被取代：无

## 背景

项目需要同时向用户提供可复制的参考用例，并向 CLI 集成测试和 CI 提供真实项目输入。若文档示例与测试数据分别维护，示例容易失效；若把所有测试都绑定到公开示例，针对单个分支的单元测试又会变得笨重。暖通切片还需要确定性的端到端输入，而不能依赖个人机器上的原始图纸或临时文件。

## 决策

1. 根目录 `examples/` 是 CLI 集成测试和端到端测试的统一用例来源。
2. `examples/minimal/` 与 `examples/hvac-cold-station/` 是公开参考项目；`examples/fixtures/` 保存失败反例和大型桩数据，不作为用户复制模板。
3. 每个用例是独立的 texsys 项目，包含 `texsys.toml`、源文件、资产目录和自身的 `.gitignore`。可选的 `expected/` 保存人工审核的机器可读基线。
4. `build/` 只保存可重新生成的内容。仓库仅保留空目录占位，不提交某次运行的生成物。
5. 测试先把用例复制到临时目录，再执行会写入的命令。只读检查也不得依赖仓库中的绝对路径。
6. 公开参考项目必须全部进入 CI；大型用例使用独立测试标记，失败反例必须断言诊断内容，不能只断言非零退出码。
7. 大型桩数据必须确定性生成，不访问网络，不包含客户原始资料。它证明工具链的规模行为，不扩大当前暖通模型的精度或规模承诺。
8. 针对内部函数边界的单元测试仍可使用临时目录构造最小输入。现有 `plugins/hvac/examples/` 只保留导航，实际用例位于根目录 `examples/hvac-cold-station/`。

## 备选方案

### 测试数据全部放在 tests/fixtures

不采用。该结构会让公开示例与测试输入重复，并增加示例失效的风险。

### 所有测试都只使用 examples

不采用。单元测试需要快速构造单个异常分支，强制复用完整项目会隐藏测试意图并增加耦合。

### 提交 build 中的期望产物

不采用。生成目录与审核基线必须分离；需要比较的结果放入 `expected/`，避免把工具刚刚生成的结果未经审核就当作真相。

## 后果

### 收益

- 用户示例持续可执行，CI 能直接发现命令契约或输入格式的回归。
- 端到端测试不再依赖开发者个人目录。
- 公开用例与失败桩数据边界清晰，反例不会被误认为推荐写法。

### 代价与风险

- 示例变更可能同时改变文档和测试基线，审查者必须确认语义变化。
- 大型用例增加运行时间，需要保持独立标记并控制数据规模。
- 基线必须人工审核，不能用重新生成快照替代问题定位。

## 验证与复审

- 最小与暖通项目通过 `texsys lint` 和 `texsys format --check`。
- 失败反例产生稳定规则编号和非零退出状态。
- 依赖命令在示例副本上执行后，不修改仓库中的示例输入。
- 若出现多种用例分发渠道或大型二进制资产，应新增 ADR 复审存储与发布方式。
