# ADR-0013：采用目标特定的构建推导与交付视图

- 状态：已接受
- 日期：2026-11-05
- 取代：无
- 被取代：无
- 补充：ADR-0011

## 背景

ADR-0011 将 `build` 定义为选定 target 的闭环，但 target 契约只列举了输入、产物、检查、开放项和依赖，没有明确不同交付物所需的推导过程。若把构建理解为“收集数据并调用格式导出器”，会混淆以下工作：

- BOM 需要形成设备台账，再按设备族、型号、运行参数聚合，或按区域、楼层分片；
- 原理图需要在保持拓扑语义不变的前提下进行符号排版、标签排布和连线路由；
- USD 场景需要解析局部 pose、相对定位父链和根坐标系，再生成场景图。

BOM 也不天然意味着选型或采购已经完成。可研、上会时可以使用“40 MW 机组 2 台、100 MW 机组 1 台”说明系统架构；强制要求厂家、具体型号和完整运行配置，会使早期有效交付无法闭环。反之，可研 BOM 的通过也不能被解释为可以采购。

需要统一目标特定的推导语义，同时区分交付深度、展示视图、序列化格式和生成后端。

## 决策

### 构建是目标特定的推导管线

`build` 的统一执行语义为：

```text
权威项目语义
  → 目标所需的数据收集与投影
  → 聚合、分片、排版、路由、位姿解析等必要推导
  → 视图、排版或序列化
  → 目标范围检查与构建证据
```

导出只是管线中的表示与序列化环节，不等于完整构建。核心不要求所有 target 使用相同推导算法，也不要求把每个内部步骤暴露为独立 CLI target。

相关概念分别承担不同职责：

| 概念    | 职责                             | 示例                             |
| ------- | -------------------------------- | -------------------------------- |
| Target  | 定义必须闭合的交付语义           | 设备 BOM、系统原理图、协调场景   |
| Profile | 定义交付深度、字段要求和通过条件 | 可研、方案、采购；IFC 交付约束   |
| View    | 定义同一权威数据的展示方式       | 分组、筛选、分片、排序           |
| Format  | 定义序列化或页面格式             | JSON、XLSX、PDF、SVG、USD、IFC   |
| Backend | 提供具体推导或写出实现           | 排版引擎、位姿解析器、USD 写出器 |

Target 契约除 ADR-0011 已规定的内容外，还应声明所需推导、显式 profile、视图规格及相应后端版本。默认目标解析必须同时固定必要的 profile；只确定 target 而 profile 仍有歧义时，不得擅自选择。

设备台账、原理图布局、定位图等中间结果可以作为可复用的内部构建产物。只有能够被独立请求、独立闭环或被其他 target 以稳定契约消费时，才提升为公开 target。生成后的中间文件不得脱离权威源模型独立编辑。

### BOM 不以完成选型为前提

BOM 的基础语义是：在明确统计范围内，记录设备或物料对象、数量、当前规格及其状态。厂家和具体型号属于选型承诺，不是所有 BOM 的共同必需输入。

首个设备 BOM 使用权威设备台账作为数据基础。设备实例或具有明确身份的设备组至少关联：

1. 稳定身份、设备族或功能角色；
2. 数量及计量单位；
3. 当前已有的功能规格、配置和运行参数；
4. 规格与参数的已知、假设、待定等状态及依据；
5. 独立的选型状态；
6. 按当前交付契约需要的空间归属和其他关系。

容量等级可以是功能规格，不代表具体型号。选型状态与参数状态保持正交，不能用“未选型”推断数量、容量或系统架构同样未知，也不能用“已选型”替代参数来源和确认状态。

不同交付深度使用显式 profile：

| Profile | 主要用途                 | 闭环所需内容                               | 不默认要求                     |
| ------- | ------------------------ | ------------------------------------------ | ------------------------------ |
| 可研    | 架构说明、规模估算、上会 | 范围、设备族、功能规格、数量、依据与状态   | 厂家、具体型号、完整运行配置   |
| 方案    | 系统方案与容量协调       | 更完整的性能参数、配置和设备实例关系       | 最终采购型号可保留为显式开放项 |
| 采购    | 采购与订货               | 已选型号、确定配置、准确数量及采购必需属性 | 价格不由设备 BOM 默认承担      |

可研与方案设备 BOM 明确排除价格信息；价格由独立商务契约处理，不作为默认缺失项。`current_stage` 可以参与默认 target 与 profile 的显式绑定，但不得直接触发隐藏的字段检查分支。

任一 profile 的 `pass` 只表示满足该 profile 的交付契约。可研 BOM 通过不表示选型、采购或详细设计已经完成；采购 profile 在型号未选时不得以可研规则降级通过。

### BOM 聚合与分片是派生视图

权威设备台账保持实例语义，不因展示方式改变。按设备族、型号或运行参数聚合，以及按区域、楼层分片，均由显式视图规格定义；JSON、HTML、XLSX、PDF 等产物从同一台账和视图规格生成，不形成多份独立维护的权威 BOM。

视图与汇总遵守以下规则：

- 聚合键必须明确是否包含配置和运行参数。同型号但配置不同的设备不得静默合并，应显示参数变体或分别计数。
- 参数比较和聚合前必须规范化单位。连续参数按精确值分组与按区间分箱是不同视图操作，规格必须明确选择。
- 空间分片只在使用该视图时增加空间归属要求；基础 BOM 不因缺少楼层或区域信息而失败。
- 请求完整空间分片而归属资料不足时，该视图不得闭环。只有视图契约明确允许时，才能设置“未分配”分片。
- 设备可以关联多个区域时，必须声明分片和总计规则，汇总不得因重复展开而重复计数。
- 汇总数量、总容量等派生结论继承输入的假设和开放状态，不得把基于假设的结果表示为已确认事实。

基础 BOM 至少检查统计范围、身份、分类、数量、计量单位和必需规格。数量或关键规格缺少判定依据时，按 ADR-0011 报告 `indeterminate`；明细与汇总矛盾等确定性违例报告 `fail`。

### 原理图分离拓扑、布局与渲染

原理图构建分为三个语义层次：

```text
系统拓扑
  → 排版引擎生成符号位置、端口锚点、标签和连线路由
  → 渲染为 SVG、PDF 或其他图纸产物
```

排版引擎只决定如何表达，不得新增、删除或改变系统连接语义。分页和跨页引用必须保持连接身份，图面不得引入权威模型之外的事实。

原理图闭环同时包括：

- 语义检查：必需设备、端口和连接得到表达，跨页引用可追踪，没有丢失或错误连接；
- 版面检查：必需的符号、标签和连接可辨识，不存在契约禁止的遮挡、重叠、越界或交叉歧义。

排版引擎运行成功不等于上述检查通过。引擎、符号库、字体、模板及其版本进入构建证据，以界定确定性范围。人工注记和生成后编辑的所有权继续受 OQ-11 约束；布局未完成时的投影降级继续受 OQ-13 约束。

### USD 在序列化前解析定位依赖

USD 导出器消费已经解析的场景图，不从零散领域数据中自行猜测位姿。定位构建至少收集几何资产引用、局部 Transform、几何定位父链、根坐标参考和稳定身份映射，并按依赖顺序解析世界位姿。

系统连接、空间归属和几何定位父链是不同关系，不得互相替代。一个设备连接到某根管、位于某个楼层或相对于某个 skid 定位，分别属于拓扑、空间和几何语义。

定位解析至少检查：

- 父对象和根坐标参考是否存在；
- 定位关系是否有环或冲突；
- 每个对象是否具有唯一、无歧义的定位依据；
- 单位、向上轴、旋转顺序和 Transform 约定是否一致；
- USD prim 与源对象身份的映射是否稳定；
- 必需资产是否存在且版本明确。

首个定位契约只支持单父对象的刚性相对 Transform 链。每个连通分量必须有明确根坐标参考；target 要求单一场景根时，根必须唯一。多重几何约束、欠约束求解和自动选择位姿不属于该契约；以后引入时必须由独立求解后端处理，欠约束不得任意取解后报告成功。

定位依据不足报告 `indeterminate`，环或冲突等确定性违例报告 `fail`，后端执行异常报告 `error`。USD 文件写出成功不代替定位、资产或身份检查，也不表示碰撞仿真通过。

### 证据记录推导和视图边界

除 ADR-0011 要求的证据外，`build.json` 还应按 target 记录：

- 解析后的 profile、视图规格及其来源；
- 实际执行的推导步骤、后端和版本；
- 中间产物与最终产物的关系、摘要和适用范围；
- 聚合、分片、排版或定位检查的状态；
- 假设、开放项及其对汇总、图面和场景结论的影响。

相同 target、profile、视图规格、权威输入、依赖锁和后端版本，应产生相同的权威产物与确定性证据。视图变化不得伪造权威源模型变化，后端升级也不得在证据中保持不可见。

## 备选方案

### 将 build 简化为格式导出

不采用。文件存在无法覆盖 BOM 聚合一致性、原理图语义与版面检查、USD 定位解析等不同闭环条件。

### 所有 BOM 都要求完成具体选型

不采用。这会使可研和方案阶段无法表达有效的设备数量与功能规格，也会把设计成熟度误当成 BOM 的固有定义。

### 只设一个 BOM 模板，按阶段隐式减少字段

不采用。隐式降级会使相同命令在不同阶段具有不可见的变化，也无法阻止可研结果被误用为采购依据。

### 每种聚合或分片维护一份独立 BOM

不采用。多份权威数据容易在数量、配置和状态上漂移；聚合与分片应从统一台账确定性派生。

### 由原理图或 USD 导出器隐式完成全部推导

不采用。导出器会同时承担语义解释、约束求解和格式写出，导致依赖不可见、结果难以复现，也无法独立检查中间契约。

## 后果

### 收益

- 可研、方案和采购可以共享设备身份与台账，同时具有各自明确的成功语义。
- BOM 的不同可视化方式保持一致数量、配置和状态，不因展示需要复制权威数据。
- 原理图排版与 USD 定位成为可检查、可复用的推导，而不是导出器中的隐式副作用。
- 早期交付可以闭环，同时不会被误读为选型、采购、详细设计或仿真已经完成。

### 代价与风险

- Target、profile 和 view 的声明增加契约设计与版本管理工作。
- 聚合键、单位规范化、空间多分派和不确定状态传播需要领域规则，核心不能自行猜测。
- 排版引擎、符号库、字体和定位后端的版本会影响确定性，需要纳入依赖与证据。
- 中间产物公开为 target 的门槛需要通过实现和用例持续审查，避免目标数量失控。

## 验证与复审

- 以 2 台 40 MW 和 1 台 100 MW 机组构建可研 BOM，无具体型号时可以通过，汇总容量保留假设状态；相同输入不得通过采购 profile。
- 按设备族、型号、运行参数和空间分片生成的视图，其设备身份集合和去重总量与权威台账一致；同型号不同配置不会静默合并。
- 基础 BOM 在无楼层信息时可以通过；请求完整楼层分片时，缺失归属按契约显式无法闭环或进入允许的未分配分片。
- 原理图自动排版不改变拓扑，分页引用可追踪；缺失连接、非法遮挡和路由歧义具有独立检查用例。
- USD 定位链按依赖顺序解析，父位姿变化正确影响后代世界位姿；缺失父对象、环、冲突、坐标约定不一致和资产缺失均有状态化用例。
- 构建证据能够区分 target、profile、view、format 和 backend，并追溯中间产物、开放项及后端版本。
- 引入首个多重几何约束求解器或公开中间 target 时，复审定位契约与 target 粒度。
