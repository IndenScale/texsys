# 参考资料管理

> 状态：有效。本文规定"外部原始资料如何引用、如何不入库、以及从资料到模型的提取规则"。

## 边界

| 类别                                                     | 是否入库   | 位置                                 |
| -------------------------------------------------------- | ---------- | ------------------------------------ |
| 原始图纸、施工说明、设备材料表、客户文档                 | **不入库** | 本地 `refs/`，已被 `.gitignore` 排除 |
| 脱敏源事实、位置、校验值、冲突与使用边界                 | 入库       | `docs/evidence/` 及对应核读说明      |
| 经过适用性审查的模型结论（设备类型、连接关系、参数取值） | 入库       | 领域包、`examples/`                  |
| 提取过程中的判断与取舍                                   | 入库       | 设备模型的注释或 Issues／ADR         |

理由：原始资料体积大、多为他人成果、且随客户变化；**模型才是本项目的产出**。外部原件不作为仓库构建必须访问的输入。参与计算的脱敏事实须冻结到项目 source／assets 中，保留原件身份和适用边界，并纳入输入修订；否则原件或事实变化可能绕过证据失效。仅保存哈希不能替代原件内容核读。

原始图纸和客户资料禁止上传到 GitHub 或随工程能力包分发。`refs/` 路径以及常见 CAD、BIM、PDF、办公文档和压缩格式会被提交钩子、Studio 源代码管理与工程包校验拒绝。Studio 的 AI 提交说明也拒绝含这些文件的暂存差异。发布前执行 `uv run --locked -m texsys.distribution --revision HEAD` 检查候选提交的可达历史，包括加入后又删除的文件。

文件检查依据路径和扩展名。扫描图像、改名文件和脱敏摘录仍须由提交者核实来源及分发许可。公开 GitHub 仓库的 Actions 在推送后运行，直接上传文件或绕过本地钩子的操作者仍须遵守资料边界。

## 提取规则

1. **先记录源事实与边界，再决定是否进入模型。** 脱敏的短事实、冲突、缺失项和适用范围可以入库；原文不入库，未经确认的设计值不得直接覆盖模型输入。
2. **每个取值标注来源。** 记录源文件完整 SHA-256 与实际核对位置，例如 `设计施工说明，页 1，暖施 01，第五节`。工作簿记录表名和单元格，DOCX 记录正文段落或表格行列；文件名不代替内容核对。
3. **图纸是位图，提取需要人工确认。** 本套 PDF 无文本层（`pdftotext` 近乎零输出），必须渲染后识别，识别结果按"待确认"处理，不得直接当已知值。
4. **识别错误按假设处理。** 见方法论书第二章 2.4：无法确认的取值使用"已知但未确认"，不得填默认值。
5. **客户信息脱敏。** 入库内容不得包含客户名称、内部地址、账号口令、人员信息。
6. **区分证据类型。** 图纸设计值、算法默认值、接口字典、采购要求、厂家曲线和实测样本分别记录。变量存在不证明采集已接通；采购指标不证明性能已达到；重复内容不能作为独立校核。
7. **冲突不得静默消解。** 对数量、单位、时间范围或工况不一致的资料，保留各来源的陈述与待确认事项。输入变化后重新检查关联模型和证据的适用性。
8. **输入快照属于计算依赖。** 工程操作须记录实际消费的事实快照摘要；候选参数只修改审查假设，不能同时悄然重写其引用的源事实。摘要失配时先停止相应计算、解释来源变化，再由明确的更新操作重新绑定依据。
