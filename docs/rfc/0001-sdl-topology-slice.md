# RFC-0001：SDL 术语对齐与可校验网络切片

> 状态：草案。本文提出 texsys 的下一项 Feature；现行定义见 [统一语言](../ul/README.md) 和 [SDL 核心模型](../../spec/sdl/01-core-model.md)。

## 问题与建议

下一项 Feature 建议做 **可命名、可校验的 SDL 网络**。设计者可以在冷站模型中为冷冻水和冷却水网络分别命名，让静态校验明确指出成员引用或介质归属错误，并在系统图数据中追溯同一个网络身份。

现有 [冷站示例](../../examples/hvac-dynamic-station/src/system.sdl.json#L269) 的连接可以驱动出图和仿真，但 [JSON 交换子集](../../spec/sdl/02-json-exchange.md#instance-与-connection) 只有二元连接，没有显式 Net。暖通行为后端把直接相连的端口及理想接点归并为水力接点，并通过设备支路连接接点；这是求解用的领域派生模型。将水力接点当作设计网络，会误把泵两侧等压；按设备实例连通性分组，又可能把冷机的两个水侧错误合并。稳定的网络引用将为后续层级投影、物理路由与提资建立共同落点。

## 首个可执行切片

1. **声明网络。** 只在根部件的单层暖通拓扑中引入显式命名网络。保留 Connection 作为端口连接事实；网络声明对既有连接或端口做引用，避免重抄另一套拓扑。字段、引用格式、成员规则和版本策略由 [OQ-3](../open-questions.md#oq-3) 的规范评审确定；不在词表里冻结。
2. **验证网络。** 在冷站样例中检查冷冻水网络与冷却水网络。至少为不存在的成员、介质混接和同一连接的冲突归属提供结构化诊断。同一输入中的有效身份与诊断结果不随声明顺序变化。
3. **投影并保留兼容。** 系统图交换数据能从网络及其成员回溯到 SDL，保持现有实例、端口和连接身份可用；现有无显式网络的 `.sdl.json` v1 示例继续按旧契约检查和出图。此次先验证系统图数据与 CLI，Studio 可在同一契约上接入。

用 [现有冷站](../../examples/hvac-dynamic-station/) 作正例：冷机 `CH-01` 的 `chilled-*` 与 `cooling-*` 端口各属一个水路，两侧共享设备实例但仍可区分；原有水力接点和有压降支路的解释保持独立。再用上述反例验收，并确认新增网络身份不改变现有工况求解所消费的端口拓扑。验收以可重跑的正反例为准。

这个切片先解决 [OQ-3](../open-questions.md#oq-3) 的显式网络子集。匿名推导、通用身份和 USD 映射、递归展开／折叠和跨页分别留给后续契约；层级拓扑的边界端口守恒见 [OQ-14](../open-questions.md#oq-14)。最终 `.sdl` 文本语法、几何回注、极值签核与 DFX 不进入这个切片。真实工程验收仍按 [当前范围](../scope.md#验收什么算跑通) 单独推进。
