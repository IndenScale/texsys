# RFC-0002：Device、Cell 与 Module 的项目引入交付物

> 状态：草案。术语入口见 [UL 共享词表](../ul/glossary.md#设计复用与引入)。

## 问题与现状

设备或已设计模块作为候选引入项目时，方案论证需要知道它如何接入、如何工作、占用多少空间、在哪些条件下满足要求。当前暖通示例把器件参数、项目拓扑、图元、空间包络和工况分散在项目与不同能力包中。本提案为可复用对象建立统一的交付入口。 [领域包清单](../../packages/README.md) · [设备表达层级](../adr/0009-equipment-and-topology-refinement.md#设备表达层级)

## Device、Cell 与 Module

| 对象               | 定位                                                                                                           | 例子                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| **Device（器件）** | 在当前设计层级作为一个单元选型或使用的设备或元件。它可以提供厂商型号或概念定义，按对外接口和已知行为参与评价。 | 泵、阀、冷机。                           |
| **Cell（单元）**   | 在 Module 内复用的局部设计单元，声明功能与端口，可封装 Device 和局部连接。此处是待评审的工作定义。             | 由阀和测点组成的隔离测量单元。           |
| **Module（模块）** | 由 Device 和 Cell 组合形成的已设计单元，保有内部拓扑、对外接口与整体行为，并随版本交付工艺角和工况角。         | 由泵、连接管段与隔离测量单元组成的泵组。 |

SDL 用 `Component` 表达可复用定义，用 `Instance` 表达项目中的具体使用。交付清单绑定候选定义、配置和版本。项目可据此开展候选比较，再独立记录选型批准及实例绑定。 [SDL 核心模型](../../spec/sdl/01-core-model.md#component) · [设备选型与实例绑定](../adr/0009-equipment-and-topology-refinement.md#引用不等于选定)

## 引入交付物

引入清单逐项记录交付物的固定版本或内容摘要、来源、保真度和适用范围。允许引用可解析的固定资产。每项注明已提供、待补或不适用及依据，方案结论只引用满足该论证所需条件的交付物。

| 交付项                | 支持的论证                                                                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **定义、配置与版本**  | 识别设备型号或模块修订、配置及依赖，区分概念模型与产品资料。                                                                               |
| **拓扑与拓扑图**      | Module 提供 Device、Cell 实例及连接，并说明对外端口如何绑定内部网络。Device 可按对外接口表达为黑盒。拓扑图随权威拓扑生成或附可追溯的视图。 |
| **示意图元**          | 给出拓扑图或原理图可用的符号、端口锚点和适用配置。                                                                                         |
| **3D 模型或空间包络** | 给出坐标基准、设备占位、接管位置和必要的安装或检修空间，注明几何保真度。                                                                   |
| **布置图平面图元**    | 给出平面轮廓、基准点、必要接管和空间约束。可以是独立资产，也可以从固定三维资产生成。                                                       |
| **行为模型**          | 指定可执行的实现或固定模型引用，并提供参数、输入、输出、端口绑定和求解条件。                                                               |
| **端口签名**          | 用稳定的端口标识连接逻辑拓扑、图元、几何和行为模型，注明介质或信号类型、方向、适用单位和兼容条件。                                         |
| **不变式与能力边界**  | 分别声明结构不变式和带条件的使用限值。限值应给出指标、单位、适用角、依据及检验方法，例如允许的压力、载荷或冲击。                           |
| **角点与验证证据**    | Module 交付工艺角、工况角、选定的组合，以及适用的用例和已有证据。结论能追溯到版本、配置、角点和断言。                                      |

## 工艺角与工况角

- **工艺角**描述制造或装配差异的联合参数取值，例如尺寸偏差、材料特性和器件性能公差的组合。
- **工况角**描述运行边界的联合条件，例如负载、环境温度、供给和扰动的组合。
- **角点组合**为指定评价目标选择工艺角与工况角的组合，记录选择依据和覆盖范围。若依据只支持某些组合，则按该范围解释结果。

验证用例固定模块版本和角点组合，按「激励—求解—断言」记录结果。比如在指定工艺角和峰值负载工况下，先求解泵组流量与压力，再分别判定供水能力和压力限值。缺少适用模型、限值或角点证据时，对应结论记为无法判断。 [测试执行契约](../adr/0010-build-test-sim-and-package-boundaries.md#激励求解断言)

## 首个验收切片

用一个泵组分别展示 Device、Cell 和 Module 的身份与组合关系。固定模块版本后，应能追溯拓扑、示意图元、3D 包络、平面图元和行为模型上的对外端口，选择一个明确的工艺角与工况角组合，并用同一份交付清单复跑至少一个限值断言。交付清单的文件格式、Cell 的独立交付与嵌套规则留待该切片评审。
