# 工程开发 POC：目标、验收与证据台账

本台账跟踪“让复杂系统可以持续开发、验证和演化”的完整目标。当前优先贯通数据中心管路变更，但不以这个切片替代完整目标。范围以 [范围契约](scope.md) 为准，开发取舍以 [AGENTS.md](../AGENTS.md) 为准。

状态使用“已验证”“部分实现”“进行中”“未完成”。“已验证”必须指明具体输入、版本、验证方法及适用边界；代码存在、文档声明或计划执行都不能独立证明完成。

## 当前贯通案例

案例使用 [混合冷却数据中心概念单元](../examples/datacenter-hybrid-unit/README.md) 中已有的 FWS 支管几何、水力求解和泵组配流。输入仍包含概念假设；本次接受仅能针对明确的概念水力范围。

| 步骤 | 应证明的用户行为和系统反馈 | 状态 |
| --- | --- | --- |
| P01 建立基线 | 固定输入、依赖、工况、判据和适配器版本，保留运行记录 | 进行中 |
| P02 预览修改 | 展示同一管路对象的旧值、新值、单位、来源、影响及重算目标 | 进行中 |
| P03 应用变更 | 仅应用准确预览；拒绝过期、被篡改或不合法计划 | 进行中 |
| P04 重算并解释失败 | 路由／管径变化进入实际压损和配流；工程失败与测试成功分别显示 | 进行中 |
| P05 修复与比较 | 修改导致不足的输入，保留失败记录，解释恢复条件及新旧结果 | 进行中 |

接受入口不得用未覆盖专业的结果推断整个数据中心可接受。只修改检验预期值以使测试变绿，或者只扩大页面和接口数量，不计入上述步骤完成。

## 验证层次

1. **机制回归。** 检查事务、输入一致性、证据摘要、状态和失效行为。
2. **概念物理案例。** 使用现有水力实现与几何提取，验证基线、失败反例和修复；记录数值与判据。
3. **用户操作。** 在复用的 Chrome 和唯一 Studio 实例中验证真实交互，不以静态组件测试代替。
4. **真实工程验证。** 补充设备资料、适用依据、独立参考和工程责任人的审查。
5. **复用验证。** 第二个项目和第二位使用者还原输入、执行并审查，记录成本。

完整目标完成审查逐行检查 G01—G14。某个案例或某一层测试通过，不关闭其他层次的未完成项。
