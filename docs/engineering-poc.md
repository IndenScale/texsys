# 工程开发 POC：目标、验收与证据台账

本台账跟踪“让复杂系统可以持续开发、验证和演化”的完整目标。当前优先贯通源文件修改、Git diff 与工程检查，不建设专用工程变更 GUI；DevOps 门禁、可视化及通知不属于 POC。以下历史验证记录不构成当前产品接口承诺。范围以 [范围契约](scope.md) 为准，开发取舍以 [AGENTS.md](../AGENTS.md) 为准。

状态使用“已验证”“部分实现”“进行中”“未完成”。“已验证”必须指明具体输入、版本、验证方法及适用边界；代码存在、文档声明或计划执行都不能独立证明完成。

## 验证层次

1. **机制回归。** 检查事务、输入一致性、证据摘要、状态和失效行为。
2. **概念物理案例。** 使用现有水力实现与几何提取，验证基线、失败反例和修复；记录数值与判据。
3. **用户操作。** 验证普通源文件编辑、真实 Git diff 与命令行运行；删除或修改已有 Studio 入口时复用 Chrome 验证，不新增专用变更界面。
4. **真实工程验证。** 补充设备资料、适用依据、独立参考和工程责任人的审查。
5. **复用验证。** 第二个项目和第二位使用者还原输入、执行并审查，记录成本。

完整目标完成审查逐行检查 G01—G14。某个案例或某一层测试通过，不关闭其他层次的未完成项。
