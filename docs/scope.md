# 当前范围：从数据中心出发的工程开发 POC

> 状态：有效，2026-11-11 更新。本文是判断当前工作范围与验收边界的权威依据。范围变化需要修改本文或形成后继 ADR，不在讨论中默认扩张。

## 当前目标

以数据中心中的有限跨专业问题验证工程开发环境：工程师修改一个设计对象后，能够理解影响、更新计算、定位不满足项、修正方案，并保存对应版本的检查结果。工程变更使用普通源文件编辑与 Git diff，不建设专用变更 GUI。

暖通同源冷站仍是物理求解、图纸投影和输入状态的回归基础。数据中心算例承接供电、冷却、空间、结构及相关接口的组合研究。当前优先贯通已有 FWS 管路几何与水力计算，不以扩大专业数量或算例规模作为完成条件。

使命与开发取舍见 [AGENTS.md](../AGENTS.md)，逐项目标、证据与后续工作见 [工程 POC 台账](engineering-poc.md)。本文限定本期交付，台账保留完整长期目标。

## 范围内

1. **稳定的工程对象与接口。** 表达组件、实例、端口、连接、具名网络、参数、工况和来源，并使图纸、清单、场景与计算引用可核对的对象。
2. **有限跨专业计算。** 使用已有数据中心模型研究供电、冷却、热响应、空间、结构及其他已声明接口。每项研究分别声明适用条件、近似和验证范围。
3. **几何提取与反注。** 从受支持的路由和布置提取长度、弯头、流阻等模型输入，保留源修订和假设，再重算相关工程判据。
4. **源文件变更与工程检查。** 使用 Git diff 表达修改，重跑声明的计算与检查，保留诊断、范围及输入版本；已知工程冲突使必需检查失败。
5. **一致的开发入口。** 工程师与代理使用同一源文件、Git 和 CLI 工具链；Studio 提供通用编辑器、Source Control 和终端，不为工程变更另造页面或审批步骤。
6. **工程依赖。** 锁定模型、规则、模块和设备资产，检测内容漂移；逐步补齐实际执行环境与外部求解器的复现记录。
7. **真实小场景验证。** 采用可核实的设备资料和独立参考，验证一个小机房或机柜列；在第二个相近项目检验复用成本。资料未取得或验证未执行时保持未完成状态。
8. **增量构建与文件预览。** 按声明依赖复用有效缓存，在失败后继续独立分支，构建记录保存完整性、判定与适用性。BOM、拓扑、原理图和场景以独立文件打开，复用通用文件组件与「预览 / 源代码」；普通 JSON 直接编辑，Markdown 和专业格式只替换预览实现。生成文件可编辑保存，图形反向写回声明式设计尚不在本期范围。交互边界见 [DDR-0012](ddr/0012-studio-file-preview-and-source.md)。

## 三类能力与接受边界

| 类别 | 当前含义 | 可以证明什么 | 不能据此声称什么 |
| --- | --- | --- | --- |
| 已有可执行切片 | 暖通链路、数据中心领域计算、模块库与部分 Studio 交互 | 声明输入与实现可以执行，部分反例和一致性有回归覆盖 | 完整工程 IDE、任意拓扑、任意项目均成立 |
| 本期工程 POC | 将源文件变更、反注、计算、失败检出和修正贯通 | 对声明范围内的固定输入形成可重跑、可审查的过程 | 模型已被厂家或现场校准，整个数据中心可正式交付 |
| 真实工程接受 | 有真实资料、适用依据、独立验证和明确责任人的审查 | 对固定项目版本与声明范围作出工程接受 | 自动扩展到未覆盖工况、其他专业或后续版本 |

数据中心 `datacenter-hybrid-unit` 是参数化概念算例。40 MW、400 台机柜及相应几何和计算数量描述算例规模，不能替代真实 40 MW 项目的性能、模型可信度或交付验证。其 `expected` 反例被正确检出时，回归仍可成功；工程判据和接受状态须单独读取。

## 本期不承诺的完整能力

- 通用高保真水力瞬态、多相、完整多物理场和任意 CAD/BIM 精确几何内核。
- 任意工程领域、任意规模模型的性能与可扩展性。
- 自动生成可直接用于制造、施工或报审的完整图纸与规范符合性结论。
- 施工、采购、运维和退役全过程管理；实际运行调度仍遵守 [ADR-0002](adr/0002-design-time-vs-operation-time.md)。
- 远程多用户协作、第三方包市场和全自动方案综合的完整产品。
- DevOps 主线保护、必需状态检查、合并队列、失败可视化，以及 Slack、Linear、飞书、钉钉等通知集成。
- 工程变更专用 GUI、独立工程语义合并器，以及替代 Git／DevOps 的人工接受门禁。

这些内容在长期台账中保留，以真实接口和复用需求推进；不会因本期 POC 通过而被视为完成。

## 模型与计算纪律

- 几何精度按数据源和校核用途声明。概念包络、路由中心线与精细构造具有不同证据能力。
- 准稳态水力、集总热力、经验或代理模型必须标注适用范围、参数来源和未覆盖效应。
- 依赖不完整时保守重算，明确未登记的专业影响；没有发现影响不等于证明不受影响。
- 构建依赖排序与物理联合求解分别组织。循环耦合须由声明的求解方法和收敛判据处理。
- 分别记录输入状态、运行状态、回归符合性、工程判定、证据适用性和人工处置。
- 任何被依赖的工程能力保留可重跑的正例、反例和必要的独立参考；工具返回成功不代替结果正确。

## 验收：什么算跑通

当前工程 POC 至少满足以下条件，并在 [台账](engineering-poc.md) 中给出直接证据：

1. 固定设计、依赖、工况、模型和判据，取得可比较的基线。
2. 直接修改工程源文件，通过真实 Git diff 查看变化，不依赖专用变更计划或确认页面。
3. 变化使相关旧证据失效；提取量关联几何来源，重算产生可解释的满足或不满足结论。
4. 工程师定位失败对象与控制条件，修改方案并验证修复，保留前后结果及限制。
5. 必需检查不满足、执行错误或无法判定时返回非零退出码，结果与输入和依赖版本对应。
6. 第二位使用者能够通过普通编辑器、Git 与 CLI 按文档重跑；不要求 DevOps 或通知系统接入。

真实小场景还需要设备资料、适用依据、独立参考及责任人审查。第二项目复用还需要记录新增规则、适配代码和人工准备成本。前述三类验收分别完成，不相互替代。

当前分工及工具职责见 [ADR-0026](adr/0026-git-build-workflow-and-devops-boundary.md)。普通构建仅对选定目标负责，完整工程检查命令必须显式声明；本地失败不证明远端分支保护已经配置。
