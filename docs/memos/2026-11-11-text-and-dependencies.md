# 备忘录：可审查文本与工程依赖管理

- 日期：2026-11-11
- 分类：可入库

## 用户主张

用户要求用可解析、可比较差异的文本记录设计决策，并希望协议乃至部分核心实现开放。
用户还提出，工程项目需要系统性的依赖管理、manifest 与锁文件，包管理在离线环境中同样有价值。

用户列举的依赖范围包括：

- 标准、规范的文本，以及将其解释为可执行检查的单元测试或 RuleSet。
- 求解器，以及通用 Formatter 和 Linter。
- 供应商设备的符号、行为模型、平面图元、三维模型、仿真输入或代理模型、工况和标定资料。
- 成熟单元与模块，以及施工机械的能力、定位精度、通过性和工作条件。
- 用于理解服役变化的真实工况分布。

## 文本与二进制资产的分工

影响设计结论的意图与参数采用可解析文本；几何、图像和大型结果采用适合处理效率的格式。

| 对象 | 建议表示 | 主要审查内容 |
| --- | --- | --- |
| 需求、实例、连接、参数、规则配置 | 结构化文本 | 身份、单位、关系、状态与变更理由 |
| 人工决定、豁免和证据索引 | 可解析记录加必要说明 | 谁作出何种决定、适用范围与依据 |
| 精细几何、图像与大型计算结果 | 合适的原生或二进制资产，加显式引用 | 来源、摘要、格式版本与解释工具 |
| 图纸和报告 | 由权威数据投影的交付物 | 输入版本、生成配置和图面附加标注 |

稳定身份、显式单位和缺值状态使文本具有明确的工程含义。
当前 SDL 使用 JSON 交换子集，专用文本语法可以围绕表达效率和编辑体验继续演进。

## 从行差异到语义差异

建议语义差异至少回答以下问题：

1. 哪个稳定对象发生了变化，是否仅更改显示名称或格式。
2. 数值经过单位归一后是否真正变化，未知状态是否改变。
3. 哪些连接、端口契约、工况或规则适用条件受到影响。
4. 哪些派生图纸、验证结果和下游接口需要重新生成或确认。
5. 变化是设计者明确提出，还是依赖升级和参数提取产生。

例如，`1000 mm` 与 `1 m` 可以是同一长度；设备能力相同但控制响应不同则可能是重要工程变更。
差异界面同时提供工程摘要、原始文本和修改来源。
自动合并结合对象身份、专业契约和工程检查处理变更。

## 规范原文与 RuleSet 分开管理

标准文本提供依据，RuleSet 将特定条款、范围和例外表达为可执行检查。
建议分别保存版本和依赖关系，并提供以下映射：

| 记录 | 用途 |
| --- | --- |
| 依据名称、版本与条款定位 | 确认检查针对哪一份依据 |
| RuleSet 标识、版本与维护来源 | 确认解释实现及更新责任 |
| 适用对象、工况、地区或项目条件 | 选择当前项目适用的规则 |
| 输入、单位、例外与缺失数据策略 | 定义计算输入和结果状态 |
| 正例、反例和边界用例 | 检验实现与所声明解释是否一致 |
| 人工确认与解释分歧记录 | 记录条文解释和工程判断 |

依据包记录来源、版本和访问方式，RuleSet 记录条款覆盖和每项检查结果。

## manifest、锁文件与执行记录的职责

manifest 表达项目选择了哪些依赖及其约束；锁文件记录本次具体解析到的版本与内容。
执行记录说明使用这些依赖实际做了什么，以及输入、配置和结果之间的关系。
三类记录以项目修订和内容摘要关联。

| 层次 | 保留的信息 |
| --- | --- |
| 依赖声明 | 包身份、来源要求、版本约束、用途 |
| 锁定结果 | 精确版本、内容摘要、传递依赖、解析策略 |
| 资产证据 | 标定条件、来源、有效域、缺项 |
| 执行记录 | 输入摘要、后端、配置、数值设置、诊断、产物摘要 |

设计依赖还应与 Python、Node 和求解器运行环境区分；需要联合复现时分别记录并关联。
设备的三维外形、接口行为和标定数据通过版本与兼容关系配套。
界面分别展示包安装、模型加载、计算执行和判据检查的状态。

## 离线包管理

离线包管理可以在受控来源、项目交付介质和本地缓存中工作，价值在于依赖清楚、版本固定和完整性可检查。
建议离线闭环覆盖以下行为：

- 在断网状态下还原已取得且锁定的完整依赖集合。
- 定位缺包、内容摘要不符和格式不兼容，并给出所需版本。
- 将升级作为可审查变更，展示接口、规则和标定数据的影响。
- 记录更新信息的获取时间和项目采用版本。

离线交付包含锁文件、资产副本、运行环境及其版本记录。

## 数值复现不止一种含义

建议在结果中声明希望保证的复现层级：

| 层级 | 判断方法 |
| --- | --- |
| 输入可还原 | 取得相同的设计、依据、依赖与执行配置 |
| 构建产物确定 | 对声明确定性的文本和证据比较字节或摘要 |
| 数值结果一致 | 在明确绝对或相对误差内比较变量及轨迹 |
| 工程判断一致 | 在同一适用范围和判据下得到可解释的结论 |

随机种子、并行策略、求解器版本、容差、步长和运行平台都可能需要记录。
临界值附近即使数值差异小，也可能改变通过与失败，应保留裕量和敏感性信息。
依赖锁定负责还原输入，标定数据负责修正模型，数值容差负责比较不同运行的结果。

## 当前基线与优先修改意见

[ADR-0006](../adr/0006-design-dependency-management.md) 已接受声明、锁定、同步分离；首个契约支持本地路径包。
[SDL 概述](../../spec/sdl/00-overview.md) 定义语义目标；[构建规范](../../spec/build/00-overview.md) 定义输入摘要、产物和执行证据。

优先建议是：先把一套真实工程依赖完整锁定和离线还原，再验证一次设备或 RuleSet 升级能否解释受影响结论。
随后完善单位和身份敏感的差异展示、包有效域与来源记录，以及数值复现口径。
