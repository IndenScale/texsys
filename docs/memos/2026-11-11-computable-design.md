# 可计算工程设计

日期：2026-11-11。分类：可入库。类型：产品分析。

## 用户提出的核心主张

建筑科技的高价值对象，往往具有机器的性质。许多使用建筑设计工具的项目，本身就是建筑尺度的机器；另一些建筑由于能量、物质、信息与人流高度密集，也表现出强烈的系统性。

这一判断把设计工具的价值指向系统是否满足要求，以及如何通过计算获得更好的设计。机器性可以从系统耦合、性能要求、运行方式和失效代价来理解。

计算包含连续物理仿真，也包含线路冗余、材料兼容性、可制造性、疏散、导引可见性与巡检可达性。用户由此提出按指标、架构、原理设计、物理实现和反注验证组织设计。

## 产品命题

> 将工程要求转化为可运行的验证，把设计、计算和变更连接起来，让工程师直接看到方案怎样满足要求、修改怎样影响结果。

设计对象、行为模型、空间表达、判据和计算证据共同构成工程资产。图形承担编辑和理解任务，文本保存系统语义，计算揭示行为，证据支持审查。

界面可以根据任务采用图、表格、代码、问题清单或 AI 对话。最值得贯通的体验是：修改设计 → 展示影响 → 更新计算 → 解释结果 → 完成审查。

## 广义计算的工程对象

| 问题类别 | 计算内容 | 主要输入 |
| --- | --- | --- |
| 离散关系与逻辑 | 连通性、兼容性、单点故障、接口一致性 | 对象、连接、故障集合、接口契约 |
| 物理响应 | 流量、压降、温度、能耗与动态响应 | 工况、边界条件、设备行为和求解配置 |
| 空间与施工 | 间距、通过性、检修净空、安装与运输可行性 | 几何、施工能力、动作顺序与场地条件 |
| 感知与使用 | 可见性、对比度、导引和巡检覆盖 | 观察点、人群、光照、视域和路径 |
| 方案选择 | 比较代价、性能、可维护性与实施方案 | 目标、权重、候选方案及计算结果 |

感知与可用性指标可以通过现场观察、使用反馈和实测数据校准。计算模型由此持续吸收工程经验。

## 计算结果的组织

结果页面以工程要求为索引，关联设计版本、工况、判据、观测量和处置意见。

| 信息维度 | 表达内容 |
| --- | --- |
| 输入状态 | 已知、假设、待定、缺失、不适用 |
| 运行状态 | 完成、失败、超时、未执行 |
| 判据结论 | 满足、不满足、未判定、不适用，以及临界项的裕量 |
| 计算方法 | 解析、数值、经验或代理方法，附模型与校准信息 |
| 人工审查 | 待审、接受、驳回、带条件接受 |

这些信息分别回答“用了什么”“运行得怎样”“是否满足要求”“结论怎样产生”“工程师怎样处置”。

## 设计与证据的连接

建议将以下信息直接联结到设计对象：

1. 要求来源、适用对象和工况。
2. 稳定身份、设计版本、依赖和求解配置。
3. 判据版本、观测量、单位、限值和容差。
4. 计算结果、模型信息和运行诊断。
5. 变更影响与相关结果的更新时间。
6. 人工审查及发布记录所对应的快照。

工程师从一个失败项可以直接进入相关设备、连接或参数；从一次设计变更可以直接看到受影响的要求和计算。

## 首个体验闭环

以暖通系统为起点，工程师改变一段路由后，工具提取新的长度与阻力，重算流量和压降，定位发生变化的要求，并给出调整入口。修复后，计算和审查材料随设计同步更新。

随后将同样的机制扩展到设备升级、工况变化和接口协作。推进方法见 [工程验证与推进次序](2026-11-11-assumptions-and-validation.md)。
