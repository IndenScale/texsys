# DDR-0030：右侧面板的智能体视图

- 状态：已接受
- 日期：2026-11-17
- 取代：无
- 被取代：无

## 用户体验与交互背景

工程师在阅读源文件、预览场景和审查差异时，需要随时把任务交给智能体，并看清它读了什么、改了什么、运行了什么。独立应用需要来回切换上下文，修改也无法进入 Studio 的源代码管理。VS Code 把聊天放在辅助侧栏，与资源管理器和编辑器同时可见，用户已熟悉这种布局。

## 设计决策与规范约束

### 信息架构

- 右侧面板顶部是视图标签栏：「属性」与「智能体」。标签采用 `tablist` 语义，左右方向键切换；当前视图记入布局偏好。智能体处理中时，标签旁显示脉动圆点。
- 智能体视图的标题操作依次为「新建会话」「会话历史」和「更多智能体操作」。更多菜单提供关闭当前会话、刷新智能体列表和在源代码管理中审查修改。
- 「查看」菜单和命令面板提供「智能体」命令，macOS 快捷键为 ⌃⌘I，其他平台为 Ctrl+Alt+I。命令在右侧面板关闭或显示其他视图时打开智能体视图并聚焦输入框，再次执行时关闭右侧面板。
- 空白工作区欢迎页的智能体视图只说明需要打开已启动的项目，并提供该入口，不启动智能体。

### 会话与对话

- 未选会话时显示欢迎内容：用途说明、智能体清单和本机配置文件位置。可用智能体带绿色状态点；未安装的条目置灰并显示缺少的命令。进行中的会话列在下方，可直接恢复。
- 输入首条消息即用所选智能体新建会话，就绪后自动发送。会话头部显示智能体名称、版本和状态（启动中、就绪、处理中、需要登录、启动失败、已退出）。
- 对话按事件顺序呈现：用户消息框、可折叠的「思考过程」、工具调用卡片、计划、授权请求、文件写入和回答。回答按 Markdown 渲染，不执行 HTML。
- 工具卡片一行显示状态、类别图标、标题和路径或命令。路径可点击打开文件；展开后显示差异、终端输出或文本结果，失败的卡片默认展开。只发送原始输入的智能体，按编辑参数显示片段差异，并标记「片段」。
- 授权请求以醒目卡片列出智能体给出的选项，允许类选项使用主按钮；处理后显示所选项。需要登录时在错误卡片中列出登录方式。
- 智能体修改过文件时，输入框上方显示「智能体修改了 N 个文件」，可展开文件清单，并提供「审查修改」入口跳到源代码管理。工作台在工具完成、文件写入和轮次结束后刷新资源管理器与 Git 状态。

### 输入框

- 输入框位于底部，Enter 发送，Shift+Enter 换行，输入法组合期间不发送；处理中按 Esc 或停止按钮取消本轮。
- 当前编辑器中的普通项目文件以标签形式附带，点击可切换是否附带，选择记入浏览器偏好。以 `/` 开头时列出智能体声明的命令，方向键选择，Tab 补全。
- 底栏左侧为智能体选择器（会话进行中显示当前智能体），随后是智能体提供的配置项（如模型、推理强度）和模式选择器；右侧显示上下文用量百分比与发送或停止按钮。

### 视觉约束

- 沿用工作台色板、4 px 控件圆角、12–13 px 字号，字重不超过 500。卡片使用 1 px 边框和 6 px 圆角，差异以浅绿和浅红底色区分增删，终端输出使用深色等宽区域。
- 动画仅用于状态指示，遵守减少动态效果偏好。

## 备选方案

- **在底部面板增加智能体标签。** 不采用：底部面板常被终端与问题占用，对话需要较高的纵向空间。
- **以独立编辑器标签打开对话。** 不采用：会遮挡正在审查的文件，与 VS Code 辅助侧栏习惯不一致；后续可作为“在编辑器中打开”补充。
- **为智能体修改增加接受／拒绝按钮。** 不采用：违反工程变更只走源文件、Git diff 和构建检查的约束，撤销修改使用源代码管理。

## 体验影响与权衡

- 属性面板变为右侧面板的一个视图，原有属性内容与插件提供的检查器保持不变。
- 不同智能体的协议覆盖不同，面板对缺少 diff 或权限请求的智能体降级为原始输入呈现，工程师仍需在源代码管理中核对实际差异。
- 会话列表限于当前 Studio 后端进程，重启后需要新建会话。

## 可用性走查与验收标准

1. 在欢迎页打开右侧面板，确认两个标签及智能体视图的项目入口。
2. 打开已启动的项目，切到「智能体」：清单状态、配置文件提示和输入框正确；⌃⌘I 打开并聚焦，再次执行时关闭。
3. 打开 README.md 后发送只读任务，确认附带文件标签、启动与处理状态、工具卡片、思考过程、回答、配置项和用量显示正确，处理中可停止。
4. 让智能体修改一个文件，确认修改清单出现、资源管理器和源代码管理刷新，「审查修改」跳到源代码管理。
5. 在默认、窄和宽三种右侧面板宽度下核对无文字裁切与溢出，键盘可完成标签切换、发送、命令补全和停止。
