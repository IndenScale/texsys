# DDR-0015：资源管理器工作区分区与项目根层级

- 被取代：无
- 关联：[Explorer 对照分析](../studio-explorer-context-analysis.md)、[工作台契约](../../spec/studio/01-workbench.md)

## 背景与观察

原实现把资源管理器面板下的项目根直接作为分区标题，并将新建文件、新建文件夹、刷新与全部折叠放在根节点同一行。此前右键菜单分析没有识别这一层级错误。用户截图明确展示三个不同层级：资源管理器面板标题、工作区分区标题、分区内的项目根树条目。

在既有 Google Chrome 对照中，工作区分区收起后，文件树和四个工具按钮隐藏；重新展开恢复此前的树展开状态。项目根仍是独立的树条目。参考 VS Code Web 在深层目录展开时，第一次执行「折叠文件夹」折叠子目录但保留根展开，第二次才收起根，不能把它描述为一次操作折叠所有层级。

Tex Studio 已有用户明确要求「全部折叠」同时收起根并清除子目录展开状态。本轮修正层级与工具归属，保留这一操作契约，不照搬参考产品的分步折叠行为。

## 决策

### 三个层级分别表达

| 层级               | 职责                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 资源管理器面板标题 | 标识资源管理器面板，不兼作工作区分区或项目根。                                                       |
| 「工作区」分区标题 | 独立的可折叠分区；同一行承载新建文件、新建文件夹、刷新和全部折叠。                                   |
| 项目根树条目       | 使用实际项目名称，作为文件树中的根 `treeitem` 参与选择、键盘导航和展开／收起，不再承载四个工具按钮。 |

工作区分区控制与工具按钮具有独立命中区域，点击工具不触发分区折叠。项目根和普通树条目沿用共享箭头、图标、缩进与焦点规则，不能再次通过样式将根伪装成工作区标题。

### 三种折叠操作分别处理

- **收起工作区分区：** 隐藏项目根、文件树和四个工具按钮；保留根与子目录的展开状态。重新展开分区时恢复之前的树状态。
- **单独收起项目根：** 只收起根的子树，保留子目录展开状态；工作区分区标题与其四个按钮仍可操作。再次展开根时恢复其子树状态。
- **全部折叠：** 一次收起项目根并清除全部子目录展开状态；工作区分区保持展开。随后手动展开根时只显示第一层条目，不恢复此前展开的深层目录。

工作区分区是否展开与项目根是否展开是两个独立状态，不能复用同一个状态值。工作区收起不会切换编辑器文档、清空选择或丢弃未保存内容。

### 新建、定位与操作目标

- 工具栏移动到工作区分区后，继续沿用已有的新建目标规则：选中目录时在目录内创建，选中文件时在其父目录创建，根或无选择时在项目根创建。选择根节点必须同步更新目标，不能沿用此前子目录。
- 执行新建或需要展示文件的定位操作时，主动展开工作区分区、项目根及所需祖先路径，使输入行或目标条目实际可见。
- 新建继续使用树内行内输入，Enter 提交，Escape 或点击树空白区域取消。分区、根及新建操作不引入新的模态对话框。

## 范围与取舍

本轮仅修正资源管理器层级、工具按钮归属及三种折叠职责，不顺带实现多根工作区、完整右键菜单、多选或文件剪贴板。此前对这些能力的分析继续作为实施建议，不作为本轮已实现或已接受的完整范围。

采用独立工作区分区会增加一行结构，但消除了分区开关与项目路径混用的歧义。默认隐藏或显示的状态不应改变文件身份、创建目标或编辑器内容。全部折叠的行为遵守用户已经明确的契约，与参考产品的两步行为分别记录。

## 验收标准与证据边界

以下为 Tex Studio 修改后的验收要求，参考界面的观察不等于修改后的实现已通过。

1. 界面依次呈现资源管理器面板标题、工作区分区标题、项目根树条目；四个按钮只位于工作区标题行，根节点没有重复按钮。
2. 展开至少两级目录后收起工作区，树和四按钮隐藏；重新展开工作区，根与子目录的展开状态恢复，编辑器与草稿不变。
3. 单独收起并重新展开项目根，工作区工具保持可用，子目录展开状态保留；执行全部折叠则根收起、子状态清空，工作区仍展开。
4. 工作区或项目根处于收起状态时，从已有入口执行新建或文件定位，所需层级自动展开；新建目标仍正确，Escape 和空白区域取消继续有效。
5. 用鼠标和键盘核对分区开关、根节点和工具按钮的焦点与命中区域，执行新建、刷新或全部折叠不误触发分区切换。

实际 Chrome 验收结果由 [工程 POC 台账](../engineering-poc.md) 单独记录；本决策不将先前的右键菜单建议或其他文件操作自动记为完成。
