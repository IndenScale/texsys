# DDR-0023：项目模式资源管理器大纲与时间线，视图菜单对标参照

- 状态：已接受
- 日期：2026-11-15
- 取代：无（修订 DDR-0005 的项目模式大纲另行决策表述、DDR-0016 的标题菜单职责表述）
- 被取代：无

## 背景

用户给出 vscode.dev 参照截图：项目模式资源管理器自上而下为「打开的编辑器」、文件夹树、「大纲」、「时间线」，标题「…」仅列四个视图复选项（打开的编辑器／文件夹／大纲／时间线，文件夹必需而禁用）。实现的项目模式此前没有大纲与时间线，标题菜单还混入活动栏位置等布局操作，与参照及空白工作区（DDR-0016 修订）不一致。

## 决策

- 项目模式资源管理器复用 `OutlineView` 提供真实大纲：消费活动文档文本与编辑器光标（含未保存修改），点击符号经 `revealSourceOutline` 居中定位、不抢夺大纲焦点；无文档、不支持语言与无符号在固定高度主体内诚实空态。
- 新增 `TimelineView`：按文件的 Git 历史。后端 `/api/scm/history` 增加 `path` 参数（`git log` 限定文件），条目显示主题、相对时间与作者提示；点击经 `/api/scm/commit` 的 `path` 参数打开该文件在该提交的历史差异，复用 `openScmDiff` 与既有差异视图。无文件、读取中、Git 不可用与无历史各有空态；主体固定高度 `min(160px, 20vh)`，内容增减不改变节高度。
- 标题「…」与标题右键仅列视图复选项：打开的编辑器、文件夹（必需，禁用）、大纲、时间线，顺序与参照一致。布局操作（活动栏位置、移动／隐藏主侧栏）保留在活动栏菜单，修订 DDR-0016 标题菜单兼列布局操作的表述。
- 视图可见性复用 `explorerOpenEditors`／`explorerOutline`／`explorerTimeline` 布局偏好，与空白工作区同一持久化路径；隐藏视图不关闭文档、不清空树展开状态。
- 分区顺序与高度契约同空白工作区：打开的编辑器与文件夹树占据布局空间，树区独立滚动；大纲／时间线置底、固定主体高度，展开／折叠与空态不推移分区。
- 后端路径参数统一校验：仓库内相对路径，拒绝绝对路径与 `..` 越界；历史与提交差异共用同一校验，不改动工作树与索引。

## 验收

组件行为测试覆盖：项目模式标题与右键菜单仅列四个视图项、大纲／时间线隐藏与恢复、时间线按文件取历史与空态；后端测试覆盖按文件历史、按文件历史差异与越界路径拒绝。既有 Chrome 核对菜单方向遵循 DDR-0002、分节高度稳定遵循 DDR-0005。

验证：`node --test tools/test_navigator_menu.mjs tools/test_studio_ui.mjs` 82 项、其余前端套件 37 项通过；CI 参数 tsc、ESLint、Prettier 通过；`uv run pytest` 仅余两个基线失败（并行会话 `runtime.build` 契约，HEAD 即失败，与本轮无关），新增按文件历史测试通过。既有 Chrome 的 8710 标签页以 `/?workspace=project` 实测：标题菜单仅列打开的编辑器／文件夹（禁用）／大纲／时间线；打开 README.md 后大纲显示真实标题树，时间线列出该文件的提交与相对时间；点击时间线条目打开「差异 ·3d75979a」历史差异标签；大纲隐藏／恢复与勾选态同步，时间线位置稳定。
