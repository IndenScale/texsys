# DDR-0008：对标 VS Code 的底部终端模块、面板控制与下拉菜单交互系统

- 状态：已接受
- 日期：2026-11-08
- 取代：无
- 被取代：无

## 用户体验与交互背景

在 Texsys Studio 对标 VS Code 实现底部终端模块（Terminal）、多会话管理、面板最大化/还原与标题栏集成过程中，我们在设计审查与真机交互中识别出了一系列影响沉浸感与工程规范的严重设计问题：

1. **菜单弹出方向与锚点漂移**：
   Header 工具栏下拉菜单在纵向空间紧凑时粗暴向上弹出（Pop Up），遮挡上层代码编辑器与设计画布；横向使用 End-alignment 导致菜单向左飞出大半个屏幕，破坏了用户在工具按钮下方的视线聚焦。
2. **会话选择器状态混淆与逻辑错误**：
   在仅有一个终端会话时，错误地在右侧显示了单行会话栏并挂载了树状连接符 `┌`，下方出现大片死白无容器感的空白区，缺乏工程合理性。
3. **关键操作控件在单终端模式下遗漏**：
   在单终端隐藏侧栏模式下，由于对“Header 简化”理解偏差，粗暴移除了当前会话标识 `[>_] zsh` 与终止按钮 `[🗑]`，导致用户在单终端场景下无法获知当前运行的 Shell 身份，且在界面上找不到任何杀死当前终端的快捷入口。
4. **视觉系统与排版失调**：
   激活标签文字使用了高饱和度墨绿大字，破坏了专业 IDE 面板选项卡的深色中性字重；Badge 徽标定宽抖动且层级喧宾夺主；终端视口套有生硬的全包围绿线外框；最大化图标在小尺寸下粘连模糊。

本设计决策记录（DDR）旨在确立底部面板终端、多会话拓扑、Header 工具栏与弹出菜单的系统性设计与交互规范。

## 设计决策与规范约束

### 1. 终端会话侧栏（Terminal Tabs）的自适应隐藏与树状拓扑

- **单终端自适应隐藏（Single Terminal Hide Condition）**：
  - 严格对标 VS Code 默认配置 `terminal.integrated.tabs.hideCondition: "singleTerminal"`；
  - 当仅有**一个终端会话且未发生拆分**时，**彻底隐藏右侧终端会话侧栏**；终端视口自动横向撑满 100%，消除右侧条目悬空与空白断层。
- **多终端/拆分自适应展开**：
  - 当新建多个会话（`sessions.length > 1`）或发生终端拆分（`splitSession`）时，右侧终端侧栏平滑呈现；
  - 右侧侧栏具备统一的底座背景色（`var(--ui-workspace-chrome, #f4f6f7)`）与贯穿上下的 1px 细分割线（`border-left: 1px solid var(--border)`），形成明确的抽屉容器感。
- **树状连接符展现逻辑**：
  - **仅在发生终端拆分（Split Terminal）时**成对呈现 `┌` 与 `└`，表达同一视口内的并排分屏关系；
  - 多个独立的并行会话以扁平序号（如 `1: zsh`, `2: zsh`）呈现，绝不滥用树状符号。
- **行内操作按需浮现（Hover Actions）**：
  - 会话行日常只展示终端图标、名称与未暂存警告标；
  - 拆分 `[|]` 与终止 `[🗑]` 按键**仅在鼠标悬停（Hover）在具体某一行时才动态淡入**，保持视觉秩序。

### 2. 底部面板 Header 操作栏的模式互斥设计

Header Bar 的操作按钮配置与右侧侧栏的可见性严格互斥，分为两种确定性状态：

| 模式 | 触发条件 | Header Bar 右侧按钮序列 | 设计依据 |
| :--- | :--- | :--- | :--- |
| **单终端完整模式**（图 4 基准） | `sessions.length === 1 && !splitSession` | `[>_] zsh` + `+ ⌵` + `[\|]` + `[🗑]` + `...` + `\|` + `[⧈]` + `✕` | 侧栏隐藏时，Header 是唯一控制入口，必须提供完整的 Shell 指示与一键关闭能力。 |
| **多终端精简模式** | `sessions.length > 1 \|\| splitSession` | `+ ⌵` + `...` + `\|` + `[⧈]` + `✕` | 每一个会话的标识、拆分与删除均在侧栏行内完成，Header 回归纯粹的全局面板动作。 |

- **会话指示胶囊样式**：
  - `[>_] zsh` 采用透明扁平按钮规范（`background: transparent; border: none; height: 26px; padding: 0 6px;`），悬停微弱背景，不再使用厚重方框，保持与右侧工具栏按钮同等呼吸感。
- **终止终端按钮 `[🗑]`**：
  - 单终端模式下常驻于 Header，点击立即触发 `closeSession(activeSessionId)`，销毁进程并重置视口。

### 3. 菜单展开、定位与“严禁内部滚动”准则

- **严禁菜单内部滚动，一律直接完整展开（No Scroll, Direct Expand）**：
  - **设计硬性约束**：所有下拉菜单、上下文右键菜单与级联子菜单**严禁出现内部滚动条（`overflow: visible; max-height: none;`）**；
  - 菜单必须以全量完整尺寸直接展开呈现所有项目，杜绝任何项目被截断或需要用户手动滚动查找；
  - 废除一切生硬将菜单限制在下方狭小空间并触发 `overflow-y: auto` 的裁切逻辑。
- **上下文菜单跨点击点自然延展（“上面有一点，下面有一点” 原生对齐模型）**：
  - **右键上下文菜单（`placement === "point"`）的科学定位**：
    - 对标 VS Code 与 macOS 原生上下文菜单机制，当鼠标在屏幕中下部（如选项卡或标题栏）触发右键时，**绝不粗暴地把整个菜单底边推到点击点上方**（那会导致菜单完全悬在点击点之上，逼迫用户把视线与光标往上移开大半个屏幕）；
    - 采用贴底约束公式：`y = Math.max(edge, Math.min(point.y, window.innerHeight - height - edge))`；
    - 效果：菜单底部自然贴合窗口下边缘，**跨越点击坐标自然展开**——点击点上方展示前面的几个条目，点击点下方展示后面的条目（即**“上面有一点，下面有一点”**）；
    - 既保证了鼠标指针始终停留在菜单的舒适操作热区内，又杜绝了滚动条与生硬位移。
- **左对齐与起始点锚定（Start-aligned Anchor & Placement Point）**：
  - 工具栏下拉菜单左边沿与触发按钮左边沿严格对齐（`x = left`），形成自然顺畅的视觉流出，杜绝跨屏漂移；
  - 右键上下文菜单横向以鼠标点击坐标（`point.x`）为基准自然流出，贴近右边界时自动左翻。

### 4. 选项卡、Badge 与视口视觉规范

- **激活选项卡（Inline Tabs）**：
  - 废除厚重高饱和绿色膏药块，改用浮动白卡片圆角矩形（`background: #ffffff; box-shadow: 0 1px 2px rgba(24, 59, 66, 0.08); border-radius: 4px;`）；
  - 激活文本采用中性深色主文本色（`#263b46`），严禁使用彩色大字；未激活项为安静中性灰，彻底移除底边厚重横线下划线。
- **Badge（计数气泡）规范**：
  - **绝不定宽**：单数字为 16px 圆形，多数字自适应扩展为椭圆药丸；
  - **等宽数字特性**：设置 `font-variant-numeric: tabular-nums`，杜绝数字跳动引发宽度抖动；
  - **阶梯阈值折叠**：超过 999（或 99）折叠为 `999+`，并在 Tooltip `title` 完整保留无截断真值；
  - **未激活分层**：未激活标签上的气泡为弱对比度浅灰底，激活时点亮强调色。
- **终端视口纯净度**：
  - 单视口移除四周全包围 `inset box-shadow` 绿线框，仅保留白底画布与 `10px 14px` 舒适内边距；仅在多窗格拆分对比时，对获得焦点的子窗格呈现 1px 微弱轮廓。
- **SVG 矢量图标、排版字体与光学对齐规范**：
  - **终端会话胶囊（Session Pill）对标 VS Code**：终端名称采用原生 UI 字体（`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`，12px 400 常规字重，严禁加粗），通过提升文本对比度（`--ui-text-strong, #111b20`）实现清晰辨识度；终端图标尺寸为 **15px**（stroke 1.5），告别笨重糊块感；
  - **警告徽标精细化与对比度分离**：警告图标采用圆角顶点三角造型，规格精细化为 **13px**（stroke 1.5），与文本高度完美契合；文本本身严格保持高对比度深色中性字，不改变文字颜色，仅通过警告标点亮琥珀金（`var(--ui-attention, #b87503)`）提示状态；
  - **自然轴对齐**：采用 `inline-flex` 与 `align-items: center` 自然轴对齐，移除导致下沉脱节的 `transform: translateY(1px)` 硬编码偏移；
  - **点状与小图标实心填充**：`more`（`...`）三个圆点采用 `fill="currentColor"` 纯实心渲染，小尺寸下清晰有力不发虚；最大化图标内外留白精确控制在 3.5px。

### 7. 底部面板选项卡右键上下文菜单系统（Tab Context Menu）

- **触发范围**：
  - 底部面板选项卡栏上的任意具体 Tab 标签（如 `[Problems 1]`、`[Tasks and logs]`、`[Terminal]`，用户上传图 3、图 4 绿框区域）。
- **专属首段菜单条目（Tab-Specific Actions）**：
  1. **配置键绑定（Configure Keybinding）**：
     - 触发键绑定配置与搜索通知。
  2. **隐藏当前选项卡（Hide '{tabName}'）**：
     - 动态代入当前选项卡名称（如 `隐藏“终端”` / `Hide 'Terminal'`、`隐藏“问题”` / `Hide 'Problems'`）；
     - 点击直接将该 Tab 从栏中移入隐藏集合，并自动平滑切换激活项至首个存活 Tab。
  3. **隐藏徽标 / 显示徽标（Hide Badge / Show Badge）**：
     - 针对带有计数气泡的选项卡（如 `Problems 1`），提供一键隐藏徽标气泡能力；隐藏后菜单条目自适应翻转为 `显示徽标`。
  4. **移动至（Move To >）**：
     - 级联子菜单：`面板` (`Panel`，当前位置，默认置灰或勾选)、`辅助侧边栏` (`Secondary Side Bar`)。
- **后置全局条目承接**：
  - 在分割线后完整承接第 6 节中定义的 7 项面板视图开关列表、面板位置、对齐方式、显示图标与隐藏面板。
- **级联子菜单展开机制（Cascading Submenu Mechanism）**：
  - 鼠标悬停在带 `>` 箭头条目或按下右方向键（`ArrowRight`）触发子菜单；
  - 子菜单默认紧贴父级菜单右侧（`x = rect.right + 2`）展开；当贴近屏幕右边缘时自动向左翻转（`x = rect.left - width - 2`）；
  - 子菜单同样遵循“严禁内部滚动，一律完整直接展开”原则。

### 11. 按钮尺寸、线条对比度与底边重心视觉对齐规范

- **图标规格与线条对比度规范（严禁加粗）**：
  - 对标 VS Code 标准，面板操作栏按钮图标全量统一为标准 **16px** 规格，笔触严格采用纤细清晰的 **`1.5px`**（严禁将 SVG strokeWidth 粗暴提升至 2.0~2.2）；
  - 杜绝依靠加粗线条提升辨识度的做法，纯粹通过**高对比度色彩**（`color: var(--ui-text-strong, #111b20)`）实现锐利、精致的专业工具栏质感；
  - 会话侧栏列表项高度统一为 28px，行内操作按钮（拆分、终止）为 24px，图标尺寸统一为 15px/16px（stroke 1.5）。
- **警告图标底边与重心地心引力吸附（防浮起与防下沉）**：
  - 三角形警告图标（`⚠`）精细化调整为 13px（stroke 1.5），与 12px 文本的 x-height 及 cap-height 达到最佳光学比例；
  - 废除生硬的 `transform: translateY(1px)` / `translateY(1.5px)` 强制下沉，利用精准 Flexbox 轴对齐与微边距，使警告三角形底边与相邻操作按钮及文本基线完全平齐，重心沉稳踏实。

## 备选方案

1. **备选方案 A：无论几个终端始终固定显示右侧侧栏**
   - *未采用原因*：在 90% 的日常轻量开发中用户只有一个终端，强制常驻侧栏造成右侧 180px 严重横向浪费，且单条目下方留白空洞，严重违背轻量化设计原则。
2. **备选方案 B：菜单自适应翻转不做方向倾向**
   - *未采用原因*：面板位于屏幕底部，自适应算法容易把长菜单判定为高度不足而向上反转，强行遮挡用户正在比对的代码或电路图纸，带来巨大的交互割裂。
3. **备选方案 C：单终端隐藏侧栏时，Header 依然保持极简（不加 `zsh` 和 `[🗑]`）**
   - *未采用原因*：直接剥夺了用户感知 Shell 环境和杀死终端的最关键路径，造成严重可用性缺陷。

## 可用性走查与验收标准

1. **单终端就绪状态走查**：
   - 打开底部面板切换至终端：右侧无会话侧栏，终端占据全宽，无四周全包围绿线；
   - Header Bar 完整呈现：`[>_] zsh`、`+ ⌵`、`[|]`、`[🗑]`、`...`、`|`、`[⧈]`、`✕` 共 8 项控件；
   - 分割线 `|` 高度 16px、颜色对比清晰，无异常空隙。
2. **下拉菜单流出走查**：
   - 点击 `+ ⌵` 右侧的下箭头：菜单紧贴按钮底边向下流出，左边缘与按钮左对齐，不向上遮盖编辑区。
3. **拆分流转走查**：
   - 点击 `[|]`：终端横向平分为两栏，右侧会话栏平滑出现，显示 `┌ [>_] zsh` 与 `└ [>_] zsh`；
   - Header 自动精简为 `+ ⌵`、`...`、`|`、`[⧈]`、`✕`；
   - 鼠标悬停在侧栏任一行：该行右侧平滑浮现 `[|]` 与 `[🗑]`。
4. **终止流转走查**：
   - 点击 `[🗑]`：会话即刻关闭；当会话恢复为单终端时，侧栏自动收起，Header 恢复全量控件。
5. **进程卡片与快捷键文案走查**：
   - 鼠标悬停在 `zsh` 会话胶囊或侧栏列表项上：平滑展现进程信息卡片（PID、命令行、Shell 集成状态及贡献链接），顶部指示针精准指向上方控件，不显示浏览器默认黑块 `title`；
   - 鼠标悬停在 `+ ⌵` 按钮：显示 `新建终端 (⌃⇧\`)`；悬停在`[|]` 按钮：显示 `拆分终端 (⌘\)`。
6. **标题栏空白与选项卡右键上下文菜单走查**：
   - 右键点击底部面板标题栏空白区域：精准在点击坐标弹出全局面板菜单，直接向上完整展开，无任何内部滚动条，完整展现全部 7 项视图开关、面板位置、对齐面板、显示图标与隐藏面板；
   - 右键点击具体 Tab（如 `Problems` 或 `Terminal`）：弹出专属上下文菜单，首段包含 `配置键绑定`、`隐藏“{tabName}”`、`隐藏徽标`（若有气泡）、`移动至 >` 等专属条目，同样直接完整展开，杜绝内部滚动。
7. **直接完整展开与无滚动体验走查**：
   - 无论在屏幕底部何处唤起菜单或子菜单，系统均自动利用开阔空间直接完整展开所有条目，`overflow` 锁定为 `visible`，`max-height` 锁定为 `none`，彻底消除任何灰色滚动条与内容截断。
8. **全面板全组件右键菜单响应走查**：
   - 右键点击 `[>_] zsh` 或侧栏会话行：弹出终端会话专属菜单（`拆分终端`、`移动到编辑器`、`重命名`、`终止终端` 等）；
   - 右键点击终端视口缓冲区：弹出视口剪贴板与控制菜单（`复制`、`复制为 HTML`、`粘贴`、`全选`、`清空`、`终止终端` 等）；
   - 右键点击右上角操作工具栏按钮：弹出工具栏按键显示与重置菜单（`聚焦终端`、`新建终端`、`拆分终端`、`终止终端`、`重置菜单` 等）。
9. **控件尺寸饱满度、对比度与底边重心对齐走查**：
   - Header 动作按钮与侧栏按钮呈现顶天立地、比例饱满的视觉厚度，图标尺寸达 18px，描边扎实有劲，杜绝小气感；
   - 会话胶囊与侧栏行中的 `⚠` 警告图标底边与相邻 `◫` 拆分、`🗑` 终止按钮及文本基线绝对平齐，无任何“重心悬空飘起”现象。
