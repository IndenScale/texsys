# DDR-0020：空白工作区完整外壳与无重定向默认入口

- 状态：已接受
- 日期：2026-11-15
- 取代：无（修订 DDR-0004 的空白工作区部分；标题栏与菜单决策仍有效）
- 被取代：无

## 用户体验与交互背景

开发容器默认落在空白工作区后，实现曾把外壳裁剪为单个资源管理器入口、隐藏状态栏并禁用底部／属性面板开关，编辑区也没有文档操作。与正常项目工作台及 VS Code 等标杆的空工作区对比，用户认为组件缺失不符合预期：哪怕工作区为空，也应保留完整的 Activity 等组件。同时默认入口曾 302 到 `/?workspace=empty`，地址栏后缀既无必要，也暴露了实现细节。

## 设计决策与规范约束

- 默认入口不重定向。`--empty-workspace` 服务在入口 HTML 注入 `<meta name="tex-studio-workspace" content="empty">`，前端以显式 `workspace` 查询参数优先、meta 声明兜底解析工作区模式；裸 `/` 直接渲染默认工作区。`?workspace=project` 与 `?workspace=empty` 仍可显式覆盖；「文件 → 新建窗口」继续显式打开 `/?workspace=empty`。
- 空白工作区复用与项目工作台相同的外壳组件：完整 `ActivityBar`（文件资源管理器、搜索、源代码管理、扩展、部件库、项目实例，含右键布局菜单与位置／尺寸切换）、状态栏、标题栏布局控件（底部／属性面板开关不再禁用）、底部面板（问题、输出、任务与日志、终端等标签）与属性面板。
- 活动入口切换侧栏视图。资源管理器保留本地文件夹浏览；搜索、源代码管理、扩展、部件库、项目实例在空白工作区显示诚实空态，说明能力在打开项目后可用，并提供「打开已启动的项目」动作。不为此加载绑定工程，也不新建本地搜索等并行能力。
- 编辑区标签行右侧保留「更多操作」菜单：关闭、关闭其他、全部关闭、关闭已保存、配置编辑器，作用于本地文档与欢迎标签。
- 属性面板在空白工作区显示「当前没有可显示的属性。」；任务与日志标签显示打开项目后可查看的提示。终端为宿主级能力，空白工作区可用。

## 备选方案

- 维持裁剪外壳：实现简单，但空工作区与项目工作台认知不一致，用户明确否决。
- 空工作区直接连接绑定工程的搜索／Git／扩展视图：功能完整，但违反 DDR-0004「显式操作后才加载工程」的边界，且把工程数据带入空白工作区。
- 用查询参数重定向表达默认模式：地址栏出现 `?workspace=empty` 后缀，刷新与分享 URL 携带实现细节，被无重定向的 meta 声明取代。

## 体验影响与权衡

空白工作区看起来与项目工作台一致，入口、状态栏与面板开关不再「消失」；空态视图明确告知能力边界，避免把空工作区误认为功能损坏。代价是空白工作区承载更多外壳代码，非资源管理器视图暂为空态而非完整功能。受影响模块：Studio 宿主、WelcomeWorkspace、服务端入口与开发容器文档。

## 可用性走查与验收标准

复用现有 Chrome 标签页访问 `http://127.0.0.1:8710/`：URL 无查询后缀；活动栏六个入口可切换且右键菜单可用；状态栏可见并可配置；底部／属性面板开关可用，终端可打开；编辑区「更多操作」可关闭本地文档。点击「打开已启动的项目」后加载绑定工程，外壳行为与项目模式一致。服务端测试覆盖裸入口 200 与 meta 注入、显式 URL 不受影响。
