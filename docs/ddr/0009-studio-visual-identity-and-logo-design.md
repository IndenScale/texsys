# DDR-0009：Tex Studio 视觉识别（VI）系统、Logo 语义与正交节点设计演进

- 状态：提议
- 日期：2026-11-08
- 取代：无
- 被取代：无

## 用户体验与交互背景

在 Tex Studio 本地 Web 工作台的原型与工程实现推进过程中，界面视觉呈现与品牌一致性暴露了以下直接体验问题：

1. **浏览器标签页缺失 Favicon**：页面未配置合规的 `<link rel="icon">` 且服务端返回空响应，导致 Chrome 等现代浏览器直接显示通用的地球占位图标，破坏了专业工程工作台的第一印象；
2. **标签页标题与特定业务领域硬编码耦合**：此前服务端将 HTML `<title>` 写死为 `Tex Studio — {project.name}`，在运行示例工程时直接显示为 `Tex Studio — hvac-dynamic-station`，使宿主框架被特定专业领域（HVAC）反向渗透；
3. **工作区 Hero 空状态的认知混乱**：核心编辑区在无打开文件时，直接放大居中展示了 `Icon name="system"` 临时线框；同时底部复用了同一个图标渲染无文字的 `EditorActionButton` 作为“打开专业预览”跳转按钮。用户极易将底部的悬空操作误判为 Logo 水印或装饰物，界面信息层级发生严重割裂；
4. **缺乏正式的 VI 视觉识别资产**：Texsys 取自 **textual system**，是面向设计自动化（SysDA）的声明式系统描述语言（SDL）参考实现与通用插件宿主。目前仓库中缺乏能够同时承载“物理系统/空间工程”与“文本/符号语言”核心隐喻的正式 Logo。

## 设计决策与规范约束

本决策确立 Tex Studio 的视觉识别（VI）体系，并实施**两阶段演进策略**：

### 阶段一：现行中立化与兜底实施（立即落地）

1. **生成并装配当前过渡 Favicon**：
   - 提取当前 `system` 几何矢量结构，生成统一的 `favicon.svg` 并放置于 `src/texsys/assets/studio/favicon.svg`；
   - 矢量外框配备圆角背景垫板（浅色 `#f4f6f7` / 深色 `#1c252a`），内部描边绑定品牌主色 `--ui-proof`（`#15796e` / `#2ec4b6`），确保在 Chrome、Safari 浅色/深色标签栏中均具备高对比度；
   - 标准 HTTP 模式与 Vite HMR 模式均配置 `<link rel="icon" type="image/svg+xml" href="/favicon.svg">`，并由静态资源服务与 `host.tsx` 动态挂载形成双重保障。
2. **解耦网页标题与领域信息**：
   - 将 HTML 文档默认标题与 React 顶层标题统一规范为：

     ```html
     <title>Tex Studio</title>
     ```

   - 禁止在标签页标题中直接泄漏特定插件名称（如 HVAC）或文件系统路径，保持宿主框架的领域中立（Discipline-agnostic）。
3. **净化 Core Editor 的 Hero 空状态**：
   - 移除 `core-welcome` 区域底部挂载的悬空 `EditorActionButton`；
   - 核心编辑区的空状态应纯粹服务于通用文件浏览与编辑（命令面板、文件检索、全局搜索），专业工作台切换统一交由标题栏（Titlebar）、活动栏（Activity Bar）与学科切换器承载。

### 阶段二：正式 Logo 构想（正交三维节点平面化 + 字母 T）

正式 Logo 采纳用户提出的设计原则：**将三维正交关系平面化，左上方为正交钢结构三向节点，右下角为几何字母 T**。

```text
    0       4       8      12      16      20      24
 0  ┌───────┬───────┬───────┬───────┬───────┬───────┐
    │  \    │       │       │       │       │       │
 4  │   \───┼───────┼───────┐       │       │       │
    │   │   │       │       │       │       │       │
 8  │   │   │       │       │       │       │       │
    │   │   │       │       │       │       │       │
12  │   └───┼───────┼───────┴───────┼───────┐       │
    │       │       │       │   │   │       │       │
16  │       │       │       │   │   │       │       │
    │       │       │       │   │   │       │       │
20  │       │       │       │   └───┼───────┘       │
    │       │       │       │       │       │       │
24  └───────┴───────┴───────┴───────┴───────┴───────┘
    [左上：3D 正交节点平面化]   [右下：文本象征 字母 T]
```

#### 1. 核心构图与几何构造

- **左上方（Top-Left）：正交钢结构三维节点**：
  - 构造：三条在三维空间中彼此正交的结构轴线（X、Y、Z 轴向构件），通过轴测投影（Axonometric Projection）投影于二维平面；
  - 几何路径：斜向轴从 `(3, 3)` 汇聚至核心节点 `(7, 7)`，随后分流为水平梁线 `(7, 7) -> (14, 7)` 与垂直柱线 `(7, 7) -> (7, 14)`；
  - 隐喻：工程结构实体、空间拓扑节点、BOM 构件连接以及多物理场工程系统（SysDA）。
- **右下角（Bottom-Right）：字母 T**：
  - 构造：现代无衬线单线或体块大写字母 “T”；
  - 几何路径：横梁 `(13, 13) -> (21, 13)`，竖挺 `(17, 13) -> (17, 21)`；
  - 隐喻：**Textual System（texsys）**，表达以文本代码、形式化语法与 SDL 标准描述和驱动系统自动化的根本属性。
- **空间对话与“三维平面化”哲学**：
  - 左上（空间、结构、物理三维）与右下（文本、符号、二维语言）形成强烈的对角平衡与张力；
  - 巧妙诠释了 Texsys 的核心方法论：**“将复杂的物理三维系统，抽象并平面化为简洁严谨的系统描述文本”**。

#### 2. 多端尺寸应用规范

| 场景                 | 尺寸规格          | 表现形式                  | 规范要点                                                     |
| :------------------- | :---------------- | :------------------------ | :----------------------------------------------------------- |
| **浏览器 Favicon**   | 16×16 / 32×32     | 矢量 SVG + 垫板           | 线宽增强至 2px，保证小像素下对角结构清晰可见，不出现模糊粘连 |
| **工作台内部 Icon**  | 18×18 / 24×24     | 单色描边 (`currentColor`) | 贴合 24px 网格，线宽 1.65px - 1.8px，与全套 UI 图标风格一致  |
| **空状态 Hero 标志** | 44×44 / 64×64     | 品牌主色 + 双色阶         | 展现节点与字母 T 的比例美感，作为 Welcome 区域核心视觉锚点   |
| **应用与桌面图标**   | 128×128 / 512×512 | 体块化 / 渐变光影         | 引入微质感与等轴测立体截面，承载产品发布与桌面应用形态       |

## 备选方案

### 备选方案一：继续沿用当前 `system`（双方块对角折线）

- **未采用原因**：该图形在各类矢量图标库中过于常见，第一视觉印象高度类似于图形软件的“变换框选框（Bounding Box）”或“裁切工具（Crop）”，显著性极低，无法在法律层面形成商标壁垒，且完全缺失了“文本（Text）”维度。

### 备选方案二：纯代码标签与括号（如 `<T>` 或 `{texsys}`）

- **未采用原因**：过于偏向通用纯文本代码编辑器（类似 Sublime Text 或 Bracket 系工具），完全丢失了设计自动化（SysDA）、工程拓扑、物理构件与多物理场系统的“工程刚性”，无法代表复杂的工业系统建模。

### 备选方案三：暖通或特定工程专用图标（如风机、冷机、阀门）

- **未采用原因**：Tex Studio 是通用的领域系统建模宿主，虽然首个落地切片是暖通（HVAC），但内核必须保持对电气、给排水、动力等未来专业的完全开放，框架 Logo 严禁与任何单一细分工科绑定。

## 体验影响与权衡

- **积极收益**：
  - 彻底终结标签页默认地球图标带来的草稿感与廉价感；
  - 纠正空状态将领域跳转按钮伪装成图标的混乱交互，使代码编辑区回归纯粹；
  - 建立了深植于产品本质（Text + System）的视觉心智资产。
- **潜在代价与约束**：
  - 在极小尺寸（16×16）下，三维节点的三条线与字母 T 的间隙必须严格对齐像素网格（Pixel-snapping），避免抗锯齿模糊。

## 可用性走查与验收标准

1. **Favicon 渲染检查**：在 Chrome 与 Safari 浏览器的浅色与深色模式下，标签页均能清晰辨识 Logo 形状，无锯齿或透明度丢失；
2. **标签页标题中立性**：访问工作台任意页面，浏览器 Tab 标题均标准显示为 `Tex Studio`，不夹带项目路径或特定插件字样；
3. **Hero 视觉纯粹性**：在关闭所有打开文件后，居中空状态区域布局平稳，无多余未解释的纯图标按钮悬挂；
4. **SVG 规范性**：导出的 Logo SVG 符合标准 W3C 规范，代码精简，支持通过 CSS `currentColor` 进行无损着色。
