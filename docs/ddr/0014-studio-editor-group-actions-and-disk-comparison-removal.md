## 背景与实际观察

在用户既有 Google Chrome 中，通过 VS Code Web（`vscode.dev`）和 Tex Studio 打开同一项目 `build/project-preview-poc/20261111-replay/project-a/` 中的 `src/system.sdl.json` 与 `README.md`，对照实际操作入口。

观察结果如下。这些是本轮对照记录，不代表 Tex Studio 的修正已经完成验收。

| 对照项                           | 实际观察                                                                                                       |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| VS Code Web 的普通 JSON 标签操作 | 提供拆分和更多操作。                                                                                           |
| VS Code Web 的更多操作           | 提供显示打开的编辑器、全部关闭、关闭已保存、启用预览编辑器、锁定组和配置编辑器；打开的编辑器列表可搜索当前组。 |
| Tex Studio 修改前的更多操作      | 列出保存、另存为、重新读取、与磁盘比较和关闭，把文件操作放在了编辑器组操作入口。                               |
| VS Code Web 的 Markdown 标签操作 | 依次观察到侧边预览、以预览方式打开、拆分和更多操作。                                                           |

另外，同一 README 在两边均观察到文本编辑器、Markdown 预览、Markdown Editor 与按 `*.md` 设置默认值的子菜单。分栏后两个编辑器组独立显示标签，VS Code Web 的预览标签使用「预览 README.md」标识；Studio 采用相同标识并保留实际路径身份。

修改前的 JSON 对照截图保存在本地证据目录 `build/editor-parity-proof/`：`vscode-json-before.png` 与 `studio-json-before.png`。参考产品中的入口用于核对操作职责；具体保留范围由用户要求和当前范围契约决定。

用户进一步明确要求删除磁盘一致性／比较功能。DDR-0013 只删除常驻比较按钮、保留其工作流的处理不再适用，不能将入口藏到更多菜单后视作完成清理。

## 决策

### 更多操作管理当前编辑器组

- 普通 JSON 的标签操作区保留「分栏」和「更多操作」。更多操作面向当前编辑器组，按顺序提供「显示打开的编辑器」「全部关闭」「关闭已保存」「配置编辑器」。
- 「显示打开的编辑器」列出并搜索当前组实际打开的文档，选择后激活该组中的对应文档。「全部关闭」和「关闭已保存」只作用于当前组，不连带关闭其他组的视图。
- 「关闭已保存」依据共享文档的未保存状态判断；关闭当前组时，其他组仍有视图的共享草稿继续保留。关闭最后一个视图时沿用通用未保存内容处理。
- 「配置编辑器」进入已有编辑器设置，不新建专用配置页面。保存、另存为和还原继续通过文件菜单等通用入口执行，不出现在编辑器组更多菜单中。
- 本轮不实现预览编辑器的临时标签复用，也不实现锁定组。这些入口不显示、不提供空操作或占位项；此处的临时标签复用不影响已有 Markdown 预览能力。

### 删除磁盘一致性与比较流程

- 删除磁盘一致性／比较的专用入口、状态、比较布局、对话框及处理逻辑，包括「与磁盘比较」「采用磁盘内容」和通过比较流程「更新保存基准」的操作。删除应覆盖整个流程，不以隐藏按钮、改名或迁移入口代替。
- 保留普通文件的共享编辑内容、未保存基线与保存版本校验。保存基准过期时，后端仍拒绝覆盖并返回正常保存错误，当前编辑内容继续保留；不因此恢复专用比较或接受流程。
- 删除额外的「读取外部修改」菜单及命令入口；文件菜单的保存、另存为和还原继续使用既有文件能力。Git diff 和 Source Control 表达版本变化，属于范围内的通用开发能力，不随磁盘比较功能删除。
- 删除源内容区额外的已保存状态页脚。文件状态沿用统一标签的未保存标记及通用保存反馈，不在内容区重复增加状态布局。

### 打开方式与预览保持通用文件行为

- 只有一个可用打开方式时，不显示没有选择意义的打开方式选择器。普通 JSON 直接进入文本编辑器；这项决策取代 DDR-0013 中单一方式仍保留选择器的要求。
- 存在多种实际可用方式时，继续使用统一打开方式选择器。Markdown 保留文本编辑器、Markdown 预览和真实可编辑的 Markdown Editor，以及按扩展名设置默认值；偏好仍只影响之后新开的视图。
- Markdown 源代码模式的操作顺序保持用户既定要求：「预览、分栏预览、分栏、更多操作」。不因参考产品观察到另一顺序就改写已明确的用户要求。
- 分栏继续使用独立编辑器组，并共享同文件内容与保存状态。专业预览只替换内容区实现，不改变标签、路径导航、工具栏等通用外壳，不增加专用工程标题或状态条。

## 范围与取舍

本轮修正通用编辑入口的职责并清理被删除的功能，不扩建工程变更、依赖管理、合并审批或 DevOps 界面。参考产品中的临时标签复用、锁定组等能力也不自动进入当前 POC。用户已经要求的 Markdown Editor、文件类型默认值和通用分栏仍属于当前文件工作流。

删除磁盘比较减少了专用的人工处理路径，但不能借此覆盖未保存编辑或绕过保存版本检查。文件保存与 Git 差异继续承担各自职责；本轮编辑器交互修正不增加物理模型覆盖，也不证明完整工程 POC 已完成。

## 验收标准与证据边界

以下为修正后的验收要求，修改前截图仅证明问题和对照观察。最终 Google Chrome 验收完成前，不将本节记为通过。

1. 在既有 Chrome 中重新打开同一 JSON 和 Markdown，确认 JSON 只有分栏与更多操作，单一文本打开方式不显示选择器；Markdown 保留三种打开方式、扩展名默认值及规定的按钮顺序。
2. 在两个编辑器组中核对可搜索的本组文件列表、全部关闭和关闭已保存；操作只影响当前组，跨组共享的未保存内容不丢失。配置编辑器进入既有设置。
3. 核对标签操作区、更多菜单、对话框和内容区域，不再出现磁盘一致性、磁盘比较、采用磁盘或更新保存基准的专用流程，源内容区不再显示额外的已保存状态页脚。
4. 核对普通保存、另存为、还原及 Git diff 仍可使用；保存版本不匹配时拒绝覆盖并保留当前编辑，不出现已删除的比较流程。
5. 检查分栏后的独立视图、打开方式切换和共享保存状态，专业预览只替换内容区，未实现的临时标签复用和锁定组不显示占位入口。

修正后的截图与操作记录继续保存在 `build/editor-parity-proof/`，实际结果汇入 [工程 POC 台账](../engineering-poc.md)，与本节验收标准分别记录。
