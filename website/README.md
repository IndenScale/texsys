# Movement 网站

Movement 是“让复杂系统像软件一样被开发”的多页静态网站。内容同时呈现工程思想、技术机制与当前原型证据；网站是传播与阅读入口，Tex Studio 继续作为工程操作工作区。

## 构建与预览

只需要 Node.js，无需安装网站专用依赖。在本目录运行：

```bash
node build.mjs
node check.mjs
node serve.mjs
```

默认预览地址为 `http://127.0.0.1:8787`。可通过 `MOVEMENT_PORT` 设置静态预览端口。此服务仅提供生成的静态文件，不启动 Tex Studio；不得为 Studio 另开实例。浏览器验证使用现有 Google Chrome。

构建输出为被 Git 忽略的 `dist/`，可部署到支持目录索引的静态托管服务。`.openai/hosting.json` 记录 Sites 项目身份，更新时应复用，不重复创建。`build.mjs` 的 `origin` 是 canonical、站点地图和分享元数据的基准域名，换域名时同步修改。

## 内容组织

| 入口                | 内容                                          |
| ------------------- | --------------------------------------------- |
| `/`                 | 思想命题、系统关系、实验回放与阅读路径        |
| `/manifesto/`       | 用户提供的十二章宣言全文与章节目录            |
| `/ideas/`           | 设计空间、实现反馈、工程证据三篇专题          |
| `/system/`          | Engineering Compiler、IDE、PDK 架构与实现边界 |
| `/lab/pipe-change/` | 设施水管路变更真实运行摘录与三状态回放        |
| `/lexicon/`         | 16 个独立术语、定义、边界和交叉引用           |
| `/journal/`         | 可扩展的研究记录入口                          |
| `/participate/`     | 开放问题、参与方向与讨论提纲下载              |

`content/manifesto.md` 保存宣言原文。`content/pages.mjs` 保存文章与词条，字段包括路径、栏目、中英文标题、摘要、HTML 正文和关联阅读。增加内容后，重建会更新列表、搜索索引与站点地图。正文的二级标题应提供唯一 `id`，构建器会生成阅读目录。

`public/app.js` 实现搜索、键盘导航、术语筛选、移动菜单和阅读进度。`public/lab.js` 只回放 `public/evidence/pipe-change.json` 中冻结的真实运行摘录，不执行求解，不提交工程接受。站点不包含账号、消息接收、遥测或虚假联系表单。

## 设计约定

延续瑞士国际主义与精密开发工具的双重表达：白色阅读空间、黑色主排版、工程蓝 `#2457e7` 表达关联，暗色实验面板表达可检查的状态。正文使用 Helvetica Neue 与系统中文无衬线字体，不依赖外部字体服务。布局沿统一网格展开，使用系统依赖示意作为视觉资产。

首次加载的结构组装动效只展示层级关系；交互反馈由用户操作触发。支持窄屏、可见键盘焦点、跳过导航、模态搜索焦点恢复、减少动态效果及打印阅读样式。

## 证据与验证边界

本轮实验由公开入口在隔离项目副本中重跑：

```bash
uv run --locked tools/verify_engineering_poc.py \
  --output build/engineering-poc/website-20261111
```

命令应在 Texsys 仓库根目录执行，输出目录必须尚不存在。三次运行覆盖基线、缩径与移位导致的失败、恢复原输入；旧接受失效，失败接受被拒绝，修复结果需要单独审查。详细来源、运行 ID 与局限在下载 JSON 中。该 JSON 是精简摘录，保留的证据摘要属于原始运行，不能作为摘录文件的内容校验和。

`node check.mjs` 检查站内资源和锚点、路由唯一性、页面语义、搜索索引及回放与下载证据的一致性。Chrome 验收另行记录在仓库[工程 POC 台账](../docs/engineering-poc.md)。这些检查不证明真实工程签核、第二项目复用或完整 Studio 交互闭环。

网站以静态多页形式实现，每页都能直接访问、刷新和分享。新增后台业务、实时求解或用户讨论系统时，应另行定义权限、数据与运行边界。
