# Movement 网站

Movement 是“让复杂系统像软件一样被开发”的方法与知识网站。TexSys 是当前检验这些方法的工具链，Tex Studio 是其中的本地工程工作区。网站把方法、产品文档和可复核实验连接起来；工具行为与完成状态以源码契约和工程 POC 证据为准。

## 构建与预览

需要 Node.js。先按锁文件安装 Markdown 导出依赖，再构建与检查。在本目录运行：

```bash
npm ci --ignore-scripts
node build.mjs
node check.mjs
npm test
node serve.mjs
```

默认预览地址为 `http://127.0.0.1:8787`。可通过 `MOVEMENT_PORT` 设置静态预览端口。此服务仅提供生成的静态文件，不启动 Tex Studio；不得为 Studio 另开实例。浏览器验证使用现有 Google Chrome。

构建输出为被 Git 忽略的 `dist/`，可部署到支持目录索引的静态托管服务。`.openai/hosting.json` 记录 Sites 项目身份，更新时应复用，不重复创建。`build.mjs` 的 `origin` 是 canonical、站点地图和分享元数据的基准域名，换域名时同步修改。

## 内容组织

| 入口                | 内容                                          |
| ------------------- | --------------------------------------------- |
| `/`                 | 思想命题、系统关系、实验回放与阅读路径        |
| `/texsys/`          | 工具链定位、当前能力和源码预览入口            |
| `/docs/`            | 快速开始、工程变更流程、结果与证据            |
| `/manifesto/`       | 十二章宣言全文与章节目录                      |
| `/ideas/`           | 设计空间、实现反馈、工程证据三篇专题          |
| `/system/`          | Engineering Compiler、IDE、PDK 架构与实现边界 |
| `/lab/pipe-change/` | 设施水管路变更真实运行摘录与三状态回放        |
| `/lexicon/`         | 16 个独立术语、定义、边界和交叉引用           |
| `/journal/`         | 可扩展的研究记录入口                          |
| `/participate/`     | 开放问题、参与方向与讨论提纲下载              |

`content/manifesto.md` 保存经术语校订的宣言全文，并注明校订范围。`content/pages.mjs` 保存文章与词条，`content/product.mjs` 保存产品说明与用户文档；字段包括路径、栏目、中英文标题、摘要、HTML 正文和关联阅读。新增内容后，重建会更新列表、搜索索引、站点地图及 Markdown。正文的二级标题应提供唯一 `id`，构建器会生成页内目录和标题锚点。

文档根据仓库契约人工编写，不是另一套行为规范。命令或状态语义改变时，应同时核对 `README.md`、`spec/engineering/01-change-evidence.md` 和 `docs/engineering-poc.md`，更新对应用户文档。尚未提供独立的 API 全量参考或多版本文档切换。

文章使用共同的三栏阅读框架：持续侧栏、适度行宽的正文、页内目录；窄屏将导航折叠为菜单。所有内容页提供复制 Markdown、打开和下载 Markdown、复制页面链接；代码块可单独复制。`lib/markdown.mjs` 从正文生成 GFM 表格、列表、代码和绝对链接，排除导航与交互控件。复制按钮与 `.md` 文件使用同一份文本；剪贴板不可用时展示可手动选取的文本。首页 Markdown 地址为 `/index.md`，其他页面如 `/docs/quick-start/` 对应 `/docs/quick-start.md`；`/llms.txt` 提供完整阅读索引。

`public/app.js` 实现搜索、键盘导航、术语筛选、移动菜单和阅读进度。`public/lab.js` 只回放 `public/evidence/pipe-change.json` 中冻结的真实运行摘录，不执行求解，不提交工程接受。站点不包含账号、消息接收、遥测或虚假联系表单。

## 设计约定

延续瑞士国际主义与精密开发工具的双重表达：白色阅读空间、黑色主排版、工程蓝 `#2457e7` 表达关联。正文使用 Helvetica Neue 与系统中文无衬线字体，不依赖外部字体服务。首页的矢量图说明布局信息如何更新设计模型；不以装饰图标代替工程关系。

实验面板使用相同的 300 kW 尺度同时呈现基线、变更、修复，输入表与图可直接对照。切换状态只更新选中项和诊断，不隐藏其他记录，不改变面板高度。长证据摘要放在面板之外按需展开。支持窄屏、可见键盘焦点、跳过导航、模态搜索焦点恢复、减少动态效果及打印阅读样式。

## 证据与验证边界

网站冻结的实验由公开入口在隔离项目副本中重跑，源码基线为 `8a4a3d5`。后续文档与视觉改版继续回放这批结果，不代表重新验证当前工作区的全部工程实现：

```bash
uv run --locked tools/verify_engineering_poc.py \
  --output build/engineering-poc/website-20261111
```

命令应在 TexSys 仓库根目录执行，输出目录必须尚不存在。三次运行覆盖基线、缩径与移位导致的失败、恢复原输入；旧接受失效，失败接受被拒绝，修复结果需要单独审查。详细来源、运行 ID 与局限在下载 JSON 中。该 JSON 是精简摘录，保留的证据摘要属于原始运行，不能作为摘录文件的内容校验和。

`node check.mjs` 检查站内资源和锚点、路由唯一性、页面语义、搜索索引、Markdown 下载与复制文本一致性，以及回放与下载证据的一致性。`npm test` 验证 Markdown 转换的表格、列表、代码、链接、源文保留和界面排除行为。Chrome 验收另行记录在仓库[工程 POC 台账](../docs/engineering-poc.md)。这些检查不证明真实工程签核、第二项目复用或完整 Studio 交互闭环。

网站以静态多页形式实现，每页都能直接访问、刷新和分享。新增后台业务、实时求解或用户讨论系统时，应另行定义权限、数据与运行边界。
